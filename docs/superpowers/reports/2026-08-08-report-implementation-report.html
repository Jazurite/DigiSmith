Summary

Built report-implementation — DigiSmith's map item N — so that every superpowers:subagent-driven-development plan automatically gets an HTML implementation report (what shipped, per-task review record, final-review findings and resolutions, commit list), generated right before the plan's ledger is deleted, instead of relying on a human remembering to write one by hand (as happened once, manually, for map item G). It is a single skill, skills/report-implementation/SKILL.md, that triggers when a subagent-driven-development plan's final review has just passed and reads that plan's ledger (.superpowers/sdd/<plan>/progress.md) plus the plan file and git log over the plan's commit range, renders an HTML report using the same template as the existing hand-written G report, and commits it to docs/superpowers/reports/. It never modifies subagent-driven-development or finishing-a-development-branch — it runs once, immediately before the former's own Finish step deletes the workspace. Followed the full Superpowers process: brainstorming → spec → writing-plans → superpowers:subagent-driven-development (3 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 3 fix rounds before merge — two scoped to Task 2, and one comprehensive whole-branch wave after the final review.

Reference documents: the design spec and the implementation plan.

SeverityFindingResolution
Important The ledger parser was written against a controller-invented Final review (...) line format with no upstream or DigiSmith-documented grammar — it only existed because this session's controller happened to write it that way. Compounded by verdict derivation reading only the completion line, so a task with a bruising fix-round history could still render as "Approved, clean" purely because its last line said "review clean". Fixed — the final-review line grammar (Final review (...), Scoped re-review (...), Final review: parked — ...) is now an official DigiSmith convention recorded in MEMORY.md, alongside a second convention requiring every subagent-driven-development plan to invoke digismith:report-implementation. Step 1 now refuses to silently absorb a missing final-review line — it says so and asks. Step 2b's verdict rule now scans all Task <N>: ... lines and renders "Approved after <R> fix round(s)" whenever any fix round <R>/5 line exists for that task.
Important Seven header-level placeholders (FEATURE_TITLE, DATE, MAP_ITEM, SPEC_RELATIVE_LINK, PLAN_RELATIVE_LINK, REPORT_FILENAME, SUMMARY_PARAGRAPH) had no derivation rule at all — SUMMARY_PARAGRAPH especially, which as written needed facts only someone who lived through the feature's conversation could supply. Fixed — new Step 2a gives each one a mechanical rule. SUMMARY_PARAGRAPH is now composed from the plan's own Goal: and Architecture: lines plus a fixed closing sentence naming the task count and any fix rounds. Missing spec/plan files cause the link (and its clause) to be dropped rather than rendered as a 404.
Important The FINAL_REVIEW_SECTION placeholder was described in prose ("same shape as G's report — a table of Severity/Finding/Resolution") instead of being given as a literal template, unlike every other part of the report. Fixed — Step 3 now carries the literal <section id="finalreview"> block, with FINAL_REVIEW_ROWS and FINAL_REVIEW_SUMMARY_SENTENCE defined. The zero-findings omission rule (section and its TOC entry) is restated alongside it.
Important README.md had no mention of report-implementation — and its "One skill sits outside that front door" sentence had become factually false, since two skills now sit outside using-digismith's front door. This repeats a gap M's own final review already caught once. Fixed — the paragraph now opens "Two skills sit outside that front door", and a new paragraph in the same style describes report-implementation's trigger, output, and why its timing matters, linking to its SKILL.md and docs/history.html.
Security (hardening) No escaping rule existed for ledger or plan text substituted into the HTML template. This project's own ledger lines routinely contain literal angle brackets (<Key>__<slug>, <plan-basename>) that would be swallowed as unknown tags or break the table markup outright. Fixed — new Step 2f requires escaping &, <, and > (in that order) before substitution, then converting Markdown backtick-spans to <code> elements. Applies to deferred-minor lines, finding text, resolution text, verdicts, summary content, and commit subjects.
Minor (bundled — 7 items) Dead git diff --stat instruction nothing consumed · commit-list ordering unspecified · Task <N>: BLOCKED lines unhandled · AskUserQuestion availability assumed but never stated · bare, unqualified cross-skill name in the frontmatter description · unguarded fast-forward-merge assumption · docs/history.html's Tier 5 status read "2/4" against an Items cell listing 5 groups.
