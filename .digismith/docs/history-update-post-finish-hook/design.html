Overview

A third stock post-finish hook, .digismith/hooks/post-finish/03-history-update.md, that keeps .digismith/history.html's Timeline section current after every DigiSmith self-merge. In the numbering this handoff introduced, the two shipped stock hooks read as Y.1.1 (version bump) and Y.1.2 (plugin reinstall); this is Y.1.3, a third child of Y.1 (the post-finish point itself), not a new Y sub-item.

Why: history.html's own callout says to update it whenever a map item ships, but nothing enforces that — it went untouched from 2026-08-27 through V.3, while every one of those builds updated MEMORY.md. Same failure shape as the manual plugin-version bump that W.4.1 → Y.1 already fixed: a required-but-unenforced finishing chore that gets missed the moment attention is elsewhere. The page was hand-backfilled once (commit 4071e4c) as a prerequisite; this hook only has to keep it current from here on, never catch it up again.

Full backlog write-up (source material for this design): backlog/history-update-post-finish-hook-y13.md.

Architecture

03-history-update.md is gated on DigiSmith's own repo exactly like 01-version-bump.md and 02-plugin-reinstall.md (same IS_DIGISMITH check, verbatim — an explicit, human-confirmed precedent from Y.1 keeps each hook file self-contained rather than sharing the gate logic). It fires last in filename-sort order, independent of 02's outcome; if 01 fails, fire-lifecycle-hook.md's existing "stop, don't continue to any further post-finish hook" contract already prevents this hook from running at all — no change needed there.

  1. cd to repo root, run the gate check.
  2. Invoke node --experimental-strip-types .digismith/hooks/post-finish/scripts/update-history.ts --base "$(git rev-parse ORIG_HEAD)".
  3. The script finds every .digismith/docs/*/report.html that changed in ORIG_HEAD..HEAD. Zero found → prints NOTHING (no report in range) and exits 0 — the expected outcome for a docs-only commit or a merge that didn't go through report-implementation (N).
  4. For each report found, it parses the fixed markers N's own template guarantees ({{FEATURE_TITLE}}, {{MAP_ITEM}}, {{DATE}}, the #summary paragraph), checks for sibling design.html/plan.md to build the same three-link "design / plan / report" sentence every existing timeline entry already ends with, and derives the feature's slug from the report's own path.
  5. Builds one <div class="event"> block per report and inserts it as the last child of .timeline, before its closing tag.
  6. Bumps the header's Last updated: span to today.
  7. Writes history.html, prints APPENDED <n>: <titles>.
  8. Hook's bash: on APPENDED, chains git add .digismith/history.html && git commit -m "docs(history): record shipped features" && git push origin <base-branch> — same chained-commands-plus-rejection-handling pattern 01 uses (stop, report, no force-push, if rejected).
  9. Always ends with a plain reminder: the Map table, Build Order, and Progress Overview sections were not touched — review them by hand if this merge closes a letter or sub-item.

Source of truth and slug derivation collapse into one decision: since report-implementation (N) already runs for essentially every DigiSmith self-dev feature (its reporting gate only applies via a consumer repo's .digismith/profile, which DigiSmith's own repo never has), a changed report.html in the merge range is both the trigger signal and the complete data source — no new sidecar file, no separate slug-derivation heuristic.

Components & Interfaces

.digismith/hooks/post-finish/scripts/update-history.ts — mirrors bump-plugin-version.ts's shape: small exported pure functions plus a thin CLI.

function

findChangedReports(baseSha, cwd?)

git diff --name-only --diff-filter=AM baseSha..HEAD -- '.digismith/docs/*/report.html' via spawnSync (same pattern as versionChangedSince). Returns a list of relative paths, possibly empty.

function

parseReport(reportPath)

Reads one report.html, regex-extracts FEATURE_TITLE, MAP_ITEM, DATE, and the #summary paragraph; derives slug from the path. Throws a clear error naming the file and the missing marker — a malformed report is a real failure, not a silent skip.

function

buildReferenceLinks(slug)

Checks whether design.html/plan.md exist next to that report.html; returns the standard "design / plan / report" sentence, omitting a clause for whichever file is missing — mirrors N's own omit-if-absent rule.

function

buildEventHtml(entry)

Returns one <div class="event">…</div> block, indentation matching existing entries. Does not re-escape content — N's own Step 2f already escaped it; double-escaping would corrupt entities.

function

insertTimelineEntries(historyHtml, eventsHtml[])

Pure string transform. Locates <section id="timeline">…</section> by id first, then inserts the new block(s) as the last child of the nested .timeline div. Throws if that section can't be found, surfacing a future template change immediately.

function

bumpLastUpdated(historyHtml, todayIso)

Replaces the header's Last updated: <date> span content.

main() — CLI glue via the shared scripts/cli-args.ts parser (same as bump-plugin-version.ts): orchestrates the functions above, reads/writes .digismith/history.html, prints APPENDED <n>: <titles> or NOTHING (no report in range), process.exit(1) with a stderr message on any parse/insert failure. Not separately unit-tested, same scope boundary bump-plugin-version.ts already draws around its own main().

Error Handling

  • Gate false → hook no-ops, identical to 01/02.
  • No changed reports → NOTHING, exit 0, hook does nothing further (no commit, no push). Not an error — the expected outcome whenever a merge didn't go through report-implementation.
  • A found report fails to parse, or the timeline anchor can't be located → exit 1 with a specific stderr message; hook's bash stops and reports plainly, does not commit or push a partial result.
  • Push rejected (the remote moved) → stop, report the rejection plainly, do not force-push — identical handling to every other push in this skill and its hooks.

Testing

Vitest, same fixture-per-case style as bump-plugin-version.test.ts:

  • parseReport: correct extraction from a valid fixture; throws on each kind of missing marker.
  • buildReferenceLinks: all three links present; design.html missing; plan.md missing.
  • buildEventHtml: correct shape, and confirms it does not double-escape already-escaped content.
  • insertTimelineEntries: single insert; multiple inserts preserve order; throws when the timeline section is absent from the fixture.
  • bumpLastUpdated: replaces the date correctly.
  • findChangedReports: temp-git-repo integration test, same spawnSync git init fixture pattern as versionChangedSince's tests.

Explicitly Out of Scope

  • Badge/stats auto-updates. Whether a merge closes a map letter or sub-item is judgment, not mechanics — the hook only appends the timeline entry and reminds the agent to check the Map/Build Order/Progress Overview sections by hand.
  • The direct-to-main gap. Same stranding already documented in backlog/post-finish-hooks-direct-push-gap.md: a commit pushed straight to main never fires post-finish, so it gets no timeline entry either. Acceptable — bookkeeping-only commits aren't map items — and not re-solved here.
  • Dedup checking. No check for an existing link to a given report.html before appending. ORIG_HEAD..HEAD is a fresh range per merge, so the same report reappearing is very unlikely in practice; not worth the defensive code for a scenario that hasn't happened.
  • Draft-and-pause review. The hook commits and pushes immediately, matching 01/02's fire-and-forget pattern, even though a mechanically-generated entry will read tersely next to hand-written ones already in the timeline. Consistently current but terser beats accurate-but-often-missing.

Design Decisions

QuestionDecisionWhy
Source of truthParse report.html directly No changes to N needed; reuses existing infrastructure; N already runs for nearly every DigiSmith self-dev feature.
Which slug just mergedWhichever report.html changed in the merge rangeSame signal as source-of-truth above — collapses two open questions into one.
Badge flippingTimeline only; suggest, never auto-apply Not mechanically derivable from a diff; a wrong auto-flip silently corrupts the map's accuracy.
Multiple reports in rangeOne entry per report found Same mechanism handles the common (one) and rare (several) cases without special-casing.
Dedup checkSkip itYAGNI — the range is fresh per merge, the collision scenario hasn't occurred.
Commit timingImmediate, fire-and-forget Matches 01/02's established pattern; a paused/drafted flow reintroduces the "required-but-skippable" risk this hook exists to close.
Implementation approachBacking TypeScript script, not inline bash Matches 01's own precedent; parsing HTML and looping over multiple reports is too complex for reliable, testable sed/awk.
