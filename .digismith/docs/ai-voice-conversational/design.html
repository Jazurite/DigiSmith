Overview

T.5 curates ayghri/i-have-adhd (MIT) — a 10-rule discipline shaping how an assistant's live conversational response reads — into a DigiSmith-owned standard: action-first, numbered steps, one concrete next step, suppressed tangents, restated progress, concrete time estimates, visible wins, matter-of-fact errors, capped lists, no preamble/recap/closers. Team-shared per Jack's explicit call (like T.3's direction), not a personal preference — the point is how any AI model should communicate with engineers on this team, not just how Claude talks to Jack specifically.

Scope, mirroring T.1's own precedent: ship the curated content only. How this actually gets enforced for every live response in a consuming repo — the delivery/propagation mechanism — is deferred to T.3, which should generalize to carry any T.x content, not just T.1's.

Source and what changed

Absorbed as-is: rules 1–7, 9, 10, all six "when to break the rules" overrides, and the pre-send deletion checklist — well-crafted, no tension with anything else DigiSmith already enforces.

Amended: rule 8 ("matter-of-fact tone for errors"). The upstream repo's own published eval (blind judge, weighted rubric, 14 cases × 3 trials) caught this rule pressuring the model into asserting an unconfirmed root cause in one case (−0.63, the eval's one flagged regression) — the grader noted the response "asserts a definitive cause... without any evidence." That's the exact failure mode T.1's hedge-preservation rule already guards against for artifact prose, so T.5's own version of rule 8 adds the same discipline: state the cause plainly when confirmed; say "not yet confirmed" plainly when it isn't. Matter-of-fact tone survives; fabricated certainty doesn't.

Discarded: the upstream delivery mechanism (a personal opt-in flag file, ~/.claude/.i-have-adhd-always, toggled by "stop adhd mode") — built for one person's own global config, doesn't fit "team-shared." Its underlying idea (re-inject on every session start/resume/clear/and compaction, so the discipline survives a long session) is worth keeping in mind for T.3's eventual propagation design, but that's T.3's problem, not content T.5 needs to carry.

File content

standards/global/ai-voice-conversational.md — structure mirrors the upstream SKILL.md exactly (it's a well-proven shape), rules 1–7/9/10 adapted closely to the source, rule 8 rewritten per above:

SectionContent
Intro + persistence noteThe reader is an engineer on this team, not just Jack. These rules apply to every response for the rest of the session unless the task itself overrides them (see Overrides) — credit line to ayghri/i-have-adhd
10 rulesLead with the next action · Number multi-step tasks · End with one concrete next action · Suppress tangents · Restate state every turn · Give specific time estimates · Make completed work visible · Matter-of-fact tone for errors (hedge-preserving) · Cap lists to 5 items · No preamble, no recap, no closing pleasantries
When to break the rulesAll six overrides kept verbatim in spirit: explain/walk- through mode, destructive-action confirmation, debug-spiral stop, real ambiguity, "the rule would delete the answer itself," harness system prompt outranks the skill
Pre-send checkThe 5-item deletion checklist kept as-is (strip announcement openers, strip "anything else?" closers, strip "by the way" sidebars, strip empty hedging adverbs while keeping real ones, strip idioms for literal actions)

  ai-voice-conversational:
    kind: prose
    description: Live-conversation response-shape discipline for talking with engineers (action-first, numbered steps, no preamble/recap/closers, hedge-preserving error tone). Not for code — skip for code-writing tasks
