Summary

Builds a generic, local, hardcoded-pricing token/cost calculator (scripts/token-counter/) that works for any provider — including native Claude Code — with a fire-and-forget webhook hook point for a future, not-yet-built consumer. It mirrors scripts/providers/'s existing shape: one pricing-data file per provider (chutes, tokenreply, anthropic), a shared types.ts, a registry.ts doing a plain object lookup, and a pure compute.ts that turns real token usage into a CostRecord, with a separate webhook.ts handling the optional fire-and-forget POST as a side effect of computing. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (3 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 1 fix round before merge.

Reference documents: the design spec and the implementation plan.

What Was Delivered

Task 1

Types & pricing registry

Exports TokenUsage, PricingEntry, CostRecord (in types.ts) and resolvePricing(provider, model): PricingEntry | undefined (in registry.ts), backed by one hardcoded pricing-data file per provider.

Task 2

Webhook dispatch

Exports dispatchWebhook(record: CostRecord): Promise<void> — a no-op unless DIGISMITH_TOKEN_COUNTER_WEBHOOK_URL is set, otherwise a fire-and-forget POST with a timeout, logging on failure without throwing.

Task 3

Cost computation (public entry point)

Exports computeTokenCost(provider, model, usage): CostRecord — the module's public entry point, composing the registry and the webhook dispatch, never throwing on an unknown provider/model.
