Summary

Replaced the Atlassian MCP connector as jira-progress-write-back (map item I.1)’s Jira transport with packages/jira-client, a zero-dependency TypeScript package calling Jira’s REST API v3 directly — fixing the lossy-description-ADF bug found live on EMKT-756. A new pnpm workspace package (packages/jira-client) exposes five functions (checkCredentials, getIssue, updateDescription, addComment, getAttachmentContent) as a thin library, plus a cli.ts subcommand wrapper the skill invokes via node; credentials live at ~/.digismith/.env, outside every git repo. jira-progress-write-back’s own ADF business logic is unchanged — only its transport calls and step numbering change. Followed the full Superpowers process: brainstorming → spec → writing-plans → superpowers:subagent-driven-development (4 tasks) → a final whole-branch review, plus 1 fix round before merge.

Reference documents: the design spec and the implementation plan.

Final Review & Fix

Ready to merge: with fixes — 2 Critical, 5 Important, and 3 Minor findings, all resolved.

SeverityFindingResolution
CriticalThe CLI could not run at all on this repo’s own installed Node version — ERR_UNKNOWN_FILE_EXTENSION for .ts, reproduced by directly executing it. Every subcommand was broken as shipped, and the passing test suite never caught it because it only exercised client.ts via Vitest’s transform, never the CLI entry point.Fixed — added engines/devEngines (onFail: "error") requiring Node >=24 to both package.json files. Verified: pnpm install now hard-fails with a clear message on Node 22, and the CLI runs cleanly under Node 24.
CriticalSKILL.md treated any non-zero exit from check-credentials as “credentials incomplete” and looped back into re-collecting email/token/site — so the crash above would have been misdiagnosed and the skill would loop forever without ever finding the real cause.Fixed — closed by the Node-version fix above; the failure mode this finding described can no longer occur once pnpm install gates the Node version up front.
ImportantgetIssue requested the comment field with no pagination handling, even though Jira’s REST v3 issue-GET embeds only a page of comments — a long-lived ticket could silently look emptier than it is, causing a duplicate progress comment instead of an update.Fixed — added getComments with real startAt/total pagination via the dedicated /issue/{key}/comment endpoint; SKILL.md Steps 3 and 8 updated to fetch comments separately and completely.
ImportantbaseUrl() interpolated creds.site with no stripping of an accidental scheme or trailing slash — a user pasting a full URL for the site hostname would double the scheme and break every request.Fixed — added hostname normalization (strips a leading http(s):// and trailing slashes) in checkCredentials.
ImportantThe .env parser stored values verbatim with no quote-stripping, unlike standard dotenv convention — a hand-quoted token would break every authenticated call with a generic 401.Fixed — added quote-stripping for matching single/double-quoted values in parseEnvFile.
ImportantCLI flag parsing had no presence validation — a missing required flag surfaced as a raw, undiagnostic JS TypeError instead of a usage error.Fixed — added a requireArgs helper; every subcommand now fails with a clear missing required flag: --x message.
ImportantgetAttachmentContent sent Authorization with redirect: "follow", which fetch strips across an origin change by spec — confirmed empirically against a local test server. A same-origin redirect requiring the credential would come back unauthenticated.Fixed — switched to manual redirect handling that re-attaches Authorization only when the redirect stays on the same origin, verified against both same- and cross-origin redirect scenarios.
Minorconsole.log(JSON.stringify(result)) immediately followed by process.exit(0), which does not guarantee a large piped stdout write finishes flushing.Fixed — replaced every process.exit() call with process.exitCode, letting Node exit naturally once output has flushed.
MinorMEMORY.md pointed at backlog/jira-rest-graphql-direct-api.md as the place to find root-cause history, but this same diff deletes that file.Fixed — repointed the reference to .digismith/docs/jira-rest-migration/design.html.
MinorThe same fetch-then-check-ok-then-throw pattern was repeated near-identically across all four REST functions in client.ts, with no shared helper.Fixed — extracted a shared jiraFetch helper used by all REST calls.
