Background

Map item Q (Convention enforcement) is implemented today by a standalone skill, digismith:enforcer, which wraps digismith:brainstorming and digismith:writing-plans from the outside: an "Advisory" step injects override instructions before each call, and a "Verified" step checks the output landed correctly afterward, correcting it if not. This is exactly the kind of "H/Q-style interception" that map item W's own philosophy note says DigiSmith would rather avoid — W exists specifically to vendor and directly edit Superpowers' primitives instead of wrapping them.

This session proved W's actual mechanism works end-to-end for the first time (W.4, finishing-a-development-branch's push-after-merge fix, activated 2026-09-04). Given that, Jack's direction: fold Enforcer's real logic directly into the vendored primitives it wraps, retire the standalone skill, and free letter Q for future reuse.

Section 1 — Detection & slug resolution

Moves into brainstorming's own vendored content. Self-detects DigiSmith-tracked work via the same two signals Enforcer already uses: current working directory has .claude-plugin/plugin.json with "name": "digismith" (this repo), or .digismith/profile is present (a consumer repo). Neither signal → behave exactly as upstream, unmodified.

Slug resolution: when invoked from bootstrap/adopt, they've already derived one before calling brainstorming — passed along explicitly in the invocation context, reused verbatim rather than re-derived. A fully ad-hoc call (no bootstrap in the loop) derives it itself using the same deterministic rule jira-intake Step 3.1 already defines (lowercase, drop filler words, hyphenate, truncate ~40 chars at a word boundary) — inlined into brainstorming's own vendored copy rather than referenced by pointer.

Section 2 — brainstorming's path/format override

When DigiSmith-tracked work is detected, brainstorming's own "Write design doc" step targets .digismith/docs/<slug>/design.html instead of docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md, using the exact HTML shell (style block byte-for-byte) currently defined in Enforcer's Step 1, inlined directly. The gitignore check moves in as part of the same step: git check-ignore -q .digismith/docs/<slug>/design.html — exit 0 (ignored) → write but skip git add/commit; exit 1 (not ignored) → commit normally.

Not DigiSmith-tracked → unchanged upstream behavior (plain Markdown, default location) — the fallback must stay intact since not every repo Jack touches is DigiSmith-tracked.

{{MAP_ITEM}} keeps its existing rule: "no map letter — <one-line reason>" for a structural change with none, never left blank or invented.

Section 3 — writing-plans' equivalent

Same detection logic as Section 1. When DigiSmith-tracked, writing-plans' save step targets .digismith/docs/<slug>/plan.md instead of docs/superpowers/plans/YYYY-MM-DD-<feature-name>.md. Format is unchanged either way (Markdown) — a pure location override. Faithfully matching Enforcer's actual current behavior, there is no gitignore-check step here (Enforcer never had one for plan.md, only for design.html — not inventing new scope).

Slug: reuses whatever brainstorming already established in the same session (writing-plans runs as its terminal step, not a separate dispatch). A fully standalone invocation with no prior brainstorming in the same session falls back to the same ad-hoc derivation rule from Section 1.

Section 5 — Enforcer retirement & letter Q

skills/enforcer/ is deleted entirely. Every piece of its responsibility now has a home: detection/slug/path-format logic lives inside brainstorming's and writing-plans' own vendored content (Sections 1–3), the publish step moved into bootstrap, and the wrap-and-place mechanics for externally-sourced content moved into adopt (Section 4).

brainstorming's and writing-plans' Enforcer-absorption is treated as one combined activation, W.5 — not two separate ones — since they are not independently meaningful (writing-plans' change only matters in the same session/slug context brainstorming already established). This supersedes the earlier "add a no-op fork-provenance tag to brainstorming" idea floated before Enforcer came up — real content is diverging now, so a tag-only activation is moot.

MEMORY.md's map: Q's row marked retired ("absorbed into W.5 once the vendoring mechanism was proven live — letter freed for future reuse"), same precedent as letter R being freed and later reused for W's own predecessor numbering. The Build order table's Tier 2 entry for Q gets an annotation noting the retirement date, not a silent removal — preserving the historical record of when it was built and later retired, consistent with how W's own entry already documents its R→W renumbering history.

Testing

These are markdown/prose skill files, not executable code — no unit tests apply directly. Verification plan:

  • check_vendored_skills.ts should report both brainstorming and writing-plans as locally diverged (not upstream drift) once activated, the same way it already correctly reported finishing-a-development-branch's W.4 activation.
  • Manual read-through of the edited bootstrap/adopt flows for internal consistency — no dangling reference to digismith:enforcer anywhere in the repo after the change (a repo-wide grep for enforcer should return zero matches outside this spec and historical frozen docs under .digismith/docs/).
  • No live end-to-end dry run of the full bootstrap → brainstorming → writing-plans chain is practical within this session — flagged as a real gap, same class of risk K.6's runner had before its live confirmation this session.

Out of scope

  • Deciding what letter Q gets reused for next — freed, not reassigned, in this change.
  • Any other vendored primitive beyond brainstorming/writing-plans diverging further (W.6+) — separate future work.
  • Fixing the fact that writing-plans' location override never had a gitignore check historically (Section 3) — carried over faithfully as-is, not treated as a bug to fix here.
