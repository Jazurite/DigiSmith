Background

Map item W.2's scripts/check_vendored_skills.ts resolves "upstream" by reading whatever Superpowers plugin version is installed locally (resolveUpstreamSkillsDir, scanning ~/.claude/plugins/cache/claude-plugins-official/superpowers/*/skills/ for the most-recently-modified hash directory). Jack has said he plans to stop keeping Superpowers installed going forward ("I'm not gonna install Superpower from now on. Everything is Digi Smith") — once that happens, this resolution fails outright ("Superpowers plugin cache not found") and the entire upstream-drift mechanism goes permanently dark, even though the real upstream repository keeps evolving on GitHub regardless of what is or isn't installed locally.

Fix: resolve upstream directly from https://github.com/obra/superpowers (per vendored/PROVENANCE.md) instead of local install state. Confirmed during this session's brainstorm: a shallow git clone (not the GitHub REST API), replacing local-cache resolution entirely (no fallback), against the default branch's current tip (not a pinned release), failing loudly with no partial report when GitHub is unreachable.

Section 1 — Shallow-clone replacement for resolveUpstreamSkillsDir

A new function replaces both resolveUpstreamSkillsDir and pickMostRecentDir (both deleted entirely — no more "pick the most recent hash dir" logic is needed once there's only one source of truth). It creates a temp directory via fs.mkdtempSync, runs git clone --depth 1 <repo-url> <tmpdir> via spawnSync — matching every other git operation already in this file, which all use spawnSync rather than a new HTTP/API dependency — checks out the default branch tip (the clone's own default, nothing extra needed), and returns path.join(tmpdir, "skills"). On clone failure (offline, GitHub unreachable, bad URL), it throws a clear Error naming what failed. The repository URL becomes a parameter (defaulting to https://github.com/obra/superpowers.git in production), which Section 2's tests depend on.

Section 2 — Testing without hitting real GitHub

Every existing test in this file already runs real git commands (readGitBlob/ listBaselineFiles tests run actual git show/git ls-tree against this repo's own history) — no mocking anywhere. The new clone function's tests keep that same style: since the repository URL is now a parameter, tests create a small local git repo fixture in a temp dir (git init + a skills/<fake-name>/SKILL.md file + one commit), then call the clone function with that local path in place of the real GitHub URL — git clone works identically against a local path, no network involved, no mocking needed.

The 5 existing tests for resolveUpstreamSkillsDir's hash-dir-picking logic (picks most-recent, throws if cache not found, throws if no skills/ subfolder, warns/ doesn't warn on multiple candidates) are deleted entirely — that logic no longer exists. New tests for the clone function cover the equivalent real scenarios: clones successfully and finds skills/; throws a clear error when the clone fails (point it at a nonexistent local path to simulate this without needing a real network failure); confirms the returned path is correct.

Section 3 — Wiring into main(), and cleanup

checkSkill(), compareFile(), readGitBlob(), listBaselineFiles(), diffContent(), readFileIfExists(), formatSkillReport(), the VENDORED_SKILLS array, and BASELINE_SHA all stay completely untouched — they only ever consumed a skills/ directory path, never cared how it was resolved. main() changes minimally: swap the call from resolveUpstreamSkillsDir() to the new clone function, keep the existing try { ... } catch (err) { console.error(...); process.exit(1); } shape unchanged around it (the new function's thrown errors flow through the same path), and add a finally block that removes the temp clone directory (fs.rmSync(tmpDir, { recursive: true, force: true })) after the skill-checking loop completes — matching the same cleanup pattern diffContent() already uses for its own temp dirs elsewhere in this file.

Section 4 — Doc updates to match the new mechanism

Two places currently describe the old local-cache-based resolution and would become inaccurate:

vendored/PROVENANCE.md

Sync policy section

Currently says the script diffs "vs. whatever Superpowers plugin version is currently installed." Updates to say it now clones the upstream GitHub repository's default-branch tip directly, no local Superpowers install required — closing the exact gap this backlog item was raised to fix.

MEMORY.md

W.2 map entry

Same phrase, "vs. currently-installed upstream," gets the same correction.

Both are small, single-clause edits — no restructuring of either doc, consistent with how W.5/W.6 handled their own doc touch-ups.

Testing

  • New unit tests for the clone function, using a local git-repo fixture (Section 2) — real git behavior, no network, no mocking, consistent with the file's existing style.
  • The 5 existing resolveUpstreamSkillsDir tests are deleted, not adapted — the function itself is gone.
  • All other existing tests in this file (for readGitBlob, listBaselineFiles, diffContent, compareFile, formatSkillReport) require zero changes — none of them touch upstream resolution.
  • Manual verification after implementation: run the script for real once, confirm it actually clones from the real https://github.com/obra/superpowers.git URL and produces the same kind of report as before (this is the one thing unit tests with a local fixture can't prove — a live confirmation against the real remote, same category of gap flagged for W.5/W.6's own live end-to-end paths).

Out of scope

  • A fallback to the local plugin cache when GitHub is unreachable — explicitly declined (Section 1's "replace entirely" decision).
  • Configurable ref/tag pinning — explicitly declined in favor of always comparing against the default branch's current tip.
  • An offline bypass flag — this is a manually-triggered, on-demand tool per W.2's own design ("still manual-trigger, not automatic-schedule"); if you're running it, you need network access, full stop.
  • Extending drift coverage to files upstream has added since the baseline commit — a pre-existing, separately-noted limitation of check_vendored_skills.ts (backlog/check-vendored-skills-hardening.md), unrelated to this change.
