Overview

digismith:depot (map item V) manages five machine-wide resources, but only VPS Session (V.3/V.4) has ever been ported into real, tested code — it already routes through packages/cli/src/index.ts vps. The other four resources are still raw bash embedded directly in skills/depot/SKILL.md, executed live by whichever Claude Code session invokes the skill.

This feature adds a second command group, depot, to @digismith/cli, covering the three resources that already have a documented "invoke directly" use case outside any automated flow: the packages/ clone, the OpenCode server, and the Agentic Bridge proxy. Claude Code readiness stays skill-only — it has no standalone use case, only ever running as an internal prerequisite check inside offload-implementer's own dispatch.

Decided during this brainstorm, in order: scope is clone + opencode + bridge, not all four resources · skills/depot/SKILL.md's three resource sections are rewritten to delegate to the new CLI commands, the same way its VPS Session section already delegates — one source of truth, not a second implementation · OpenCode and Agentic Bridge share a common process-lifecycle helper module, since this is now real tested code rather than skill prose (where duplicating the same ~80-line pattern was previously judged cheaper) · Agentic Bridge's ensure requires a resolvable DigiSmith checkout path (cwd walk-up, or an explicit --repo), the same real constraint that exists today, not a project to also bundle the proxy server into the package.

Command Tree and Entry Point

dg depot clone ensure
dg depot clone refresh
dg depot opencode ensure
dg depot opencode stop
dg depot bridge ensure [--repo <path>]
dg depot bridge stop

packages/cli/src/depot/index.ts is the new command-group dispatcher (parses the resource, then the verb), registered in the top-level GROUPS map in packages/cli/src/index.ts alongside vps. An unknown resource or verb falls through to the same usage-message-plus-exit-1 behavior the dispatcher already gives vps. Naming follows the tree's existing rule: the package runs src/index.ts, a command group runs src/<group>/index.ts — no file is called cli.

Resource: clone

Simplest of the three — no process or PID tracking, just git commands against the fixed path ~/.digismith-depot/repo, ported directly from the skill's existing bash. packages/cli/src/depot/clone.ts uses node:child_process directly (spawnSync per git step) — no shared helper needed, since there is no daemon/PID lifecycle here, just sequential commands with pass/fail exit codes.

  • ensure — idempotent, clone-if-missing: sparse packages checkout of git@github.com:Jazurite/DigiSmith.git, main checked out. No-op if ~/.digismith-depot/repo/.git already exists.
  • refresh — fetch --all --prune --tags + checkout main + reset --hard origin/main. If the clone doesn't exist yet, runs ensure's sequence first instead of failing (an ordering case, not an error case — same disposition as today).

Resource Lifecycle Helper

packages/cli/src/depot/process-lifecycle.ts exports the shape shared by opencode and bridge:

interface LifecycleConfig {
  trackingFile: string;   // e.g. ~/.digismith-depot/opencode-server.json
  logFile: string;
  spawn: () => { command: string; args: string[]; env?: Record<string, string> };
}

function ensureProcess(config: LifecycleConfig): { port: number } { ... }
function stopProcess(config: LifecycleConfig): { stopped: boolean } { ... }

ensureProcess — read the tracking JSON. Present → confirm the tracked PID is still alive (tasklist //FI "PID eq <pid>", checking the output actually lists it, not just that the command exits 0 — an absent PID still exits 0 with an empty-ish table). Alive → return the tracked port. Absent or stale → spawn detached (--port 0, output redirected into logFile), resolve the real PID, poll the log for a line ending listening on http://127.0.0.1:<port> (a shared regex works for both resources, since both log lines share that suffix), write the tracking file, return the port.

stopProcess — read the tracking file. Absent → report nothing-to-stop, exit 0. Present → taskkill //PID <pid> //F, then delete the tracking file regardless of whether the process was still alive by the time it ran.

PID resolution correction (folded in from a confirmed, recorded lesson, hit 3+ times including on the Agentic Bridge itself): ps -W | awk WINPID resolution can silently return the wrong PID under concurrent process load — not just empty, wrong. The skill's existing bash only falls back to netstat -ano when ps -W comes back empty, which doesn't catch this. Since this is the first real, tested implementation of this logic (the skill's bash prose never got this fix either), ensureProcess always cross-checks the ps -W result against netstat -ano (matched to the actual listening port) before persisting or killing a PID, treating netstat as authoritative rather than a fallback-of-last-resort. Never persist an empty or unconfirmed PID.

Resource: opencode

packages/cli/src/depot/opencode.ts calls the shared helper with:

  • trackingFile: ~/.digismith-depot/opencode-server.json
  • logFile: ~/.digismith-depot/opencode-server.log
  • spawn: opencode serve --port 0 --hostname 127.0.0.1, with CHUTES_API_KEY fetched via python3 ~/.claude/skills/chutes-ai/scripts/manage_credentials.py get --field api_key and passed as an environment variable — the same external credential-fetch script the skill already shells out to today; nothing new introduced here.

Resource: bridge

packages/cli/src/depot/bridge.ts calls the same shared helper, plus a repo-resolution step opencode doesn't need: ensure-agentic-bridge spawns node <digismith-repo>/scripts/agentic-bridge/server.ts — a file that only exists inside a full DigiSmith git checkout, not in the sparse packages/-only depot clone and not published in @digismith/cli's own tarball. Today this works only because offload-implementer always calls it from inside a live DigiSmith-repo session that already resolved that repo's own path; a bare dg depot bridge ensure typed from an unrelated directory has no such path to fall back on.

Resolution order: walk up from cwd for .claude-plugin/plugin.json with "name": "digismith" (the same marker inject-standards and offload-implementer already use); if not found, require an explicit --repo <path> and validate it carries the same marker. Exit 1 with a plain message if neither resolves — never guesses a path. The resolved path only matters for ensure; stop never needs it, since it only reads the tracking file.

  • trackingFile: ~/.digismith-depot/agentic-bridge.json
  • logFile: ~/.digismith-depot/agentic-bridge.log
  • spawn: node --experimental-strip-types <repo>/scripts/agentic-bridge/server.ts --port 0
Deliberately not pursued here: bundling scripts/agentic-bridge/{server,anthropic-response}.ts into packages/cli the way V.4 relocated scripts/vps-session/ — that would let dg depot bridge ensure work from a bare global install with no DigiSmith checkout nearby, but it's a bigger scope increase (also touches K.9's own map history and offload-implementer's references to the script's current path) than this feature is meant to cover. Requiring a real checkout path preserves today's actual constraint, just expressed as an explicit CLI check instead of an agent's own prior resolution.

Relocation and Skill Integration

skills/depot/SKILL.md's three resource sections (packages/ Clone, OpenCode Server, Agentic Bridge Proxy) are rewritten to delegate to the new CLI commands, the same way its VPS Session section already reads — replacing the embedded bash with checkout-form invocations:

node <digismith-repo>/packages/cli/src/index.ts depot clone ensure|refresh
node <digismith-repo>/packages/cli/src/index.ts depot opencode ensure|stop
node <digismith-repo>/packages/cli/src/index.ts depot bridge ensure|stop

bootstrap/adopt (clone ensure) and offload-implementer (opencode ensure, bridge ensure) keep invoking the digismith:depot skill by name exactly as today — only the skill's own internal instructions change, from "run this bash" to "run this CLI command." No caller-facing change to any of those three skills. The "Which Operation" tables and Quick Reference table stay conceptually the same; only the commands they point at change. The existing Out of Scope bullet about the shared ensure/stop shape ("duplicating this well-understood ~80-line pattern twice is still cheaper and clearer than a premature abstraction") is updated to note the shape is now consolidated in process-lifecycle.ts rather than duplicated, since it's real tested code now rather than skill prose.

Error Handling

CaseDisposition
No SSH/git access for the DigiSmith cloneReport the real git error, exit 1
ensure fails when the clone doesn't exist and bootstrap/adopt called itExit 1; caller skill fails the ticket-start flow, same as today
opencode not on PATHExit 1, point at pnpm add -g --allow-build=opencode-ai opencode-ai
Bridge repo not resolvable (no cwd marker, no valid --repo)Exit 1, plain message — never guesses a path
Server fails to start (no listening line in the log within a few seconds)Exit 1, print the log content, no silent retry
Tracking file's PID no longer aliveTreat as stale, start fresh, overwrite the tracking file
ps -W WINPID disagrees with (or is missing from) the netstat -ano cross-checkTreat netstat as authoritative; if neither resolves a PID, exit 1 and never persist an empty/unconfirmed PID
stop with no tracking fileExit 0, "nothing to stop"

Testing and Acceptance

Same split V.3/V.4 already established: log-line parsing, tracking-file read/write, port extraction, and repo-marker resolution are Vitest-unit-tested. Actual process spawn, taskkill, and PID resolution (ps -W/netstat) are live-verify-only by design — documented as such, not faked with mocks. Acceptance: from a checkout, each of the six commands runs correctly against a clean ~/.digismith-depot state and against an already-running/already-cloned state (idempotency); skills/depot/SKILL.md's three rewritten sections are read back to confirm they now point at the CLI, not embedded bash.

Out of Scope

  • Claude Code readiness as a fourth resource — stays skill-only; no documented standalone use case, only ever runs as an internal prerequisite check inside offload-implementer's own dispatch.
  • Bundling the Agentic Bridge proxy server into packages/cli — see the callout under Resource: bridge above.
  • Locking ensureProcess's check-then-start against a concurrent caller — same accepted, disclosed risk the skill already carries for ensure-opencode-server/ensure-agentic-bridge: two callers within the same few seconds can each start their own process, whichever writes the tracking file last wins the slot, the other leaks untracked. Not solved here, for the same reason (a personal, single-operator tool doesn't warrant a lockfile for a window this narrow).
  • Publishing this as a new @digismith/cli version — ships as an unreleased addition to the package until a separate decision to publish, same manual-publish stance V.4 already established.
  • A generalized multi-resource CLI abstraction across command groups — vps and depot each keep their own dispatcher and internal shape; no shared "command group" framework beyond the existing GROUPS map.
