Summary

Adds a depot command group to @digismith/cli (dg depot clone|opencode|bridge ...) covering the three Depot resources that already have a documented "invoke directly" use case, and rewrites skills/depot/SKILL.md to delegate to it instead of embedding raw bash. Built as a new packages/cli/src/depot/ module: clone.ts (git commands, no process tracking), process-lifecycle.ts (shared ensure/stop helper for daemon-style resources), opencode.ts and bridge.ts (each wired to the shared helper), and index.ts as the resource dispatcher registered in the top-level GROUPS map alongside vps. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (5 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 3 fix round(s) before merge.

Reference documents: the design spec and the implementation plan.

What Was Delivered

Task 1

clone

depot command-group dispatcher (routes clone/opencode/bridge), plus the clone resource: ensureClone/refreshClone against a sparse ~/.digismith-depot/repo checkout.

Task 2

process-lifecycle

Shared ensureProcess/stopProcess helper: spawns a detached daemon, confirms its real PID via netstat (never ps/awk), stops via a tree-killing taskkill.

Task 3

opencode

opencode resource — ensure starts a shared OpenCode server (fetching a Chutes API key), stop tears it down, both wired to the Task 2 helper.

Task 4

bridge

bridge resource — ensure locates a real DigiSmith checkout (cwd walk-up or --repo) and starts the Agentic Bridge proxy; stop tears it down.

Task 5

docs

Documentation-only: skills/depot/SKILL.md delegates its three resource sections to the new CLI, README.md and MEMORY.md updated.
