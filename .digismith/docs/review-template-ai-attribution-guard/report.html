Summary

Makes AI/assistant attribution in a commit message mechanically, deterministically blocked before any review package is written — not left to a reviewer subagent's judgment, which already got it backwards once. A new check-attribution script inspects a commit range's full messages for three narrow attribution patterns; review-package calls it before writing anything, failing loudly with nothing written on a hit; code-reviewer.md's standalone review path (which can't always route through review-package) runs the same script directly; the one documented bash-less fallback and the task reviewer's own policy gap were closed too. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (4 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 4 fix round(s) before merge.

Reference documents: the design spec and the implementation plan.

What Was Delivered

Task 1: check-attribution script

Code

A CLI, check-attribution BASE HEAD — exit 0 silent (clean), exit 1 with commit-by-commit detail on stderr (attribution found), exit 2 on usage/bad-SHA error.

Task 2: Wire check-attribution into review-package

Code

No review package is ever written for a commit range that carries attribution — the guard fires before any reviewer is dispatched, not after.

Task 3: Activate requesting-code-review

Docs / Activation

First-ever activation of this dormant Superpowers primitive — its shared code-reviewer.md template now runs the same mandatory attribution check, covering the standalone review path review-package can't reach.

Task 4: Close the manual-fallback bypass; fix the root-cause policy gap

Docs

The one documented bash-less review path now runs the check inline too; the task reviewer template gained an explicit stated no-attribution policy, closing the exact gap that let the original incident's reviewer assume the trailer was expected.
