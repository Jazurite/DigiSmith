Summary

This fix stops dg vps connect's crash-recovery path from leaking a duplicate herdr workspace on every run. It reuses an existing, matching-labeled workspace's idle pane before it creates a new one. It adds builder and parser functions for herdr workspace list and herdr pane list --workspace <id> to checks.ts, plus a parser for the agent_pane_busy error shape. These follow the same pattern as the existing buildAgentGetCommand/parseAgentGetOutput pair. It adds one new function, tryReuseExistingPane, to connect.ts. runConnect's recovery branch tries this function before it calls buildCreateWorkspaceCommand. A failure that is not agent_pane_busy still stops the process, matching today's behavior for a start-agent failure. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (3 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 1 fix round before merge.

Reference documents: the design spec and the implementation plan.

Final Review & Fix

Ready to merge: Yes — no Critical or Important findings, the attribution check came back clean, and the review reported 6 Minor findings (1 fixed, 1 documented, 4 parked).

SeverityFindingResolution
Minor A literal null JSON payload could throw a TypeError in the new soft-fail parsers, breaking the plan's own "never throws" rule. Fixed via one fix dispatch (commit 058f69d). A scoped re-review confirmed the finding addressed in all three functions and both array-entry loops, with no new breakage.
Minor A reused pane keeps whatever TokenReply API key was current when its workspace was first created — it does not pick up a rotated key the way the old always-create path did. Documented as a known limitation in design.html's out-of-scope section (commit 7f52140), not code-fixed.
Minor A pane that disappears between pane list and agent start hard-fails connect instead of falling back to creating a new workspace. Parked — real, narrow edge case. The code correctly implements the plan's stated requirement (only agent_pane_busy retries); widening the retry set is a deliberate future design call, not an oversight.
Minor Workspace and pane IDs are interpolated unquoted into the remote shell command. Parked — real but low-risk, since the IDs come from the VPS's own trusted herdr output. A regex guard would be cheap but isn't load-bearing for this fix.
Minor The new test imports in checks.test.ts sit in a second import block. Parked — cosmetic, plan-mandated (already parked at Task 1's own review).
Minor The design doc says isAgentPaneBusyError needs the payload to match "exactly" {error:{code:"agent_pane_busy"}}; the code only checks error.code. Parked — real but harmless doc-wording overstatement. The code's actual, looser check is the more sensible behavior.
