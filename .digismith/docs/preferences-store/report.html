Summary

Adds a general, per-repo settings store to DigiSmith — .digismith/preferences.yml — plus a digismith:preferences skill wrapping get/set/clear, so a live-interaction decision (starting with W.8's saved finish option) can persist across runs and worktrees without a one-off file format per consumer. A small TypeScript module (scripts/preferences.ts) does plain-line read/write against that file — no YAML library, the same parsing convention already used for .digismith/profile's own fields — wrapped in a thin CLI (--key/--action/--value, reusing scripts/cli-args.ts). skills/preferences/SKILL.md is the only thing any consuming skill or Jack ever calls; digismith:bootstrap and digismith:adopt each gained one new worktree-copy sub-step mirroring the existing .digismith/profile copy, so a freshly created worktree doesn't silently look like "no preferences set." Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (3 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 1 fix round before merge.

Reference documents: the design spec (shared with W.8's future plan — see its own H sections) and the implementation plan.
