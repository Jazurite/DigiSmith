Summary

Migrated @digismith/cli's hand-rolled vps/depot dispatcher to a yargs-based, HubSpot-style domain framework with branded help output, and closed out letter U's ownership split from Depot's own V lineage. Every domain (vps, depot) and sub-domain (depot clone, depot opencode, depot bridge) is now a yargs "bucket" CommandModule composed of leaf CommandModules that call the logic functions each file already exported — no logic changes, only the argv-parsing shell around each was replaced. The shipped branding mechanism differs from the plan's original design: src/lib/brand-help.ts's brandOutput() regex-colorizes yargs' own fully-rendered help/error text, delivered via .parse(argv, {}, callback)'s output-buffering — not the originally-planned .showHelp(callback)/.updateLocale() approaches, both of which turned out to have real defects only a live end-to-end parse could expose (see Final Review & Fix, and plan.md's two "Correction" sections for the full history).

Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (6 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review. This was an unusually eventful build: Task 5 (the root dispatcher) discovered that the branding mechanism already shipped in Tasks 1/2/4 was fundamentally broken, requiring three full design iterations — each independently reviewed, two of which found real defects — before the mechanism was verified correct against yargs' own source rather than just its documentation. The final whole-branch review found 3 Important findings and 1 real Minor bug, all fixed in one review-mandated fix wave plus one additional targeted fix for a residual finding the scoped re-review surfaced.

Reference documents: the design spec and the implementation plan.

What Was Delivered

Task 1

Shared CLI framework primitives

lib/brand-help.ts — brandOutput(rawOutput, colors?), a pure string post-processor colorizing yargs' already-rendered help/error text, plus ROOT_USAGE, a plain marker string used to distinguish root from nested output. (This is the final, third-iteration shape — see Final Review & Fix.)

Task 2

vps domain → yargs bucket

Default-exports vpsCommand: CommandModule, composing status/connect leaves; shared.ts's loadConfigOrExit() centralizes the config-loading guard both leaves need.

Task 3

depot clone sub-domain → yargs bucket

Default-exports cloneCommand: CommandModule, composing ensure/refresh leaves over the pure logic moved into clone/lib.ts.

Task 4

depot opencode/bridge + the depot root bucket

Default-exports depotCommand: CommandModule, composing clone/opencode/bridge. opencode/bridge's ensure/stop leaves use a createEnsureCommand(trackingFile?, logFile?)/createStopCommand(trackingFile?) factory pattern preserving the old code's test-path overridability. The hand-parsed --repo flag became a declared yargs option.

Task 5

Root dispatcher

buildCli(argv): Argv — the real yargs root instance, wiring vpsCommand/depotCommand, .strict(), .version(). The production entry point (isDirectRun()) drives .parse(argv, {}, callback), buffering yargs' rendered output through brandOutput() before printing.

Task 6

Ownership/docs cleanup

package.json's description no longer frames the package as Depot's; MEMORY.md's U row records U.1's shipped state, V's row cross-references the ownership move.
