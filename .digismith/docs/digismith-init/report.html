Summary

Built digismith:init, a single front door safe to invoke regardless of whether a ticket's work is starting fresh or already mid-stream — the way git init is safe to run whether or not a repo already exists — replacing using-digismith as the thing anyone invokes by name. init dispatches to one of two internal-only workers: digismith:bootstrap (today's using-digismith, renamed and no longer directly invoked) for a fresh ticket, or the new digismith:adopt for a ticket whose spec and plan already exist outside DigiSmith. Three skills: init holds only the already-initialized check and fresh-vs-mid-stream detection, then dispatches; bootstrap is using-digismith renamed with its process content unchanged; adopt backfills profile/ticket/branch state for already-existing work, relocates the existing spec/plan into DigiSmith's docs convention by reusing enforcer's own move-and-correct logic, then hands off directly to superpowers:subagent-driven-development since brainstorming/ writing-plans already ran outside DigiSmith. Followed the full Superpowers process: brainstorming → spec → writing-plans → superpowers:subagent-driven-development (8 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 5 fix round(s) before merge.

Reference documents: the design spec and the implementation plan.
