Summary

Closed the AI Attribution Guard's third confirmed gap — check-attribution only ran inside a formal review flow, so a direct/ad-hoc git commit never got checked — with a real git commit-msg hook that fires on every commit that goes through normal message collection, plus an unconditional SessionStart reminder as defense in depth. A new scripts/git-hooks/attribution-pattern.sh became the single source of truth for the attribution regex, sourced by both the new commit-msg hook and the existing check-attribution script; a new package.json prepare script installs the hook automatically via git config core.hooksPath scripts/git-hooks on every pnpm install, relying on git's own relative-path-per-worktree resolution so every worktree of this repo enforces it correctly. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (4 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 2 task-level fix rounds and a 2-round final-review fix wave (one substantive, one a small follow-up correcting a formatting regression the first introduced) before merge. The build itself paused mid-Task-1 for a token limit and resumed the next day, and separately caught a live regression in its own mechanical-tier offload path (kimi-k3 silently returning no tool calls, twice, in two different ways) — both are recorded in the ledger, neither affected the shipped result.

Reference documents: the design spec and the implementation plan.
