Background

W.8 (.digismith/docs/review-template-ai-attribution-guard/design.html) built a real, working mechanical check for AI/assistant attribution in commit messages — skills/subagent-driven-development/scripts/check-attribution — and wired it into two places: subagent-driven-development's review-package step, and requesting-code-review's shared code-reviewer.md template. Both gates fire only inside a formal review flow.

The incident (2026-09-22/23). A session-level attribution instruction arrived mid-session and was followed literally instead of being overridden by the standing no-attribution rule, which explicitly says it overrides exactly this kind of generic default. Four commits — b0f41c8, 11bbd91, 2508f74, 490ce4f, all docs-only backlog/design bookkeeping — carried an unwanted Co-Authored-By: Claude ... trailer and reached origin/main before Jack caught it directly. Left in git history as-is; fixing forward, not rewriting shared history other concurrent sessions may depend on.

The confirmed gap. All four commits were direct git commit calls made outside any plan or review skill — ad-hoc docs/backlog bookkeeping, the shape of most commits in a DigiSmith self-development session. check-attribution never runs on that path, because it is never invoked outside review-package or code-reviewer.md. W.10's SessionStart hook (session-init.ts, shipped the day before this incident) already fires on every session start in this repo, but only prints a banner when .digismith/profile exists — and this repo deliberately never sets that file, so the one proactive mechanism that could have surfaced a reminder here already runs and already does nothing. Filed as backlog/attribution-guard-blind-spot-adhoc-commits-w.md, a third gap distinct from W.8's own final review's two already-logged and deliberately deferred gaps (PR-description checking, no escape hatch for pre-policy history) — both untouched by this pass.

Two independent, non-exclusive fixes, matching the backlog item's own framing: a reactive git hook that fires on any commit regardless of flow (the one that would have actually caught this incident), and a proactive SessionStart reminder as defense in depth. Both are built here.

Section 1 — Shared attribution pattern

New file, single source of truth for the regex both consumers need:

#!/usr/bin/env bash
# Shared regex for detecting AI/assistant attribution in commit messages.
# Sourced by scripts/git-hooks/commit-msg (fires on every commit to this repo)
# and skills/subagent-driven-development/scripts/check-attribution (fires on a
# commit range inside review flows). Edit this one file, not either caller.
export ATTRIBUTION_PATTERN='co-authored-by:.*claude|co-authored-by:.*anthropic|generated with.*claude|generated with.*anthropic|🤖'

Path: scripts/git-hooks/attribution-pattern.sh. check-attribution changes exactly one thing: its inline pattern='...' line becomes a source of this file, resolved relative to the script's own location (3 directories up from skills/subagent-driven-development/scripts/ to the repo/plugin root, then into scripts/git-hooks/) — never git rev-parse --show-toplevel, since check-attribution ships inside the vendored plugin and must resolve the same way whether it is running against DigiSmith's own repo or an installed plugin cache inside a consumer repo. No behavior change to check-attribution beyond this — same loop, same per-commit output, same exit codes.

Section 2 — The commit-msg hook

New file scripts/git-hooks/commit-msg (git's fixed name for this hook — not pre-commit, which fires before a message exists at all). Executable, sources Section 1's pattern file, reads the message git passes as $1, and on a match prints the offending line to stderr and exits 1 — blocking the commit. Same failure wording as check-attribution's own:

#!/usr/bin/env bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$SCRIPT_DIR/attribution-pattern.sh"

msg_file="$1"
body=$(cat "$msg_file")
match=$(printf '%s\n' "$body" | grep -iE "$ATTRIBUTION_PATTERN" || true)

if [ -n "$match" ]; then
  echo "AI attribution found in commit message:" >&2
  echo "$match" >&2
  echo "This repo forbids AI/assistant attribution anywhere — no exceptions." >&2
  exit 1
fi

Fires on every commit to this repo — ad-hoc, merge, amended, whatever the flow — since git invokes commit-msg unconditionally (barring --no-verify) once a message is collected and before the commit object is written.

Section 3 — Automatic install via prepare

package.json gains one script:

"scripts": {
  "test": "vitest run",
  "prepare": "git config core.hooksPath scripts/git-hooks"
}

Both npm and pnpm run prepare automatically on every pnpm install — which already runs in every fresh worktree per using-git-worktrees' own setup step, so this needs no separate onboarding instruction.

Why the value must stay relative. core.hooksPath is stored once, in the shared common .git/config every worktree of this repo reads — but git resolves a relative value against whichever working tree is currently active at hook-invocation time, not against wherever it was set. Writing the literal string scripts/git-hooks (never an absolute path) means every worktree runs its own checked-out copy of the hook — including one mid-edit on this very script. An absolute path, by contrast, would pin every worktree to whichever one happened to run pnpm install first. Section "Testing" below proves this live rather than trusting the claim.

No existing hook infrastructure to preserve or collide with: git config core.hooksPath is confirmed unset today, no husky, no .git/hooks/* beyond git's own untouched .sample files. The prepare script overwrites unconditionally.

Section 4 — SessionStart reminder

scripts/session-init.ts gains one new exported helper, matching this file's existing style of taking an explicit path rather than reading process.cwd() internally (so it stays unit-testable without process.chdir()), mirroring scripts/model_offload.ts's own isDigismithRepo() check one level up:

export function isDigismithRepoRoot(pluginJsonPath: string): boolean {
  if (!isFile(pluginJsonPath)) return false;
  try {
    const config = JSON.parse(fs.readFileSync(pluginJsonPath, "utf8"));
    return config?.name === "digismith";
  } catch {
    return false;
  }
}

main() gains one more independent statement after its existing banner logic — not threaded through buildBanner/formatBanner, so both signatures and every existing test for them are untouched:

if (isDigismithRepoRoot(path.join(process.cwd(), ".claude-plugin", "plugin.json"))) {
  console.log("DigiSmith: no AI attribution in commits or PRs — no exceptions");
}

Fires whenever the session's cwd is DigiSmith's own repo root, independent of whether .digismith/profile also produced a banner line — in practice the two never coexist today (profile is deliberately never set in DigiSmith's own repo), but the checks stay genuinely independent rather than special-cased against each other.

Section 5 — Error handling

CaseDisposition
commit-msg hook missing or not executable Git silently skips a missing hook file; a present-but-non-executable one is a build mistake — caught by the live commit smoke test in Testing, not by inspection.
core.hooksPath already set to something else Confirmed unset today. The prepare script overwrites unconditionally — nothing to preserve.
Vitest fixture repos (real git init in os.tmpdir(), used by bump-plugin-version.test.ts and others) Unaffected. core.hooksPath is set in this repo's own shared config; a fresh, unrelated git init elsewhere never inherits it.
Merge commits commit-msg fires on these identically (barring --no-verify); no special case.
--no-verify used deliberately Bypasses the hook by design — git's own escape hatch, not this feature's problem to solve. Out of scope.

Testing

  • scripts/git-hooks/commit-msg.test.ts — new, same real-git-fixture style as bump-plugin-version.test.ts (temp repo via fs.mkdtempSync, no mocking): a commit whose message carries an attribution trailer is blocked (non-zero exit, message on stderr); a clean commit is allowed. Invoked directly via spawnSync against the hook script, not through a live git commit, for speed and isolation — the live-commit path is proven separately below.
  • scripts/session-init.test.ts — new cases for isDigismithRepoRoot (true for a tmp dir with .claude-plugin/plugin.json naming digismith, false otherwise) and for main() printing the reminder line in a DigiSmith-repo-shaped tmp dir with no profile. Every existing test in this file is unaffected: their tmp dirs never contain .claude-plugin/plugin.json, so isDigismithRepoRoot reads false and the new line never appears.
  • Scratch multi-worktree smoke test (run once during implementation, not committed): a second throwaway worktree of a scratch repo, core.hooksPath set once from the first, a commit with an attribution trailer attempted for real in the second worktree — proving the relative-path-resolves-per-worktree claim in Section 3, not just asserting it.
  • Live end-to-end check on this feature's own branch: once prepare has run in this worktree, attempt one real throwaway commit with a trailer and confirm git itself refuses it before any fixture-level test is trusted as the whole story.

Out of scope

  • W.8's own two already-logged, deliberately deferred gaps — PR-description checking (backlog/attribution-guard-pr-description-gap.md) and the pre-policy-history escape hatch (backlog/check-attribution-no-escape-hatch-for-pre-policy-history.md). Both untouched.
  • Extending the SessionStart reminder to print the full standards/global/commit-style.md content — one line only, matching the banner's own established terseness.
  • Any consumer-repo enforcement. Both pieces here are scoped to DigiSmith's own repo specifically — the prepare script lives in this repo's own package.json, and isDigismithRepoRoot gates the reminder the same way. A consumer repo's own commits are untouched by this pass; they still route only through check-attribution when they hit a formal review flow.
