Overview

Today, finishing-a-development-branch's Step 7 ("Offer to Clear Context") gives only a verbal warning about unresolved threads right before calling clear_session — its own text says "never write it to a file or a memory entry." Once the clear happens, the next session starts from nothing: no orientation on which map lineage/ticket the prior session was on, what shipped, or why the clear happened.

This build closes that gap with a minimal, Step-7-only change: right before clearing, Step 7 writes a 5-section markdown handoff to .digismith/sessions/<session-id>.md, and W.10's SessionStart hook (session-init.ts) gains a small addition that points to it whenever one exists. No new skill, no generalized "assemble sections from any ledger" mechanism — that broader idea (backlog/standard-handoff-format.md) stays open for ad-hoc/cross-session handoffs; this build only wires the Step-7-triggered case.

Settled Decisions

Scope

Step-7-only, no new skill

A fixed-shape write folded directly into Step 7. Not a generalized handoff-assembly mechanism.

Location

.digismith/sessions/ folder

One file per clear, named by the writing session's own CCD session_id — not a single overwritten slot.

Repo scope

Every DigiSmith-tracked repo

Same per-repo pattern as .digismith/profile/preferences.yml.

Trigger

Always write

Every Step 7 clear (Option 1/2 only) writes a file, even for a fully-resolved merge with nothing pending.

Sections

Reuse the 5 candidates verbatim

From backlog/standard-handoff-format.md's own study of 4 real hand-written handoffs.

Verbal warning

Replaced, not duplicated

The unresolved-thread scan now feeds the file's sections; the final chat summary just points to the path.

Lifecycle

Delete on genuine pickup

The reading agent deletes the file once it has actually used the content — not the hook script.

Label sourcing

No derivation mechanism

"Where this fits" is written from whatever Step 7 already knows in context — no branch-name parsing, no per-repo fallback logic.

Architecture

Two existing files change; nothing new is added beyond a .gitignore line:

  1. skills/finishing-a-development-branch/SKILL.md — Step 7's text is rewritten to write the handoff file instead of speaking a warning.
  2. scripts/session-init.ts — gains a check for .digismith/sessions/ and a pointer line in the printed banner when it's non-empty.
Ordering check (already safe): Step 7 runs after Step 6's worktree cleanup for Option 1 (Merge Locally), but Option 1's own script already cds to $MAIN_ROOT before merge/cleanup (skills/finishing-a-development-branch/SKILL.md:179-181), so by Step 7's turn cwd is the main repo root, not the deleted worktree. Option 2 (Create PR) never deletes the worktree at all (kept per the Quick Reference table), so cwd there stays the worktree throughout. Either way, writing relative to Step 7's current cwd lands somewhere that still exists, and clear_session's own description confirms a clear never changes a session's cwd ("the session keeps its folder") — so session-init.ts resolves the same relative path afterward with no special-casing.
Re-verified during final review: the concern raised was whether a Bash-tool-level cd (Option 1's move to $MAIN_ROOT) or a native worktree-entry actually relocates where Claude Code later spawns the next SessionStart hook's process — as opposed to some fixed, session-launch-time directory that never updates. Claude Code's own hooks documentation settles this directly: "cwd follows Claude: the cwd field in the hook's input JSON is the worktree root after Claude enters a worktree, and the new directory after Claude runs cd." session-init.ts reads process.cwd() (the hook process's own OS-level working directory), which this same behavior governs — so both Option 1's cd and a native worktree switch are safe, confirmed by the documentation, not just inferred from indirect evidence.

Components

Step 7 rewrite

  • Resolve the session's own CCD session_id via get_session ("self").
  • Compose the 5 sections (below) from what the session already knows — no parsing, no lookup.
  • Ensure .digismith/sessions/ is gitignored in this repo (one-time; see Error Handling).
  • Write .digismith/sessions/<session-id>.md.
  • Final chat summary points to the path instead of restating content inline.

session-init.ts addition

New pure functions alongside the existing readProfile/loadVoiceSummary style: a function to list .digismith/sessions/, tolerate a missing directory, and return the newest file by mtime; and a title-line reader (first line of the file, # stripped).

This does not feed into buildBanner — that function returns null whenever no .digismith/profile exists, which is always true for DigiSmith's own repo (profile deliberately unset, per W.11) and for any freshly-onboarded repo. The handoff pointer must print regardless of profile presence, so it's wired as its own independent check in main(), printed alongside (not nested inside) the existing unconditional attribution reminder and the profile-gated banner.

Fixed during final review: the pointer must name the specific file and instruct deleting it once used — the original text only said "see .digismith/sessions/," a directory, with no delete cue, so nothing ever shrank the folder back down. Only files ending in .md are considered a handoff (a stray desktop.ini/Thumbs.db/editor backup in that directory must never become "the newest title").

Ignore handling — revised during final review

Originally speced as a committed .gitignore line; changed to .git/info/exclude after the final whole-branch review found the commit approach unsafe. A bare, unscoped git commit (no pathspec) after git add .gitignore commits whatever else happens to be staged too — a real risk on the shared main checkout other sessions may be concurrently touching. Worse, in Option 2 (Create PR) the commit would land inside the just-opened PR, and from a detached HEAD the push would fail outright, leaving exactly the unpushed state this step exists to prevent.

.git/info/exclude avoids all three: it's resolved once via git rev-parse --git-path info/exclude, lives in the repository's common git directory (shared automatically across the main checkout and every worktree of the same repo — never per-worktree), and needs no commit or push at all. git check-ignore honors it exactly like a real .gitignore line. The tradeoff versus the original design: it's local-only, not version-controlled, so a genuinely fresh clone (a different machine, a from-scratch checkout) doesn't inherit it — Step 7's own check-and-append is cheap and idempotent, so this just means the first Step 7 run in any new clone repeats the one-time self-heal, exactly as already designed, only now against a file that never needs a commit.

Ensuring .digismith/sessions/ is actually ignored (by whichever mechanism) stays load-bearing for one more reason beyond keeping the working tree clean: it's the cheapest available signal that content read from that directory is Step 7's own output, not something an attacker could have committed into an untrusted repo before this feature ever ran there.

Data Flow

  1. Step 7 fires (Option 1 or 2 only) — cwd is already correct per the Architecture callout.
  2. Gather context already known from the conversation; compose the 5-section markdown.
  3. Ensure .digismith/sessions/ is gitignored.
  4. Resolve own session_id; write .digismith/sessions/<session-id>.md.
  5. Say the final summary (what shipped, path to the handoff), then clear.
  6. Next SessionStart fires (any trigger, same cwd) — session-init.ts checks the folder, finds the newest file, reads its title line, appends a pointer to the banner that names the specific file and instructs deleting it once used (added during final review — see below; the first draft only pointed at the directory, never telling the reader to delete anything).
  7. A human partner or the agent notices the pointer in a real conversation turn, reads the named file, and — once genuinely used — deletes it, per the pointer's own instruction.

Handoff File Format

.digismith/sessions/<session-id>.md — 5 sections, reused verbatim from backlog/standard-handoff-format.md:

SectionContent
Where this fitsMap item(s) or ticket key, links to the relevant design.html/plan.md, the branch/worktree path.
Status per unit of workExplicit done/in-progress/not-started per item, cross-checked against any existing ledger/progress file rather than restated from memory.
Exact resume pointThe next concrete action, named precisely enough that a cold session doesn't have to infer it.
Anything flagged but deliberately out of scopeA spawned background task, a deferred backlog note, a bug found in passing — named with its own tracking id/link.
Literal resume commandsThe actual cd/skill-invocation a session would run, not just a description.

The file's first line is an H1 title — this is what session-init.ts parses for the SessionStart banner's pointer text.

Error Handling

  • Missing/empty .digismith/sessions/ → banner unaffected, same "missing config is benign" precedent as G.2/H/P/W.10.
  • Multiple pending files (e.g. two finishes with no session reading either in between) → point to the newest by mtime; banner says "N handoffs pending" when N>1 rather than silently hiding the older ones.
  • get_session fails or returns no usable id at write time → fall back to an ISO-timestamp filename rather than blocking the write — "always write" stays true even if session-id resolution hiccups.
  • File write fails (disk/permissions) → report it, but never block the actual clear on it — this is an orientation aid, not a gate.

Testing

scripts/session-init.test.ts gains real-temp-dir-fixture unit tests (no mocked fs, matching W.10's own precedent) for: empty folder, single file, multiple files (newest wins), and a malformed/empty file (graceful fallback, no crash).

Step 7's own procedure is prose/process text, not unit-testable code — verified live, the same way H.1/H.2/X.1 were: this repo's own next real Step 7 clear is the first live test of the whole path.

Out of Scope

  • A generalized handoff-assembly skill (digismith:write-handoff or similar) that builds sections from any ledger/plan/design-doc context — the broader idea backlog/standard-handoff-format.md originally sketched. This build only covers the Step-7-triggered case; ad-hoc root HANDOFF-*.md files and cross-session SendMessage handoffs stay hand-written, unstandardized.
  • Cross-worktree propagation of .digismith/sessions/ (unlike .digismith/profile, which bootstrap copies into every fresh worktree). This content is thread-specific and ephemeral, not durable per-repo config, so it deliberately doesn't follow that precedent.
  • Structured JSON instead of markdown — rejected; every other DigiSmith-generated artifact is markdown/HTML, human-reviewable directly, and this content is fundamentally narrative.
