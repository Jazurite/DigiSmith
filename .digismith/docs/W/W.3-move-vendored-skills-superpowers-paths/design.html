Background

DigiSmith's vendored subagent-driven-development still writes every plan's scratch workspace (progress ledger, task briefs, implementer reports, review packages) to .superpowers/sdd/<plan-basename>/ — skills/subagent-driven-development/scripts/sdd-workspace hardcodes the upstream Superpowers location, never re-homed when the skill was vendored into DigiSmith. The same leftover .superpowers/ path shows up in 9 files across 4 vendored skills (subagent-driven-development, brainstorming, report-implementation, executing-plans), split across two unrelated scratch concerns: the SDD workspace, and the visual companion's mockup/session storage.

A second, pre-existing bug folds into the same fix: sdd-workspace derives its workspace name from basename "$plan" .md, but every DigiSmith plan file is literally named plan.md — under both the old flat docs convention (.digismith/docs/<slug>/plan.md) and the new nested one (.digismith/docs/<Letter>/<Letter>.<N>-<slug>/plan.md). Every plan in a given worktree resolves to the identical workspace, .superpowers/sdd/plan/. Two plans active concurrently in the same worktree would silently share one ledger and one set of task briefs/reports.

SDD Workspace Relocation

The workspace nests directly inside the plan's own folder — the same folder that holds design.html/plan.md/report.html — rather than a separate top-level scratch root. This also fixes the basename-collision bug for free: every plan already gets its own folder under both DigiSmith conventions, so nesting inside it means two different plans can never resolve to the same workspace directory.

Shared-bucket fallback (e.g. vanilla upstream Superpowers' own default docs/superpowers/plans/YYYY-MM-DD-<feature>.md, where every plan is a sibling file in one shared folder, not its own folder) docs/superpowers/plans/2026-09-26-foo.md docs/superpowers/plans/.sdd-workspace-2026-09-26-foo/

Detection rule in sdd-workspace: literal filename is plan.md → nest as .sdd-workspace beside it. Any other filename (the filename itself already carries the differentiating info) → sibling .sdd-workspace-<basename>. Each workspace directory writes its own self-ignoring .gitignore (*) — previously this was written once at the shared .superpowers/sdd/ root; now every workspace owns its own, since there's no longer a shared parent bucket to ignore.

The repo-root git rev-parse --show-toplevel lookup goes away entirely — the new location is derived purely from the plan file's own path, not the repo root.

Brainstorm Mockup Storage

The visual companion's mockup/session storage has no equivalent "feature folder" to nest into — mockups get created during brainstorming, before any docs folder exists, and the final <Letter>.<N>-slug> numbering isn't assigned until the design is approved and written. The feature's slug, however, is already known up front — digismith:bootstrap always derives one before handing off to brainstorming — so nesting keys off the slug instead of the final numbered folder.

start-server.sh gains an optional --slug <slug> flag:

  • Slug known (the normal case): SESSION_DIR="${PROJECT_DIR}/.digismith/brainstorm/${SLUG}/${SESSION_ID}" — mockups for this feature all land under one slug-keyed folder, even across server restarts within the same conversation.
  • No slug (fully ad-hoc brainstorming with no ticket/slug at all): SESSION_DIR="${PROJECT_DIR}/.digismith/brainstorm/${SESSION_ID}" — today's flat scheme, just the .superpowers→.digismith rename, no nesting.

visual-companion.md's own invocation examples get updated to pass --slug <slug> whenever brainstorming already has one.

Testing / Verification

No existing test harness applies here — these are plain shell scripts under skills/, not packages/* TypeScript (where Vitest is the standing default). Verification is manual:

  • Run sdd-workspace directly against three sample plan paths: nested (.digismith/docs/W/W.3-foo/plan.md), old-flat (.digismith/docs/foo/plan.md), and a non-plan.md name (docs/superpowers/plans/2026-01-01-foo.md) — confirm each resolves to the right folder and writes its own .gitignore.
  • Run start-server.sh once with --slug and once without — confirm SESSION_DIR nests under the slug in the first case and falls back to flat in the second.
  • Grep the repo afterward for any remaining .superpowers reference to confirm nothing was missed.

Out of Scope / Deferred

  • Plugin cache propagation — a running session executes these scripts from the installed plugin cache, so this repo-side fix only takes effect after a reinstall/version bump. Not this ticket's job to trigger that.
  • Migrating any already-existing .superpowers/ scratch directories on disk — these are gitignored, ephemeral, and self-cleaning (deleted on plan completion); nothing to migrate.
