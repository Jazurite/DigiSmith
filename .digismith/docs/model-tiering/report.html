Summary

Offload two of DigiSmith's own mechanical HTML-generation steps — enforcer's rewrap correction and report-implementation's template render — to a Chutes-hosted open-weight model, with silent fallback to today's in-session generation whenever offload isn't configured, unavailable, or fails. A single shared script (scripts/model_offload.py) reads a new model_offload_provider profile field, fetches the Chutes API key from the credential store chutes-ai already manages, POSTs a prompt to Chutes' chat/completions endpoint, and returns the result over a simple exit-code contract; enforcer and report-implementation each call it at one specific point in their existing process, falling back to their current in-session behavior on any non-zero exit. Followed the full Superpowers process: brainstorming → spec → writing-plans → superpowers:subagent-driven-development (4 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 5 fix rounds before merge.

Reference documents: the design spec and the implementation plan.

This report itself was generated in-session, not via Chutes: an offload attempt was made per report-implementation's own new Step 3, and it failed with offload: failed (connection error: The read operation timed out) — a real-world confirmation that the fallback contract holds under an actual failure, not just simulated ones.
