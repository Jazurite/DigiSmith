Summary

Toolchain (map item U) gives Jack a standing, dictatable list of tool/technology defaults (test runner, styling, E2E framework, script language, package manager, Node install method) so digismith:brainstorming stops re-asking questions it can already answer. A small TypeScript module (scripts/toolchain.ts) reads/writes a flat, repo-root toolchain.yml — no YAML library, the same parsing convention as scripts/preferences.ts — wrapped by a thin CLI (--action/--domain/--value) and a single skill, skills/toolchain/SKILL.md, the only thing any consuming skill or Jack ever calls. One new subsection in skills/brainstorming/SKILL.md's clarifying-questions guidance runs list before a tooling question and either states the assumption or asks as normal. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (3 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 2 fix round(s) before merge.

Reference documents: the design spec and the implementation plan.

Ready to merge: With fixes — 1 Critical, 1 Important, and 1 Minor finding, all fixed in one round.

SeverityFindingResolution
Critical skills/toolchain/SKILL.md's documented invocation never required --path <digismith-repo>/toolchain.yml when working outside DigiSmith's own repo, so the global store would silently resolve against the wrong (caller's) cwd — a client repo could end up with a stray toolchain.yml, or the feature would silently no-op. Fixed (befe971) — added explicit guidance requiring --path whenever cwd isn't DigiSmith's own repo, and corrected the --path paragraph that previously said it was test-only.
Important The digismith:brainstorming consult subsection was missing the design's "ambiguous match → ask as normal rather than guess" rule for a queued question that could plausibly map to more than one stored domain. Fixed (befe971) — added an "Ambiguous match" bullet between "Match found" and "No match".
