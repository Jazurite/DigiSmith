Goal and scope

This is part 1 of the review pipeline for milestone DGS-110 (Agentic Architect Prototype). It gives DigiSmith one official reviewer: OpenCode on TokenReply, with GPT-6 models, running in Workbox. Workbox is Jack's name for herdr on the VPS.

The pipeline is independent. It does not know about subagent-driven-development, tasks, review prompts or .sdd-workspace. It does one thing: another session gives it a prompt and a directory, the reviewer reviews, and the pipeline returns the answer.

The manual steps from the V.8 run (DGS-78) that this part removes: start the reviewer and send it the prompt (step 2), answer OpenCode's permission prompt (step 3), and get the answer out (step 4). Step 1 (move the review package to the VPS) is already gone, because the VPS is the only machine. Step 5 (tell the implementer) is gone when the caller runs the review itself.

Style for this ticket only (Jack): functional. Each procedure (init, review, stop) is an independent function with explicit inputs and outputs. The only shared state is the roster file, and each function reads or writes it explicitly. Pure functions (grade to model, answer extraction, header format) are separate from side effects (herdr commands, opencode run, file writes).

The reviewer in Workbox

The reviewer has one dedicated workspace: w6, label DigiSmith ⚚ opencode-sol. This is the workspace of the V.8 run.

TabRunsPurpose
w6:t1 (pane w6:p1)opencode serve --hostname 127.0.0.1 --port 4097The reviewer server. Every review goes here.
watch tabopencode attach http://127.0.0.1:4097A TUI on the same server. Jack attaches to Workbox and sees each review live.

There is one reviewer at a time. More than one reviewer is DGS-130.

The functions

Side-effect functions (the edges)

FunctionInOutWho calls it
initroster path, workspace (w6), port (4097)the roster, status runningThe caller, only when health says down. If the reviewer is already up, init returns the roster that exists and starts nothing.
healththe rosterup or downAny session, before a review. up means an HTTP GET to the server URL answers with status 200 in 3 seconds.
reviewprompt (a file path, whose text is sent as the message, or the text itself), directory, grade (optional), title (optional, default review <UTC time>), output path, the rostera result: status, model, session ID, duration, tokens, output pathAny session. It never starts OpenCode. If health is down, it returns status no-reviewer.
stopthe rosterthe roster, status stoppedOptional, when RAM is tight.

Pure functions

  • gradeToModel(grade): returns the model ID for a grade (see Grades and models). No grade gives complex. An unknown grade is an error.
  • extractAnswer(events): takes the JSON events of one opencode run and returns the final assistant text, the session ID and the token counts. It returns nothing when there is no final text.
  • formatAnswerFile(result, text): returns the answer file: a front-matter header, then the reviewer's text unchanged.

How init starts the reviewer (herdr commands)

herdr pane run w6:p1 'set -a; . ~/.digismith-depot/.env; set +a; exec opencode serve --hostname 127.0.0.1 --port 4097'
herdr tab create --workspace w6 --label watch --no-focus
herdr pane run <watch pane> 'opencode attach http://127.0.0.1:4097'

<watch pane> is the pane ID that herdr tab create returns. init writes it to the roster.

The pane's own shell reads TOKENREPLY_API_KEY from ~/.digismith-depot/.env. The key does not appear in any agent's command, output or transcript.

stop sends ctrl+c to w6:p1, closes the watch tab, and writes status stopped to the roster.

The Workbox roster

The roster tells every session which reviewer to use. It is ~/.digismith-depot/workbox.json, in Depot's folder, so sessions in every repo (DigiSmith, Emma) find the same reviewer. init and stop write it. health and review read it.

{
  "reviewer": {
    "kind": "opencode",
    "status": "running",
    "workspace": "w6",
    "server": "http://127.0.0.1:4097",
    "panes": { "server": "w6:p1", "watch": "<watch pane>" },
    "provider": "tokenreply",
    "agent": "reviewer",
    "models": { "simple": "gpt-6-sol", "complex": "gpt-6-luna", "extra-complex": "gpt-6-astra" },
    "started": "2026-09-29T14:00:00Z"
  }
}

Other Workbox roles, such as the worker slots in the runbook table, can go in the same file later.

Grades and models

The caller passes a grade. The pipeline owns only the map from grade to model. The grading rules (what makes a change simple or complex) belong to the caller. For SDD they go to DGS-129.

GradeModelFor example
simpletokenreply/gpt-6-sola text-only change, a small diff
complex (the default)tokenreply/gpt-6-lunaa normal task review
extra-complextokenreply/gpt-6-astraa whole-branch review

The map is in the roster, so a change of model is a one-line edit. TokenReply's API and models page do not say how the GPT-6 variants differ. The spike checks each one on a real review, and the map changes if the result shows a different order.

Cost does not decide the map. In the V.8 run, a task review used 10k to 35k tokens and the whole-branch review about 650k. At TokenReply's listed rates that is less than a cent for a task review.

One-time setup

  1. Models. Add gpt-6-sol, gpt-6-luna and gpt-6-astra to the tokenreply provider in ~/.config/opencode/opencode.json. Today it lists only gpt-5.6-sol and kimi-k2.7. Back up the file first.
  2. Read-only reviewer agent. Add an OpenCode agent named reviewer to the same file. File edits are denied. Shell commands are limited to read-only git: git show, git diff, git log, git grep. In the V.8 run, Sol once ran a build in a checkout it was told not to change. With this agent, OpenCode enforces read-only, not only the prompt.
  3. No permission prompt. Each review runs with --dir <directory>, and the prompt tells the reviewer to read files in that directory. Files inside the session's own directory are not external, so OpenCode's external_directory prompt does not appear.

One review, step by step

  1. The caller calls health. If the answer is down, the caller calls init, then continues.
  2. review gets the model from gradeToModel(grade).
  3. review runs, in the background: 
    opencode run --attach http://127.0.0.1:4097 --dir <directory> --agent reviewer \
  -m tokenreply/<model> --format json --title "<title>" "<prompt>" \
  > <output path>.events.jsonl
    It runs in the background because a whole-branch review took about 9 minutes in the V.8 run, near the Bash tool's 10-minute limit.
  4. When the run ends, extractAnswer reads the events file, and formatAnswerFile writes the output file: 
    ---
reviewer: opencode
model: tokenreply/gpt-6-luna
grade: complex
session: ses_...
duration_s: 48
tokens: { input: 9675, output: 974 }
status: ok
---
<the reviewer's final answer, unchanged>
  5. review returns the result and exits with 0.

Errors

review always writes the output file, with a status in the header, so the caller has a record. The caller decides what to do next, for example start the reviewer or fall back to a Claude reviewer.

StatusExitWhen
ok0The reviewer gave a final answer.
no-reviewer2No roster, or health is down. The caller calls init and tries again.
model-rejected3TokenReply or OpenCode refuses the model.
no-answer4The run ended without final text, for example after broken tool calls. In the V.8 run, one session got a leaked <|tool_call_start|> as its title.
timeout5The run took more than 20 minutes. Before it stops the run, review reads the session's live progress with GET /session/<id>/message (found in V.1, see DGS-102) and puts the last progress in the output file.

Testing: the spike

Jack asked for a spike in a scratchpad. It proves each step live. Script language: TypeScript (Jack's standing default). Unit tests for the pure functions come with the CLI in DGS-131.

  1. Setup. Back up opencode.json, then add the GPT-6 models and the reviewer agent.
  2. Init with herdr. Start the server in w6:p1 with the key from the Depot file. Check that the classifier allows the command and that health is up.
  3. Watch tab. Open opencode attach in a second w6 tab.
  4. Roster. Write ~/.digismith-depot/workbox.json.
  5. One real review per grade. Replay the archived V.8 task-5 review prompt (.digismith/sessions/workbox-archive/2026-09-26-v8-sol-review/) on gpt-6-sol, gpt-6-luna and gpt-6-astra. The code comes from the reviewed commit with git archive into the scratchpad, not from a new worktree. For each model, check that: the tool calls work, there is a final answer, the answer finds the known --folder "" bug, and no file changed.
  6. Errors. Run one review with the server stopped (expect no-reviewer, exit 2) and one with an unknown model (expect model-rejected, exit 3).
  7. Stop with herdr. Send ctrl+c to the server, close the watch tab, and check that the roster says stopped.
  8. Record. Add a Reviewer section to the Workbox runbook (.digismith/sessions/workbox.md) and put the results on DGS-127. Save the spike scripts next to the runbook, so DGS-131 can build on them.

Pass: steps 2 to 7 work with no manual step by Jack, and the results confirm or change the grade map.

Out of scope

  • DGS-129: the hook into subagent-driven-development, which covers review prompts, the grading rules, checking the reviewer's claims, and the fallback to a Claude reviewer.
  • DGS-131: the dg workbox commands that turn these functions into a CLI.
  • DGS-130: more than one reviewer at a time.
  • Choosing between messaging channels. opencode run --attach with JSON events is the channel. The V.8 route (TUI, herdr agent prompt, opencode export) is not used, because it needs scraping and a model switch in the TUI.

Decisions (Jack, 2026-09-29)

  • The pipeline is independent: prompt in, answer out.
  • OpenCode has one dedicated space in Workbox, w6. A file (the roster) tells future sessions which one is the reviewer.
  • The review call does not start OpenCode. If the reviewer is not running, the caller starts it.
  • The server is started with herdr commands in this ticket. The CLI comes later (DGS-131).
  • The key comes from ~/.digismith-depot/.env.
  • Grades: simple is gpt-6-sol, complex is gpt-6-luna, and extra-complex (whole-branch) is gpt-6-astra. The caller passes the grade.
  • The one-reviewer limit is logged for later (DGS-130).
  • Functional style, for this ticket only.
