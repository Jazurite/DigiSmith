Goal and scope

Spread herdr worker load across the Claude subscription seats on the VPS (today jack and dev0, a third seat planned). The balancer chooses the account when a worker starts. That is a cold-cache point, so the choice costs no re-read. Each pane loads its own account. The VPS-wide default account stays unchanged.

Step 0 of the ticket (pooling the seats under Anthropic's terms) was approved by Jack on 2026-10-03.

This build is the first slice of DGS-139 build 2: a new dg workbox command group in packages/cli/src/workbox/ with start, list, stop and exhaust, the roster file, and the v1 assignment algorithm. Jack chose this scope (account-aware core in packages/cli) on 2026-10-03, over a separate packages/workbox package and over a balancer-only build.

Findings that shape the design

  • dg workbox does not exist on main (5f05667). The command groups are vps, depot and clickup. There is no packages/workbox. DGS-139 is a backlog proposal.
  • claude-account env prints the token of the active account only. It has no env <name> form. So CLAUDE_ACCOUNT=<name> alone cannot load a named token. The pane must read <accounts dir>/<name>.token itself, inside the pane, as the ticket says.
  • ~/.bashrc runs eval "$(claude-account env)" in each new shell. A pane-side load that runs after it wins.
  • herdr --session <s> agent list returns the live agents with their pane, workspace and session ID. This is the liveness source for the roster.
  • The runbook roster (.digismith/sessions/workbox.md) is a markdown table kept by hand. The balancer needs a file a program can read.

The start flow

dg workbox start <agent> --repo <path> --label <text> [--account <name>] [--pane <id>] [--session DigiSmith] [-- <claude args>]

  1. Resolve the account. An explicit --account that is exhausted is an error. Without it, pickAccount chooses.
  2. Without --pane: workspace create --env CLAUDE_ACCOUNT=<name>. With --pane: reuse the existing slot.
  3. Run the load command in the pane. Read the pane back for the line workbox account: <name>. If it is missing, stop before claude starts.
  4. agent start <agent> --kind claude --pane <id>, passing the claude arguments after --.
  5. Write the roster entry and lastAssignedAt only after the agent is ready.

The --env CLAUDE_ACCOUNT=<name> value carries a name, never a token. The load in step 3 does the real work, and it is the same for a new workspace and for an existing slot.

Roster rules

  • The roster key is (herdr session, agent name). start on an existing agent name replaces that entry, so a worker never appears twice.
  • When start --pane re-seats a worker, pickAccount does not count that worker's own old seat. Otherwise a handoff would see its own account as busier. With this rule, two accounts and one slot alternate through the least-recently-assigned tie-break. This is the round robin that the ticket chose for handoffs.
  • lastAssignedAt and exhaustedUntil belong to the account, not the worker, so they survive stop.
  • exhaustedUntil takes an ISO time with an offset. list shows times in UTC+7 first, with UTC in brackets. An expired mark is ignored and removed on the next write.
  • stop <agent> closes the workspace and marks the entry stopped. It does not delete the entry.

Switch flows

Handoff switch

The runbook steps 2 to 4 become: /exit, then dg workbox start <agent> --pane <pane> -- --name "<key>: <ticket> <name>". The command picks the account, loads it, checks it, starts the agent and updates the roster. The claude-account next step goes away, so the VPS-wide default stays unchanged for other sessions.

Limit-stop move

The maestro runs dg workbox exhaust <account> --until <time>, then /exit, then dg workbox start <agent> --pane <pane> -- --resume <session id>. pickAccount skips the exhausted account on its own. This move costs one full re-read and loses a running subagent, as the runbook states.

Errors

CaseResult
claude-account missing, or no accounts listedStop with a clear message. No herdr call.
All accounts exhaustedStop. Name the earliest reset time.
The pane does not print workbox account: <name> in timeStop. Print the pane tail. The check prints only the name, so no token can appear. No agent starts.
agent start fails after a new workspace was createdReport the workspace ID and leave it open. Closing it automatically could destroy work. The roster stays unwritten.
Roster file is corrupt or has an unknown versionStop and name the file. Never overwrite it.
Two maestros write at onceThe advisory lock serializes the read-modify-write cycle.

Tests

Vitest in packages/cli, the same way as vps/.

  • balancer: table tests for exhausted skip, an expired mark, fewest workers, oldest lastAssignedAt, never-assigned first, the name tie-break, own-seat exclusion, all exhausted, and three accounts.
  • roster: temp directory, atomic write, unknown-version refusal, corrupt-file refusal, the lock under two writers, and reconcile against a fake agent list.
  • herdr and the commands: an injected runner records every herdr call. Tests check the call order (workspace create --env CLAUDE_ACCOUNT=…, pane run, pane read, agent start), that the roster is written only after agent start succeeds, and each failure path above.
  • Token safety: a temp CLAUDE_ACCOUNTS_DIR holds a sentinel token. One test runs the real load command in a real bash subprocess. It asserts that only workbox account: <name> is printed and that the shell holds the sentinel afterward. Another asserts that no recorded herdr argument, stdout or stderr contains the sentinel. A third shows that the pane-side load wins over the shell's active-account export.
  • A fake claude-account stub on PATH covers list. No test touches the real ~/.config/claude-accounts/.

The build does not run live herdr or real-token commands. The real proof is the first handoff switch with dg workbox start --pane on a live worker, run by the maestro when the VPS has RAM headroom.
