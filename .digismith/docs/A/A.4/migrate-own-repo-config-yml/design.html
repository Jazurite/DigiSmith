Goal

DGS-141 shipped .digismith/config.yml and a reader that falls back to the old files. DigiSmith's own repo still tracks .digismith/profile and .digismith/preferences.yml, so every session here reads through the fallback. This ticket moves this repo onto config.yml, so new features (the role key in DGS-139 first) never touch the legacy path.

What changes

  • git mv .digismith/profile .digismith/profile.migrated and git mv .digismith/preferences.yml .digismith/preferences.yml.migrated. The history stays traceable.
  • New .digismith/config.yml, generated by migrate in a scratch copy and not typed by hand. Expected content: the header line, profile: digismith, then preferences: with finish_option: merge_locally, clear_context: no and ssh_key: /root/.ssh/jazurite_github. The old profile file has CRLF line endings, so the result must show the reader strips them.
  • New test scripts/own-repo-config.test.ts (next section).
  • No reader changes. Only scripts/session-init.ts and scripts/model_offload.ts read the profile, and both go through the shared resolve.

Approaches

Chosen

A: branch in a worktree

Generated config.yml plus the test, as the ticket describes. migrate refuses to run in a linked worktree, so the scratch copy is how its output is obtained.

Rejected

B: run migrate on main

Breaks the rule of never committing on the base branch, and leaves no test that guards the result.

The migration test

  • Copy the committed *.migrated files into a temp dir (not a git repo), restore the old names, run migrate, and assert that its config.yml equals a pinned literal. The inputs are frozen, so this guards migrate and the .migrated files.
  • Against the real repo: the live config.yml carries every key the migration produced, and profile, finish_option, clear_context and ssh_key resolve from config.yml and not from the fallback.
  • The test does not compare values in the live config.yml. digismith:preferences can change them later with a legitimate set, and a test that fails after one would be wrong. This replaces the first draft's "live file equals migrate's output" (refined while planning, 2026-10-03).
  • The ticket that removes the fallback and the .migrated copies also deletes this test.

Verification and finish

  • Full suite: the only failures are the two known DGS-117 tests (process-lifecycle.test.ts netstat check, index.e2e.test.ts --help check).
  • From the worktree: preferences.ts --key finish_option --action get prints merge_locally, and session-init.ts prints profile=digismith.
  • Commit message: chore(config): migrate to .digismith/config.yml, title only, no attribution lines.
  • Finish: merge locally into main (the saved finish_option) and push. The post-finish hooks run as usual.

Accepted risk

The Gradion Mac Desktop may still upload DigiSmith 0.57.0-beta into its VPS sessions, and a session on that plugin would read no profile in this repo. Jack decided on 2026-10-03 to build and merge now and accept that. The VPS plugin cache holds only 0.72.0-beta.
