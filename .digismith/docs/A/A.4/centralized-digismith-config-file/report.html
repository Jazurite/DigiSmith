Summary

This ticket puts every per-folder DigiSmith setting into one .digismith/config.yml. One shared reader reads it, and falls back to the old .digismith/profile and .digismith/preferences.yml files. Three new modules in scripts/ do the work: config-parse.ts parses a small YAML subset with no library, config-write.ts edits the file text in place, and config.ts reads layers (the new file, then the old files), writes atomically, guards writes in worktrees and tracked checkouts, migrates the old files, and exposes a CLI. preferences.ts becomes a thin wrapper that maps bare preference keys to preferences.<key>. The SessionStart hook, model_offload.ts, and 12 skills now read through the new reader.

Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (12 tasks, each dispatched to a fresh implementer subagent and independently reviewed), with 2 fix rounds, across Tasks 9 and 11. A separate whole-branch review (external, by Sol/OpenCode) found 10 further findings after the build finished. All 10 are fixed and re-reviewed clean before this merge — see Final Review & Fix below.

Reference documents: the design spec and the implementation plan.

Note on this report's own provenance: the per-task SDD ledger (.sdd-workspace/progress.md) that normally feeds this report was lost when the branch's worktree was removed during digismith:finishing-a-development-branch — it is gitignored scratch, and this skill's own trigger point (before that deletion) was missed this run. This report was reconstructed by hand afterward, from the plan file, git log, and the controller session's own verified record of every task, review, and fix round. Nothing in it is invented; the per-task detail below matches what was reported live, turn by turn, during the build.

What Was Delivered

Task 1

YAML-subset parser

parseConfig/parseConfigDocument read .digismith/config.yml's grammar: top-level keys, one level of headings, arrays, comments, and errors with exact line numbers.

Task 2

In-place text writer

setInText/clearInText edit the file in place, keeping comments, key order, and quoting rules intact.

Task 3

Layered reader with the fallback

resolve() reads config.yml first, then falls back to the old .digismith/profile and .digismith/preferences.yml files, per key.

Task 4

migrate and its report

migrate() merges the old files into config.yml, moves them aside to *.migrated, and reports what it did.

Task 5

Guarded writes and the CLI

setKey/clearKey stop in a tracked checkout or a linked worktree that still has an old file; config.ts's CLI exposes get/set/clear/migrate.

Task 6

preferences.ts wrapper and voice scripts

preferences.ts becomes a thin wrapper over config.ts; voice.ts and voice-init.ts read through the new .digismith folder.

Task 7

SessionStart hook

The hook reads the profile through resolve(), and warns instead of failing on a config parse error.

Task 8

model_offload.ts

Reads the profile through resolve(); its CLI flag is now --dir, not --profile-path.

Task 9

Profile rules in the reading skills

7 skills read profile through config.yml with the old-file fallback, in one exact sentence pair.

Task 10

bootstrap and adopt migrate flow

Both skills migrate untracked old files automatically, print commands for tracked ones, and copy config.yml into new worktrees.

Task 11

Storage docs

digismith:preferences, voice, toolchain, offload-implementer, and the README now describe config.yml, not the old files.

Task 12

Full suite against the baseline

Confirms no regression: the same 2 pre-existing failures, every new and changed test passing.
