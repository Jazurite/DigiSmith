1. Context and decisions

Per-folder DigiSmith state is in two files of different shapes. .digismith/profile is one line. .digismith/preferences.yml is flat key: value. The maestro role (DGS-139, O.3) adds a third setting, role. This ticket puts all per-folder settings in one file. The settings stay with their owners: profile (O.0), role (O.3), preference keys (O.1), voices (T).

QuestionDecision (Jack, 2026-10-02)
File name and format.digismith/config.yml, YAML, one level of headings. Read by a hand-written parser with no library, so the plugin cache (no node_modules) stays safe.
Global layerLater. The reader keeps an ordered list of layers, so a global layer is a one-line addition.
Old filesReadable through a fallback until a follow-up removal ticket. migrate runs on the main checkout. Old worktrees keep the fallback until they are removed.
Flat or nestedTop-level keys plus one level of headings, addressed as heading.key.
SessionStart hookscripts/session-init.ts reads the profile through the shared reader. Its output stays the same.
ApproachNew scripts/config.ts. preferences.ts becomes a thin wrapper. Skills read the YAML file directly with one shared sentence.
Auto-commitNo commit on the base branch. This ticket's branch migrates DigiSmith's own repo as part of the feature.

2. The file and its parser

One .digismith/config.yml per checkout. Example:

# DigiSmith config for this checkout. Edit by hand or through digismith:preferences.
profile: digismith
role: worker
finish_option: merge_locally
ssh_key: /root/.ssh/jazurite_github

maestro:
  poll_interval: 60
  watch_sessions:
    - DigiSmith
    - emma

Grammar

LineExampleResult
Blank line or # comment# noteIgnored
Top-level keyprofile: digismithprofile → "digismith"
Heading: key: with no value, next significant line is key: value indented 2 spacesmaestro:Opens section maestro
Key in a section, exactly 2 spaces  poll_interval: 60maestro.poll_interval → "60"
Array: key: with no value, next significant line is - item indented 2 spaces (top level) or 4 spaces (in a section)  - https://a.comkey → ["https://a.com"]

A "significant line" is a line that is not blank and not a comment.

Rules

  • Keys match [a-z0-9_]+. All current keys match.
  • Every value is a string. The parser does no type conversion, so no and 08 stay text. The key's owner converts a value when it must.
  • A value that starts with " or ' runs to the matching closing quote. Everything inside is part of the value, # included. After the closing quote, only spaces or a # comment can follow.
  • Escape sequences are not supported. \ is a literal character. A value that contains one quote type uses the other quote type.
  • An unquoted inline comment starts at # (space, then #), so https://x.com/#a stays whole.
  • The parser removes a trailing CR on each line (CRLF files, DGS-116) and a leading UTF-8 BOM.

Errors

The parser stops with config.yml line <n>: <reason> for:

  • a tab in the indentation, or an indent other than 2 or 4 spaces where allowed
  • a second level of headings
  • an indented line with no heading or array above it
  • an unindented - item under a key (the message names the required indent)
  • a key: with no value and no indented line after it (empty heading or array)
  • flow syntax ([a, b], {a: b}) or a block scalar (|, >)
  • text after a closing quote that is not a comment
  • a duplicate key
  • a key that does not match [a-z0-9_]+

The parser returns Map<string, string | string[]>, keyed by top-level names and heading.key paths.

3. Reading, writing, and the fallback

scripts/config.ts exports these functions. Each takes the .digismith folder, default .digismith under the current folder.

  • readConfig(dir): parse config.yml. A missing file gives an empty map.
  • resolve(key, dir): return { value, source }, or undefined.
  • setKey(key, value, dir) and clearKey(key, dir).
  • migrate(dir): see section 4.

Read order (per key, first hit wins)

  1. .digismith/config.yml
  2. The old files. profile comes from .digismith/profile, read as readProfile reads it today: strict UTF-8, trimmed, empty means unset. Every other key comes from .digismith/preferences.yml, read with the same parser (today's flat file is valid in the subset).

source names the file that supplied the value.

Writes

  • Writes go only to config.yml.
  • In-place edit. The writer keeps comments, blank lines and key order. set on an existing key replaces only its value and keeps its inline comment. A new top-level key goes after the last top-level key, before the first heading. A new section.key goes at the end of its section. A missing section gets its heading at the end of the file. clear removes the key's line, and its item lines for an array. A heading with no keys left is removed.
  • New file header: # DigiSmith config for this checkout. Edit by hand or through digismith:preferences.
  • Quoting. Plain when safe. Double quotes when the value is empty, has a leading or trailing space, starts with a quote, or contains #. Single quotes when the value contains ". A value with both quote types is an error.
  • set writes scalars only. Arrays are edited by hand until a key needs them.
  • Atomic. Each write goes to .digismith/.config.yml.<pid>.tmp, then a rename moves it to config.yml. A crash or two sessions writing at once never leaves a half-written file. With two writes at the same time, the last rename wins.
  • Writes migrate first. In a main checkout that still has an old file, setKey and clearKey run migrate before they write. Without this, a clear would let the old value come back through the fallback. The output reports the migration and, where git tracks the old files, commit needed.
  • Linked worktree guard. In a linked worktree (git rev-parse --git-common-dir differs from --git-dir) that still has an old file, setKey and clearKey stop and change nothing: config: failed (this worktree still has .digismith/profile or preferences.yml. Run migrate in the main checkout <path>, then remove or recreate this worktree). Reads still work. A folder outside a git repo counts as a main checkout. The hook never writes, so it makes no git call.

preferences.ts and voice.ts

preferences.ts becomes a thin wrapper over config.ts. It keeps get, set, clear and the unset output, and adds migrate. --path is replaced by --dir (the .digismith folder). Only preferences.test.ts, voice.test.ts and the digismith:preferences SKILL.md use --path. voice.ts keeps its API and reads through the wrapper.

4. Migrate

node --experimental-strip-types <digismith>/scripts/config.ts --action migrate [--dir <.digismith folder>]

All checks run before any change, so a stop leaves the folder unchanged.

  1. In a linked worktree: stop with the guard message from section 3.
  2. Classify each old file on its own:
    Original.migrated copyAction
    presentabsentMigrate it
    absentpresentSkip (already moved)
    presentpresentStop
    absentabsentNothing to do
    If no file needs migration, print config: nothing to migrate and exit 0.
  3. Read config.yml (if present) and each old file to migrate. Add each old key that config.yml does not have, through the in-place writer, profile first. A key in both files with different values: config.yml wins, the output lists the conflict, and the old value stays in the .migrated copy.
  4. Write config.yml atomically.
  5. Rename each migrated file: profile → profile.migrated, preferences.yml → preferences.yml.migrated. The removal ticket deletes the .migrated copies.
  6. Report the keys moved, conflicts, and files moved aside. Where git tracks the old files, print commit needed and the commands from the box below. migrate never commits.

Recovery. A crash between any two steps is safe. A rerun skips files already moved, finds equal values in both places, and finishes the rest.

Commit commands printed where git tracks the old files (they stage only the three paths, never other untracked files in .digismith/):

git add .digismith/config.yml .digismith/profile .digismith/profile.migrated .digismith/preferences.yml .digismith/preferences.yml.migrated
git commit -m "chore(config): migrate to .digismith/config.yml"

The printed git add lists only the old files that this run moved.

Where migrate runs

  • bootstrap and adopt Step 0, in the main checkout, before any worktree exists. They test whether git tracks an old file with git ls-files --error-unmatch.
    • Not tracked (gitignored or untracked .digismith/, as in the Emma repos): run migrate. This is a plain file move.
    • Tracked: do not migrate. Print the migrate command and the commit commands above, keep reading through the fallback, and continue the ticket flow.
  • Directly, through digismith:preferences ("migrate this repo's config").
  • DigiSmith's own repo, in this ticket's branch, by hand. DigiSmith is the only known repo that tracks .digismith/. The branch is a linked worktree, so the guard blocks the command there. The plan adds .digismith/config.yml and runs git mv on the two old files to *.migrated, in a normal commit that merges with the branch. A test checks that the committed config.yml equals the output of migrate run on the .migrated files.

Pre-migration worktrees

New worktrees start from a migrated main checkout. Only worktrees that existed before the migration keep the old files: shared-credential-resolver, and add-dg-clickup-create-list-create-folder (a detached HEAD at 3c6f562, already in main). Neither changes the old files. If a pre-migration branch changes preferences.yml and merges later, git's rename detection puts the change on preferences.yml.migrated, where nothing reads it. The migrate output says to apply such changes again with set.

5. Callers and skills

Scripts

  • session-init.ts: readProfile becomes resolve("profile"). buildBanner takes the .digismith folder. On a parse error, the hook prints one line, DigiSmith: warning: .digismith/config.yml line <n>: <reason>, skips the profile and voice banner, still prints the attribution line and the lineage pointer, and exits 0.
  • voice-init.ts: reads through the default .digismith folder.
  • model_offload.ts: readProfileProvider resolves profile through config.ts. Its --profile-path .digismith/profile flag becomes --dir .digismith. The only caller, report-implementation SKILL.md line 346, changes with it.
  • preferences.ts: wrapper plus migrate (section 3).
  • toolchain.ts: no change.

The profile rule

Each of these 7 skills replaces its own .digismith/profile check with this exact sentence, word for word: init, capture-ephemeral-url, inject-standards, jira-progress-write-back, report-implementation, brainstorming, writing-plans.

Read profile from .digismith/config.yml, or from .digismith/profile when config.yml or its profile key is missing (A.2 fallback).

The removal ticket finds every copy with grep -rn "(A.2 fallback)" skills. Where config.yml cannot be read, a skill handles it the way it handles a stale profile today.

Other skills

  • bootstrap: Step 0 gets the migrate check (section 4). First use writes profile through config.ts set. Steps 2.6 and 2.8 become one copy step: each of config.yml, profile and preferences.yml that exists in the main checkout but not in the worktree is copied in. Never git add -f.
  • adopt: Step 0 gets the same migrate check. Step 5 gets the same copy step.
  • preferences: the Storage section describes config.yml, the grammar and the fallback. Add the migrate operation and --dir.
  • offload-implementer, voice, toolchain: update only their mentions of the old paths.

6. Tests and done

New: scripts/config.test.ts

  • Parser: one case per grammar row and per error (with line number), CRLF, BOM, # inside quotes, # inside a URL.
  • Reader: layer order, source, old profile read (trimmed, empty, invalid UTF-8).
  • Writer: comments kept, insertion points, empty heading removed, quoting choices, the both-quotes error, no .tmp file left after a write.
  • Worktree guard against a real temporary repo with git worktree add.
  • migrate: the four file states, conflicts, rerun after a partial run, tracked-file message with the exact git add paths.
  • Repo migration: the committed .digismith/config.yml equals the output of migrate on the .migrated files.

Changed

  • preferences.test.ts, voice.test.ts: --dir, same outputs.
  • session-init.test.ts: banner from config.yml, banner from the old file, parse-error warning with the rest of the output intact.
  • model_offload tests: --dir.
