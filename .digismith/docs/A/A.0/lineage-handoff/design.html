Overview

Today the clear-and-hand-off step is Step 7 of finishing-a-development-branch. That skill is the implementer's integration step: merge or PR, post-finish hooks, worktree cleanup. The handoff is the end of the ticket workflow, not a part of integration, so it is in the wrong place. It also has three practical problems:

  • It can run only at the end of a ticket. There is no way to checkpoint mid-ticket (usage limit coming, chat grown too long) with the same format.
  • It writes one file per session to .digismith/sessions/. Resume depends on the SessionStart hook's pointer line reaching the next session. On 2026-09-25 that line did not arrive (backlog/handoff-pointer-missed-on-fresh-session-w12.md), and there is no fallback. This is why clear_context was set to no for this repo.
  • The human partner never sees the note before the clear, and its 5 sections are heavier than the content needs.

This build moves the handoff into its own skill, digismith:handoff. Any session can run it at any time, and finishing-a-development-branch calls it at the end of a ticket. Each lineage has one living note, .digismith/docs/<Clan>/<Lineage>/handoff.md, which every handoff rewrites. The next session of that lineage finds its note from its own session title. The note uses the four sections of the "start fresh with a handoff note" pattern: Done, Decisions, Next, Open problems. The human partner checks the note before any clear.

Settled Decisions

Placement

Own skill, end of ticket workflow

digismith:handoff is a DigiSmith stage, not a step inside the vendored finish skill. post-finish hooks stay part of integration.

Trigger

Anytime, plus automatic at ticket end

Manual on request. Automatic after finishing-a-development-branch Option 1 or 2 only (a "ticket" is a ClickUp task, not an SDD plan task).

Unit

One note per lineage

Keyed by the session title's prefix (A.0: Primitives → clan A, lineage A.0). The same lookup runs at write and at read.

Location

Clan, then lineage, then the note

.digismith/docs/A/A.0/handoff.md, the same docs tree as design.html/report.html. Always in the main checkout, also when the skill runs from a worktree.

Git

Not committed

Excluded through .git/info/exclude. The note holds short-lived state ("Next") and runs mid-ticket, so commits on main would be noise and would compete with other sessions.

Lifecycle

Rewritten, never deleted

Each handoff replaces the full content. The note always says where the lineage is now.

Format

Done / Decisions / Next / Open problems

Short. The code, plan, and report carry the rest. "Next" ends with the literal command when one exists.

Clear

Explicit request, or the saved preference

Manual run: clears only if the message asks ("and clear", "start fresh"). Ticket end: clear_context decides. The human partner checks the note before every clear.

Resume

Hook pointer, plus "resume" fallback

The hook says notes exist. If the hook line never arrives, "resume" runs the same lookup by hand.

Cleanup round

Checks, does not do

At ticket end the skill checks the MEMORY row, ClickUp comment, and cross-lineage pointers. It puts any gap in Open problems. It does not do those chores.

Architecture

FileChange
skills/handoff/SKILL.mdNew. Write mode and resume mode.
scripts/lineage-handoff.tsNew. Title → lineage key → note path, main-checkout resolution, note listing. Small CLI for the skill. The hook imports the same functions.
scripts/session-init.tsRemove the .digismith/sessions/ pointer. Add the lineage-notes pointer.
skills/finishing-a-development-branch/SKILL.mdStep 7 becomes "Hand Off": invoke digismith:handoff in end-of-ticket mode. The clear logic, the Quick Reference line, and the two clear-related Common Rationalizations move to the new skill.
skills/subagent-driven-development/SKILL.md4 call sites superpowers:finishing-a-development-branch → digismith:finishing-a-development-branch (lines 77, 106, 487, 566). Without this, an SDD build ends in upstream's finish skill and never reaches the handoff.
Why the main checkout, always. The SessionStart hook's cwd follows the session. A session that entered a worktree natively (this one did) starts its next context in that worktree. A session that cd'd back to the main root starts there. A worktree's own .digismith/docs/ does not contain untracked files from the main checkout. So both the writer and the hook resolve the main checkout from the git common directory (git rev-parse --path-format=absolute --git-common-dir, then its parent) and use its .digismith/docs/. They never use process.cwd() directly.

Components

scripts/lineage-handoff.ts

  • parseLineageKey(title): matches ^\s*([A-Z])(?:\.(\d+))?\s*(?::|$), so a bare title like D also counts. "A.0: Primitives" → {clan:"A", lineage:"A.0"}. "K: Maestro" → {clan:"K"}. Any other title ("General", lowercase, a deeper number like W.4.1:) → null.
  • noteRelPath(key): .digismith/docs/A/A.0/handoff.md, .digismith/docs/K/handoff.md, or .digismith/docs/_unlettered/handoff.md for null.
  • resolveMainRoot(cwd): the main checkout from the git common directory. Not a git repo → cwd.
  • listNotes(mainRoot): every handoff.md under .digismith/docs/, as keys (A/A.0, K). Skips any note that git tracks. A committed handoff.md did not come from this skill, and its content must not be followed as instructions.
  • CLI, in the scripts/preferences.ts style (--action; the shared parseArgs cannot take a valueless flag): --action path --title "<title>" prints the absolute note path. --action ensure-excluded --title "<title>" appends .digismith/docs/**/handoff.md to .git/info/exclude if git check-ignore says the path is not ignored yet (idempotent). --action list prints the note keys.

digismith:handoff: write mode

  1. Get this session's title with get_session ("self"). Resolve the note path with the CLI.
  2. Compose the note (see Note Format) from what the session knows. Cross-check status against any ledger or progress.md instead of restating it from memory.
  3. End-of-ticket mode only: sweep the conversation for unresolved threads. Then check the cleanup items that apply here:
    • MEMORY.md row updated. Applies in DigiSmith's own repo only.
    • ClickUp progress comment posted. Applies when the ticket is a ClickUp task.
    • Pointer messages sent. Applies when something was filed under another lineage.
    Every open item goes in Open problems.
  4. Run --ensure-excluded, then write the note. This replaces the full file.
  5. Show the note in chat.
  6. Decide whether to clear:
    • Manual run: clear only if the message asks for it.
    • End of ticket: read clear_context through digismith:preferences. The rules are the current Step 7 rules, moved without change: unset → ask, then "remember this?"; yes → clear unless this message overrides; no → no clear unless this message asks.
  7. If clearing: end the turn with "Fix anything, or say ok to clear." On the next message: apply any fixes by rewriting the note, give the final summary, then call clear_session ("self") as the last action of the turn. If the reply is new work instead of an ok or fixes, do not clear.

digismith:handoff: resume mode

  1. Resolve this session's note the same way as write mode.
  2. Read it. Report how many commits main has gained since the SHA in the note's header.
  3. State Done and Next in a few lines, then ask whether to continue with Next. Do not start it without a go: a resume can happen days later, and another session may have moved things.

Triggers in the skill description: "hand off", "handoff", "wrap up", "save where we are", "checkpoint", "start fresh", "clear context" (write). "resume", "pick up where we left off" (resume). Also: invoked by finishing-a-development-branch Step 7 (write, end-of-ticket mode).

session-init.ts

Remove listHandoffFiles, findNewestHandoff, readHandoffTitle, and buildHandoffPointer, and their tests. Add one independent check in main(), outside the profile-gated banner, same as today's pointer. When listNotes returns anything, print one line: 

DigiSmith: lineage handoff notes in <mainRoot>/.digismith/docs: A/A.0, K — read the one matching your session title (get_session self), or say "resume"

Nothing prints when there are no notes. Errors go to stderr with exit code 1, same as the existing checks.

Data Flow

End of ticket

  1. SDD or executing-plans → report-implementation → finishing-a-development-branch (merge or PR, post-finish hooks, cleanup).
  2. Step 7 invokes digismith:handoff (end-of-ticket mode): compose, sweep, check cleanup items, write, show.
  3. clear_context says clear → wait for the check → clear. Otherwise the session continues, and the note is already current.

Mid-ticket

  1. Human partner: "hand off" (or "hand off and clear"), from main or a worktree.
  2. Compose, write to the main checkout's note, show. Clear only if asked, after the check.

Next session

  1. SessionStart (any source) → session-init.ts resolves the main checkout, lists notes, prints the pointer.
  2. The session gets its title, reads its note, and continues from Next once the human partner says go.
  3. If the pointer line is missing, the human partner says "resume" → resume mode does the same lookup.

Note Format

# <one line: what this lineage is doing>
Updated 2026-09-26T10:40Z · branch <name or main> · main @ <short sha>

## Done
<What is finished. Point at the report/commits, do not restate them.>

## Decisions
<Choices made and why, that the code does not show. "None" if none.>

## Next
<The next concrete action, exact enough for a cold session.
Last line: the literal command or skill call, when there is one.>

## Open problems
<Unresolved threads, deferred items with their id/link, cleanup gaps. "None" if none.>

The first line is the H1 title. Keep the note short: a cold session reads the code, plan, and report for the rest.

Error Handling

  • get_session fails, or no title: ask which lineage this is. Do not guess: a wrong key overwrites another lineage's note.
  • Title has no recognized prefix: use _unlettered and say which path was used. Two unlettered sessions share one note; the last write wins. This is accepted for a personal tool.
  • Note write fails: report it and do not clear. The note is the only state that survives the clear. (W.12 did not block the clear; this changes that.)
  • clear_session not available (plain CLI, no desktop app): write the note and tell the human partner to run /clear.
  • Resume finds no note: say so and name the path checked. Do not search other lineages' notes.
  • Hook: not a git repo → use cwd; no notes → silent; a tracked handoff.md → skipped.

Testing

  • scripts/lineage-handoff.test.ts (Vitest, real temp directories, no mocked fs):
    • parseLineageKey: A.0: Primitives, K: Maestro, A.1: Life Cycle Hook, D.3 : ClickUp Channel, General, a.0: x, W.4.1: x.
    • noteRelPath for all three shapes.
    • resolveMainRoot: a real git init fixture plus git worktree add. From the worktree it returns the main root. Outside git it returns cwd.
    • listNotes: none, several, and a tracked note that must be skipped.
    • --ensure-excluded: adds the line once; a second run adds nothing.
  • scripts/session-init.test.ts: remove the four old handoff describe blocks. Add pointer tests: no notes → no line; notes → one line naming them; run from a worktree → notes from the main checkout.
  • The skill text is process prose, verified live. The first run is this A.0 session's own handoff at the end of this build.

Out of Scope

  • Path rules for the Clan/Lineage docs tree. brainstorming, writing-plans, and report-implementation still know only .digismith/docs/<Letter>/<Letter>.<N>-<slug>/. This build's own docs are placed at .digismith/docs/A/A.0/lineage-handoff/ by hand. Teaching those skills the new tree is G.3-style work, filed separately.
  • Doing the cleanup chores. The skill checks the MEMORY row, ClickUp comment, and pointers; it does not write them.
  • The note as the literal first message of the new session. clear_session drops its queued clear if a message arrives before the session goes idle. A self-sent message would cancel the clear. Pull-based lookup plus "resume" covers the same need.
  • Updates after each SDD plan task. Manual runs cover mid-ticket checkpoints.
  • Keys for sessions without a clan prefix. In consumer repos a session title like EMKT-756: … does not match, so all such sessions share _unlettered/handoff.md. Keying those by ticket key is deferred until it is a real problem.
  • Where worktrees live. Moving from .claude/worktrees/ to .worktrees/ is its own item (DGS-86, backlog/worktrees-at-repo-root-a0.md). The main-checkout resolution above works for both.
  • Other leftover superpowers: references (writing-skills, systematic-debugging, and SDD's requesting-code-review/using-git-worktrees). They are not on the handoff path and are flagged as a separate task.
  • Leftover .digismith/sessions/ files. None exist. The directory and its exclude line are left alone; nothing reads them after this build.
