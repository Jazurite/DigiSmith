Goal

Add dg clickup update-list so a List can be renamed and given a description from the CLI. create-list sets only the name, so new lineage Lists start with an empty description and a person pastes it in by hand. The command uses ClickUp's public API only: PUT /list/{list_id}.

Confirmed live on 2026-10-02: PUT /list/{id} with {name, content} sets the description, and GET /list/{id} returns the same text. With markdown_content, GET returned the text without its bullet markers. The command therefore sends content, never markdown_content.

Client method

  • ClickUpClient.updateList(listId, body) sends PUT /list/{listId} with body as the request data and returns the response.
  • ClickUpListWriteBody in types.ts: { name?: string; content?: string }.
  • Additive edits only. DGS-76 (move-task) edits the same client.ts, types.ts and clickup/index.ts in parallel; whoever finishes second rebases on main.

Command

New file packages/cli/src/clickup/update-list.ts with createUpdateListCommand(clientFactory), modeled on update-task.ts and registered in clickup/index.ts.

FlagRule
--list <id>Required. An empty or whitespace value is rejected before any client call.
--name <name>Optional. An empty or whitespace value is rejected.
--description <text>Optional. An empty string is allowed and clears the description. Sent as content.
--description-file <path>Optional. Read as UTF-8 and sent as content. A missing file gives a plain error. Combining it with --description is an error.
  • At least one of --name, --description, --description-file is required; otherwise the command errors before any client call.
  • Output: the response as JSON, like the sibling commands. Success sets exit code 0; any error prints clickup update-list: <message> and sets exit code 1.

Tests

Vitest with mocks only; no test calls ClickUp.

  • Client: PUT URL and body for name-only, content-only and both.
  • Command: name only, description only, description from file, both description flags, no fields, empty --list, empty --name, empty description clears, missing file, API error.

Live writes (the Town Hall rename back to "Town Hall" as the smoke test, read back with get-lists, then the C.0 to C.3 descriptions) run only after the maestro approves each one. B.2 is not renamed live: its name is undecided.

Scope and follow-ups

  • Out of scope: --description on create-list. create-list followed by update-list does the job, and the change would widen the overlap with DGS-76. Recorded as a follow-up in the D.3 handoff.
  • Out of scope: the Frontdoor rename call (PUT /hierarchy/v1/subcategory/<id>). The public API route is preferred and enough.
  • Out of scope: reading the ClickUp token. The command uses the existing createClient.
