Background & Trigger

W.1 (2026-08-20) cloned all 14 Superpowers skills verbatim into skills/vendored-<name>/, dormant, with every existing DigiSmith call site left pointed at the still-live superpowers:<name> originals — deliberately, per W.1's own design: "DigiSmith's existing internal call sites ... are left unchanged in this slice ... dormant until a future brainstorm activates one." W.2 (2026-08-29) built the general activation mechanism (a fork-provenance tag convention and an upstream-diff script) that any future activation will use.

Jack confirmed the next step explicitly: before touching finishing-a-development-branch's actual content (its confirmed no-push bug, backlog/no-push-after-local-merge.md, the leading candidate for map item W.4), make every DigiSmith call site actually invoke digismith:<name> instead of superpowers:<name> first — a broad, content-neutral pass, safe because the vendored copies are still byte-identical to what Superpowers would have run. He additionally confirmed he plans to stop keeping the Superpowers plugin installed at all going forward, once nothing in DigiSmith depends on it directly for these primitives.

Scope: W.3 vs. the Rest of the Initiative

An inventory of every superpowers:<name> occurrence across DigiSmith's own skills (excluding the 14 skills/vendored-<name>/ clone folders themselves) found:

  • 10 hand-authored skill files reference superpowers: names: adopt, bootstrap, capture-ephemeral-url, enforcer, init, jira-progress-write-back, offload-implementer, report-implementation, subagent-driven-always, telemetry.
  • Only 6 of the 14 vendored primitives currently have any DigiSmith-side reference at all: brainstorming, writing-plans, subagent-driven-development, executing-plans, finishing-a-development-branch, using-git-worktrees. The other 8 are referenced nowhere in DigiSmith's own skills today — nothing to cut over for them.
  • MEMORY.md has 6 of its own occurrences, covered separately below (see Architecture) since it's prose, not a skill file, and needs a different rule.

Explicitly out of scope:

  • Anything inside skills/vendored-<name>/. Those clones' own internal cross-references (e.g. subagent-driven-development's file telling the reader to "use superpowers:finishing-a-development-branch") stay untouched — W.1's design explicitly deferred that to each skill's own future content-activation, map item W.4+, not this pass.
  • vendored/PROVENANCE.md. It's the historical record of the clone operation itself and describes the relationship to upstream Superpowers — inherently about the third-party source, not DigiSmith's own invocation path.
  • Reworking check_vendored_skills.ts to source upstream from GitHub instead of the local plugin cache. Raised in this same conversation (motivated by Jack's plan to stop installing Superpowers), but it's a change to W.2's already-shipped script, not to DigiSmith's call sites — logged separately as backlog/check-vendored-skills-github-source.md, tentative map sub-item W.2.1.

Architecture & the Rewrite Rule

Skill files: uniform rewrite, no per-line judgment needed

Confirmed by inspection: every superpowers:<name> occurrence across all 10 hand-authored skill files describes DigiSmith's own invocation or reference behavior — none state a fact specifically about the upstream plugin. Both categories present (genuine invocation instructions like bootstrap's "invoke superpowers:brainstorming", and descriptive prose like report-implementation's "Right when a superpowers:subagent-driven-development plan's final review has come back clean") get rewritten identically, per Jack's explicit "everything, uniformly" — including inside report-implementation's generated report.html template text itself (future reports will read "Executed via digismith:subagent-driven-development").

MEMORY.md: two categories, classified below

MEMORY.md is prose describing DigiSmith's own history and philosophy, not a skill file — a blanket find-replace would occasionally break a sentence's own meaning. Two categories exist, and each of its 6 occurrences was individually classified:

The rule in one sentence: rewrite wherever the text describes what DigiSmith itself invokes or owns; leave it alone wherever the text states a fact specifically about the third-party Superpowers plugin that remains true independent of which prefix DigiSmith uses.

Data Flow: File-by-File Changes

No script — 10 skill files plus MEMORY.md is a small enough corpus for direct, reviewed text edits per file, each verified by a post-edit grep rather than trusted blind. One task per file (or a small number of closely-related files grouped) is a planning decision for writing-plans, not decided here.

Frontmatter name: fields inside skills/vendored-<name>/SKILL.md need no changes — they were already left untouched by W.1's clone, so digismith:brainstorming already resolves correctly once the plugin cache picks up this change (see Error Handling).

Error Handling & Known Limitations

  • Plugin-cache lag blocks pre-merge live testing. Documented in backlog/plugin-cache-lag-self-development.md: a live Claude Code session's installed plugin snapshot is always one version behind an unmerged branch. A Skill(skill: "digismith:brainstorming", ...) call made from inside this same unmerged branch will fail with "Unknown skill" until the branch merges and the plugin reinstalls. This is a hard limitation, not a defect to fix here — verification (below) works around it rather than pretending it doesn't exist.
  • A missed occurrence is silent, not loud. This is a text-editing task with no build step or type system to catch a stray unrewritten superpowers: reference — it would simply keep invoking the upstream skill unnoticed. Mitigated by the grep-based verification step, not by any runtime check.

Testing / Verification

  • Grep the 10 skill files for remaining superpowers: occurrences of the 6 cut-over names — expect zero.
  • Grep MEMORY.md for the same 6 names — expect exactly one remaining occurrence (map item W's clause 1, the confirmed-upstream-bug fact), and confirm every other occurrence changed.
  • Confirm no file under skills/vendored-<name>/ or vendored/PROVENANCE.md was touched — this pass is additive text changes to the 10+1 files only.
  • Cannot verify: live Skill-tool resolution of any digismith:<name> reference before this branch merges and the plugin reinstalls (see Error Handling). Documented as an accepted limitation, not worked around.

Future Phases (W.4+, Not Designed Here)

  • Post-merge live confirmation — once this branch merges and the plugin reinstalls, a quick sanity check that digismith:brainstorming (or any cut-over name) actually resolves in a fresh session is worth doing, though not part of this slice's own verification (see Error Handling).
