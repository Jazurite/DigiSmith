Re-reviewed clean, merged to main.

  • Split standards/team/ out of shopify/ — the original two-folder design conflated scope (universal vs. Emma-specific) with kind (code technique vs. process convention); real content made the seam obvious
  • Renamed the marketplace digismith → jazurite (matches the GitHub owner; the plugin itself is unaffected)
  • Pushed to github.com/Jazurite/DigiSmith so it installs from any machine
2026-08-06

Live validation

discover-standards captured snippet-render-vs-include.md in an actual session against a real Emma repo — not a dogfood simulation. First real proof the installed plugin works end to end.

2026-08-06

Explored and shelved: local standards cache + fetch-standards

Live testing surfaced friction — being asked to locate DigiSmith's repo path every time. Proposed fix: a local .digismith/ cache per consuming repo, refreshed by a new fetch-standards skill. Mid-brainstorm, self-corrected: this solves a multi-tenant sync/merge problem DigiSmith doesn't have. Shelved before any design was written — writes still go straight to canonical DigiSmith, unchanged.

I.1 now names the separate, later JIRA write-back feature that will consume M's output. Design spec approved; implementation plan written (3 tasks).

2026-08-08

M built — 3 tasks, subagent-driven-development

skills/capture-ephemeral-url/SKILL.md delivered: Task 1 built the skill and dogfooded the happy-path decision logic against fixtures (ticket-key parsing, poll-to-success branching, URL extraction from a real example comment); Task 2 dogfooded four edge cases (no-match branch, check failure, timeout, missing/malformed comment). Live gh pr view/gh pr checks calls couldn't be dogfooded against a real PR — the authenticated gh account can't reach DigiSmith's own repo, and creating a scratch PR against a real Emma repo would be visible to teammates — so those get their first live verification the next time this skill runs for real. Task 3 is this history.html update. Map item M done.

2026-08-08

N brainstormed, specced, and built — 3 tasks, subagent-driven-development

Jack asked to formalize G's hand-written implementation report into a required step. Brainstorming surfaced a real sequencing problem: the ledger content that makes a report worth reading is deleted by subagent-driven-development's own Finish step before finishing-a-development-branch even runs — so report-implementation triggers earlier than "after merge," right before that deletion, relying on this repo's merges always being fast-forward so the commit range it records never changes afterward. Task 1's dogfood run reconstructed M's actual (already-deleted) ledger from this session's own record of it and generated M's real missing report against real git history — kept, not discarded as test scaffolding. Task 2 dogfooded four edge cases with no gaps found. Task 3 is this history.html update.

2026-08-08

Unified docs convention adopted — no map letter

Replaced two inconsistent storage conventions — docs/superpowers/{specs,plans,reports}/ (DigiSmith's own repo, organized by artifact type) and docs/<slug>/ticket.md (consumer repos, hardcoded gitignored) — with one: .digismith/docs/<feature-slug>/{ticket.md, design.html, plan.md, report.html}, wherever DigiSmith writes docs. Commit-vs-gitignore in a consumer repo is now an explicit ask-once-then-remember choice instead of a hardcoded assumption. All 13 existing files across G/A/E/M/N migrated in the same pass; this is a structural change, not a new pipeline capability, so it's recorded here and in MEMORY.md's Conventions section rather than added to the map table.

2026-08-11

O brainstormed, specced, and built — 5 tasks, subagent-driven-development

Jack asked to make DigiSmith's existing "everything on" Emma flow and a lighter Personal flow (no ticket, no ephemeral capture) a declared per-repo choice instead of an undocumented, ad hoc deviation from pillar 5's prescriptive stance. Two flat YAML profiles ship (emma, personal), read independently by using-digismith, inject-standards, capture-ephemeral-url, and report-implementation at each one's own trigger point — no central orchestrator, no inheritance system. A repo with no .digismith/profile file sees using-digismith's new first-use profile picker on its next invocation, but every other consuming skill (inject-standards, capture-ephemeral-url, report-implementation) and DigiSmith's own repo see zero behavior change. Task 4 also closed a standing gap: report-implementation had never rendered a ticket-key field at all until this feature added one, gated by the same profile mechanism. Task 5 is this history.html and MEMORY.md update.

2026-08-11

Tier 1 declared satisfied; E split into E.1/E.2, remainder decoupled to Tier 3

Jack judged Tier 1 ("the frame") complete as shipped — G and the first slice of E plus the newly pulled-forward O are enough to call the frame established. Rather than leave E dangling as "in progress" inside a tier everything else has moved past, it's formally split — same pattern as I (I.1/I.2/I.3) and L (L.1/L.2) — into E.1 (the shipped intake → branch → brainstorming hand-off, Done) and E.2 (full stage-order enforcement and routing to everything else, Not started), with E.2 decoupled into Tier 3 alongside A and J. Same kind of reprioritization as A moving ahead of E on 2026-08-06.

2026-08-12

P brainstormed, specced, and built — 2 tasks, subagent-driven-development

Jack asked for a feature to fully log and track DigiSmith's own actions for data collection, aimed at finding future improvement opportunities — originally framed as covering both DigiSmith's own process and the shipped product's runtime behavior. Those turned out to be two unrelated engineering problems; this feature covers DigiSmith's own process only, with shipped-product telemetry deferred as a separate, undesigned sub-project. A new logging profile field gates capture; using-digismith marks where a ticket's build began in the live session transcript, and a new telemetry skill — triggered right after superpowers:finishing-a-development-branch's integration decision — slices the transcript from that point and commits it into DigiSmith's own repo. Raw and unredacted by deliberate choice, recorded as an explicit accepted risk given DigiSmith's repo is public. UAT planned against a real Emma repository and JIRA ticket.

2026-08-12

H brainstormed, specced, and built — 2 tasks, subagent-driven-development

Jack asked to remove superpowers:writing-plans' live "Subagent-Driven or Inline Execution" choice for every DigiSmith-driven plan. A profile toggle and a task-count rule were both explored and rejected during brainstorming — every current profile already depends on subagent-driven-development's ledger for N, and executing-plans turned out to be the no-subagent fallback, not a lighter-weight mode, so routing any plan there by task count would have broken G and N regardless of size. One new skill, subagent-driven-always, intercepts the Execution Handoff trigger directly — the same implicit-trigger pattern M and N already use — rather than patching writing-plans itself. Verified via four constructed dogfood scenarios (Task 1: default path, explicit override, no-subagent-capability, single-task plan), each dispatching a subagent to reason through the shipped skill file against one condition. Not a live trigger-point run — the skill didn't exist yet when this plan's own Execution Handoff was reached, so this build couldn't have exercised its own trigger. The first real trigger-point exercise will be the next DigiSmith-driven plan, e.g. the Emma UAT already underway.

2026-08-15

Q brainstormed, specced, and built — 4 tasks, subagent-driven-development

The open question logged when the unified docs convention shipped — "design.html/plan.md have no enforcement mechanism" — stopped being hypothetical: a real hand-off produced a plain Markdown spec at the old docs/superpowers/specs/ location instead of .digismith/docs/<slug>/design.html. Brainstorming settled on Advisory + Verified: tell brainstorming/writing-plans explicitly where and in what format to write before each hand-off, then check afterward that it landed there and correct it if not — plus a convention amendment publishing every per-feature HTML doc (design.html, report.html) via the Artifact tool once written. Task 1 built and dogfooded skills/enforcer/SKILL.md; Task 2 added the explicit call from using-digismith Step 3; Task 3 added the matching publish step to report-implementation (N); Task 4 is this history.html and MEMORY.md update. Map item Q done.
