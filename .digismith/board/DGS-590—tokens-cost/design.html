1. Goal

Oculus (DGS-586, renamed by DGS-599) keeps three empty slots: tokens per run, burn per hour, and each seat's 5h and weekly window. Jack, 2026-10-24: "show cost too, make it auto". This ticket fills the slots, adds cost in USD, and does it with no manual step except the existing usage probe.

Done when: the Runs table shows Tokens and Cost per run, the run page shows a tokens and cost card per model, the top bar shows burn per hour (tokens and $) and the seat windows. A value is "-" when its file is missing or stale. Oculus never shows a false number.

2. Facts found (2026-10-24, read only)

  • Counter. packages/cli/src/tokens/claude-code-reader.ts (DGS-214) reads a transcript whole and gives one UsageRecord per response: five classes (input, output, cache_read, cache_write_5m, cache_write_1h), model, ts, and the dedupe key message id + request id. A repeated line keeps the highest output. Subagent files are <session>/subagents/agent-*.jsonl. findTranscript finds <session>.jsonl under ~/.claude/projects/*/.
  • Sessions of a run. Every hook event already carries data.session_id (DGS-581). DGS-598 adds run.json session_id (the first session) and keeps a run across /clear with a new session id, which gets its own started event. So the started events list every session of a run, for automatic runs and for dg run start runs alike.
  • Price table. DGS-567 merged: scripts/token-counter/anthropic-pricing.ts, prices fetched 2026-10-18, with 5m and 1h cache-write prices and the Haiku 5.5 long-prompt tier (per request). It has no version field. The CLI build (tsc, rootDir: src) cannot import from scripts/; scripts already import from packages/cli/src/.
  • Scheduler. The Nexus API process runs jobs from scripts/nexus-api/src/scheduler/registry.ts; autonomous-scan and nightwatch-watchdog run every 5 min as node dist/index.js …. A new entry there is a job in the existing process, not a new LaunchAgent. It loads at the next API restart.
  • Usage probe. The conductor runs it by hand (runbook "Reading usage"): a short haiku session with the probe status line writes usage-probe/out.json (at, rate_limits.five_hour/seven_day with used_percentage and resets_at in Unix seconds, claude_version). The conductor saves it as out-<seat>.json (today out-jack.json, out-dev0.json, out-emma.json with no rate limits). No token in these files.
  • Slots. RunsTable.vue has a Tokens column that prints "-" ("not measured"). NwTopBar.vue prints Burn -/h and Seat 5h / week - / -.

3. The data job

  • A new scheduler job oculus-tokens in registry.ts: every 5 min, all day, catch-up skip, timeout 4 min, notify on failures. Command: node dist/index.js tokens runs. No new LaunchAgent, no model tokens, no Claude session.
  • dg tokens runs (new subcommand next to dg tokens <ticket>) does three things in one pass: update the tokens.json of each run in scope (section 4), write the burn file, write seats.json (section 7). It prints one summary line (runs updated, skipped, failed). --run ID updates one run only. --dry-run prints and writes nothing.
  • Runs in scope: runs active within 7 days (the DGS-598 activity window: mtime of events.jsonl, else run.json), and a run whose tokens.json is older than its last event. An ended run gets one last pass after its ended event and is then marked final; later passes skip it.
  • One failed run never stops the others. The command exits 1 only when it could not write anything at all.

4. Counting a run

Which sessions

The sessions of a run are run.json session_id (when present, DGS-598) plus every data.session_id of a started event in events.jsonl. A run with no session id at all gets no tokens.json and shows "-". Each session reads its main file and its subagent files. A session whose file is not found yet is retried next pass.

Which responses

Responses with ts at or after the run's created_at. This keeps a resumed session's older work out of a dg run start run. Dedupe by response id across all files of the run (a resumed transcript replays old lines), keeping the highest output, as the DGS-214 reader does.

Incremental by offset

  • A new reader function reads one file from a byte offset in 64 KB chunks and stops at the last full line. It returns the records and the new offset. It reuses the line parser of claude-code-reader.ts (one parser, so the counts match dg tokens).
  • Per file the state keeps offset, size and the file's ino. A file that shrank or has a new inode is read again from 0.
  • The state also keeps each counted response (id → model, five counts, cost, 5-min bucket). A repeated id with a higher output replaces the earlier one: subtract the old, add the new. So the totals equal a full recount.
  • State lives in tokens.state.json next to tokens.json. It holds ids, counts, offsets and file names (<session>.jsonl, agent-<id>.jsonl), never text and never the project folder path. When the state is missing or unreadable, the run is counted again from 0.

Burn buckets

Each response falls in a 5-min UTC bucket. tokens.json keeps the buckets of the last 24 hours (at most 288). Burn per hour = the sum over all runs of the 12 buckets that end at or before the job's run time.

5. Cost and the price table

  • The Anthropic table and costFromPricing (with the long-prompt tier) move into packages/cli/src/tokens/prices/. scripts/token-counter/ re-exports them, so there is one table. The table gets ANTHROPIC_PRICES_VERSION = "2026-10-18" (the fetch date in its header). A price change bumps the version.
  • Cost is computed per response (the Haiku 5.5 tier is per request), then summed per model. A response's cost: input, output, cache read, 5m write, 1h write at the listed rates.
  • A model with no price (resolvePricing gives nothing) gets cost_usd: null and is named in unpriced_models. The run total cost is then null too: a partial sum would be a false number.
  • Not priced, as in DGS-567: fast mode, batch, US-only. Seats are subscriptions, so the dollar figure is the list price of the tokens, not money paid. The card says "list price".

7. Seat windows

  • Who probes. The conductor, as today: the runbook "Reading usage" steps at each ticket start and each limit stop, saving out-<seat>.json. The job never starts a Claude session. A scheduled probe would start one, so it needs the Maestro's word and is a later ticket.
  • Who writes seats.json. The data job, every 5 min, from the out-<seat>.json files (seat = the name between out- and .json, a safe name; out.json itself is skipped because its seat is unknown). So the conductor's existing habit fills Oculus with no new step.
  • Shape. { schema: "oculus-seats/v1", generated_at, seats: [ { seat, read_at, five_hour: { used_pct, resets_at } | null, weekly: { used_pct, resets_at } | null } ] }. Times as ISO UTC. Only these fields are copied; claude_version and anything else is dropped. A seat with no rate limits (emma) has both windows null.
  • Showing a reading. A reading is shown with its time ("jack 5h 7% · week 32%, as of 15:09"). A window whose resets_at has passed shows "-" for that window: the number is known to be wrong. A reading older than 15 min shows in the warn tone with its "as of" time, so it is never mistaken for a live number.

8. Views and API

  • The runs view row gets tokens: { total, cost_usd } | null. The run view gets tokens: { generated_at, final, price_version, models: [ { model, five classes, tokens, cost_usd } ], total, unpriced_models } | null. The overview view gets burn: { tokens_per_h, usd_per_h, as_of } | null and seats: [ … ] | null.
  • The views stay read-only. They read the files; they never count.
  • The shared zod schema (nexus-shared/oculus.ts after DGS-599) and the contract tests get the new fields. No new API route: the existing overview, runs and run routes carry them.

9. Oculus screens

  • Runs table. Tokens (compact: 1.2M) and Cost ($3.41) columns, right aligned. A title gives the exact number. "-" with a title saying why ("no snapshot", "stale", "unpriced model").
  • Run page. A "Tokens and cost" card next to the budget card: one row per model with the five classes, total tokens and cost; a total row; the footer "list price, Anthropic table 2026-10-18 · as of 15:50". When final is false, "counting" in the footer.
  • Top bar. Burn 4.1M/h · $12.30/h, and per seat jack 5h 7% · wk 32%. "-" by the rules in section 10. On a phone the seat part folds into one line per seat under the top bar.
  • Same gates as DGS-586/599: Storybook stories for each state (value, "-", stale, unpriced, counting), visual baselines desktop and mobile, Playwright on the stub server, axe.

10. Freshness, errors, privacy

  • Run tokens: "-" when tokens.json is missing or unreadable. A non-final file older than 15 min is stale: "-" with the title "stale since 15:20". A final file never goes stale.
  • Burn: "-" when burn.json is missing or older than 15 min. $ part "-" when cost_usd is null.
  • Seats: "-" when seats.json is missing or older than 15 min; per window as in section 7.
  • Never a false number: no partial cost sum, no value from a stale live file, no window past its reset.
  • Errors: a transcript line that does not parse is skipped (as DGS-214); a line over 1 MB is skipped. A run that fails is logged as one line to stderr (run id and error code, no data) and keeps its last good tokens.json.
  • Privacy: the job reads transcript lines only for the usage fields; it writes counts, money, ids and file names only. No message text, prompt, tool input or output, terminal title or folder path in any file, view or page. A test greps every written file and view output for the fixture's message text and path.

11. Order of work

  1. Now (no dependency): the price table move and version; the incremental reader; the run counter with state, cost and buckets; seats.json; dg tokens runs with the burn file; the scheduler job entry. These work on dg run start runs today (session ids from started events) and read run.json session_id when present.
  2. After DGS-599 merges (rebase on main): the view fields, the shared schema, the Runs table columns, the run page card, the top bar.
  3. After DGS-598 merges: a test with a DGS-598-shaped run (automatic run, /clear with a second session) and the first-use check on real automatic runs. No code depends on DGS-598 beyond reading the optional session_id field.

12. Tests without Jack

Fakes only: DIGISMITH_DEPOT_DIR and DIGISMITH_CLAUDE_PROJECTS_DIR in temp folders, fixture transcripts, fixture probe files. No real depot, transcripts, herdr, ClickUp, live API or API restart.

  • Incremental equals full: count a fixture in several appends (including a half-written last line, a streamed response that grows, a resumed file that replays, a subagent file) and compare with readClaudeCodeSession on the whole file.
  • A shrunk or replaced file is read from 0; a lost state file gives the same totals.
  • Sessions from run.json and from started events; responses before created_at are left out; no session id gives no file.
  • Cost per current model id, the Haiku tier per response, an unpriced model (total null), the price version in the file; scripts/token-counter tests still pass on the moved table.
  • Buckets and burn: fixed clock, two runs, a bucket at the 60-min edge.
  • Seats: two seats, one with no rate limits, out.json skipped, an unsafe name skipped, extra fields dropped, atomic write.
  • Job: the registry entry (name, every 5, command args), --dry-run writes nothing, one failing run does not stop the rest, an ended run gets a final pass and is then skipped.
  • Views and UI: fresh, stale, missing, final, unpriced and past-reset states; the contract tests; stories, baselines, Playwright, axe.
  • Privacy grep (section 10). The strip-types smoke test covers each new file.

13. First use (after the merge, conductor on the Maestro's word)

  1. CLI build in the main checkout, then the existing Nexus API restart (loads the new job and the view fields), then build-www.sh. These are the conductor's steps; this ticket never restarts the API.
  2. dg tokens runs --dry-run, then wait one 5-min tick. A live run's tokens.json appears; its total matches dg tokens <ticket> for a single-run ticket within the responses before created_at.
  3. Oculus shows Tokens and Cost in the Runs table, the card on a run page, burn in the top bar. After a probe, the seat windows show.

14. Out of scope

  • A scheduled usage probe (it starts a Claude session; needs the Maestro's word). It is the follow-up ticket; the Maestro files it.
  • Non-Claude sessions (OpenCode, offloaded runners) and their prices.
  • Per-ticket or per-step totals in Oculus (dg tokens keeps that).
  • Budget alarms on cost, ClickUp cost fields, deletion of old snapshots.
  • Fast mode, batch and US-only prices.

15. Decisions for the Maestro

All technical, taken by me; the Maestro may flip any of them at checkpoint 1.

  1. Seat readings older than 15 min show with their "as of" time in the warn tone, not "-". Reason: the probe is manual and runs a few times a day, so a strict 15-min rule would show "-" almost always. A window past its reset shows "-".
  2. Tokens = all five classes (cache reads included, as ccusage counts). The card shows the split.
  3. Cost is list price, labelled so; seats are subscriptions.
  4. One job, one command (dg tokens runs) for run snapshots, burn and seats.
