DGS-462 state block refresh — Implementation Report

Ticket: DGS-462Date: 2026-10-13

Summary

The conductor's state block is now refreshed by a script. cli.ts state-refresh rebuilds Running from herdr and the open worker cards, keeps the hand-written parts, drops an item only when its explicit [resolves: ...] marker holds, and writes only the block. The catch-up refreshes first, shows the block's age, and warns when the block is behind the newest merge on origin/main.

Built

  • refresh.ts, markers.ts, ticket-status.ts and the state-refresh command (--workers, --dry-run, --create).
  • Ownership: --workers list (stored in the block) or a card whose under is the conductor; other panes show as owner unknown in Health.
  • Markers: ticket, merged, gone, exists; Decided is never dropped; any doubt keeps the item and warns.
  • Stale check by the recorded Main: hash; age line in Health; the catch-up does not reuse a catch-up older than the newest merge.
  • Docs: docs/conductor-state.md, skills/catch-up/SKILL.md.

Tests and review

Full suite 147 files, 2103 tests pass; the ticket's test (stale block plus newer merge gives a warning, then a refreshed Running) is in refresh.test.ts. Most code was written before its tests, so they were not red first. An independent Claude review found seven issues; all were verified and fixed with tests (wrong checkout, lost update, unpinned workspace, fast-forward dates, fractional card times, stray note creation, silent markers).

Not done

The d3-conductor's conductors.json entry and both conductors' routine lines are theirs. The catch-up reuse rule still compares times. One type error in card-hook.ts predates this branch.
