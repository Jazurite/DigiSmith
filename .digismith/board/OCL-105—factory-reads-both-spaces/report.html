The factory reads both ClickUp spaces — Implementation Report

Ticket: OCL-105 Date: 2026-11-14

Summary

The autonomous scan, the Director and the Steward now read both ClickUp spaces, DigiSmith (DGS) and Oculus (OCL), through one space list (packages/cli/src/clickup/spaces.ts); a ticket key resolves to its space by prefix, every key tool and conductor script accepts an OCL key, and the new command dg clickup create-factory-fields creates the Mode and Sign-off fields in the Oculus space (dry run by default, idempotent, no live write in this build).

What changed

  • Space list: SPACES, ALL_SPACE_IDS, KEY_PREFIXES, spaceForKey, isTicketKey. DIGISMITH_SPACE_ID keeps its value and export.
  • Trackers: ClickUpLoTracker (scan, Director) and the Steward's ClickUpTracker take a list of space ids, merge their reads, and throw on an empty list. A failed read of one space fails the whole read.
  • Key checks: the four ^DGS-\d+$ checks in attach-record, ticket-total, merge-comment and task-stamp, and the conductor scripts (ticket-status, markers, refresh, flux in-flight guard, state merged-today list) use the shared prefix set. The herdr audit log accepts dgs or ocl panes.
  • New command: dg clickup create-factory-fields --space <id> [--yes]. Prints created without location: <id> <name> and exits 1 when a field is created but its location call fails.
  • Pins (tests only): schedule-release, the report drift check, the run-role rule, board path, lock and claims, Steward event chain, Director refine pass, an end-to-end scan over the two-space tracker, and the claimed-status path (see the Dock addition).

Protected paths touched (the Dock approves the merge)

  • packages/cli/src/autonomous/: tracker-clickup.ts, index.ts, director/command.ts, tests, WATCHDOG.md.
  • packages/cli/src/steward/: clickup-tracker.ts, index.ts, tests, README.md.
  • scripts/nexus-api/src/scheduler/: not touched. The grep found one hit, notify.ts:19, a default comment-target ticket DGS-436; it does no key parsing, so no change.
