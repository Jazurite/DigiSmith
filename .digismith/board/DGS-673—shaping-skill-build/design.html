What and why

Write skills/shaping/SKILL.md from the approved DGS-671 design: the skill that takes a ClickUp ticket from backlog (a raw idea) to concept (shaped) by writing a ## Pitch on the ticket and firing the shaped Steward event (DGS-674).

The skill file

One new file, self-contained, in the plain style of jira-intake and catch-up. It holds: the trigger description; a hard gate (nothing written to the ticket and no event before Jack's yes); the seven-step flow; the pitch template; the self-review checklist; the walk-away ending; the interview mode; the Small, Medium and Big definitions; the exact commands (dg clickup get-task, dg clickup update-task --markdown-description-file, dg steward event shaped, tokens step-start and step-end with --step shaping). It never mentions digismith:brainstorming (no cross-reference, Jack's decision).

Technical decisions

  • Writing the pitch: dg clickup update-task replaces the whole description, so the skill reads the current description, keeps it untouched, appends ## Pitch and the pitch text, writes the whole text to a scratchpad file, and updates with --markdown-description-file. It reads the ticket back and checks that the raw text and the ## Pitch heading are both present.
  • Re-shaping a ticket that already has a pitch: the skill stops and asks Jack whether to replace it. It never silently overwrites.
  • Roadmap fit: the skill reads the ticket's list and the epics and initiatives in it with dg clickup list-tasks and proposes a parent and a milestone, never a done milestone. No fitting initiative becomes an open question.
  • Telemetry: step-start at the beginning and step-end before the event, same key rule as the other skills (needs the shaping step from DGS-674).
  • Tickets already in concept without a pitch: same flow; the final shaped call is a no-op by design.

Verification

The skill is prose, so the plan checks it with searches: frontmatter name, every required heading, the three commands, and zero mentions of the brainstorming skill. The live shaped command is checked with --dry-run once DGS-674 is merged.

Merge order

DGS-674 first (the event and the telemetry step), then this ticket, then DGS-676 (which narrows brainstorming).
