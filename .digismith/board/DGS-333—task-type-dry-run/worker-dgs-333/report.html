Ticket: DGS-333Date: 2026-10-11

Summary

create-task-type, update-task-type and delete-task-type now read the task types through the public API (GET /team/{id}/custom_item). They build the Frontdoor client only in the --yes branch. A dry run needs no Frontdoor session.

Built

  • Each command takes a Frontdoor factory, a public factory and (create, update) a team-id function. The default team id comes from checkCredentials(): the env file only.
  • delete-task-type builds the Frontdoor client after the --confirm-count check, so a stale count fails before any session is needed.
  • Same body as before: the public read has the same fields the PUT needs (id, name, name_plural, description, avatar source and value), the same ClickUpTaskType type. Tests pin the exact POST and PUT bodies, including the fas / user-alt fallback.
  • No edit in packages/clickup-client.
