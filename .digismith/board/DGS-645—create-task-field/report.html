create-task read-back for --field values — Implementation Report

Date: 2026-10-25 Ticket: DGS-645 Commit range: d1c9f7d1..4d39e50c

Summary

dg clickup create-task now reads the task back after it sets the --field values, compares each value, sets a wrong field one more time, and exits 1 with both values if it still differs. The cause of the original wrong Mode on DGS-644 is unproven: the CLI sends the right option. The fix makes a wrong value loud. A retry that cures a value prints one stderr line, so the cause can be found later. Built with digismith:subagent-driven-development (3 tasks, each reviewed independently in role mode) and a whole-branch review with one fix wave. Findings table: findings.md.

Reference documents: the spec and the implementation plan.

What Was Delivered

  • Task 1: findFieldMismatches. A pure function in field-set.ts that compares each resolved field with the task read back: dropdowns by orderindex or option id, text trimmed, number and currency numeric, checkbox tolerant; date and relationship fields are skipped; only the last entry per field id counts.
  • Task 2: create-task read-back. After the writes, create-task reads the task, retries the mismatched fields once (with a stderr line), and fails with exit 1 and the task key and id if a value still differs.
  • Task 3: README. One sentence that describes the read-back.
