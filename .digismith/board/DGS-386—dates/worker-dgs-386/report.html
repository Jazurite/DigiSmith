DGS-386 dg clickup dates — Implementation Report

Ticket: DGS-386Date: 2026-10-11

Summary

A plain YYYY-MM-DD in --start-date or --due-date now means that day at 04:00 UTC+7, as ClickUp stores its own all-day dates. A due date before the start date is refused before the call.

Built

  • parse-date.ts: a strict parser. Plain dates send start_date_time / due_date_time false. A value with a time and an offset is sent as it is. A time without an offset, or a day that does not exist, is refused.
  • Used by create-task and update-task, the only commands with date flags. update-task with one date reads the task once and checks the other stored date.
  • ClickUpClient.request shows ClickUp's error body in the message of the same error, so err.response stays available.
  • Tests added for the parser, both commands, the client and field-set. The whole repo passes with FORCE_COLOR=1; the CLI build is clean.

Review

Claude whole-branch review, two verified finds, fixed with tests: a timed value on a day that does not exist rolled over silently; a string error body was printed twice.

First use

Close DGS-386 with plain dates and read both back as 1791666000000. The result goes to the maestro report.
