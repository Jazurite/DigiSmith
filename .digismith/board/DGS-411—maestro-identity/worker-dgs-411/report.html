DGS-411 Maestro identity — Implementation Report

Ticket: DGS-411Date: 2026-10-13

Summary

A Claude Desktop or SSH Maestro session now learns it IS a given Maestro without hand-set env. An identity record in the depot names the project folder; the existing session-start hook writes the card from it and prints one context line (identity, project, session id, conductor, other open sessions of the identity). No settings, hooks.json or config change.

Built

  • scripts/identity.ts: the record ~/.digismith-depot/identities/<id>.yml (id, name, owner, project, folder, conductors, role, machine, state, created); validated, no secrets, never overwritten, a broken record never breaks a session start.
  • scripts/identity-cli.ts: write, list, show, resolve.
  • card-hook.ts: identity branch. A session with no DIGISMITH_ROLE, no HERDR_PANE_ID and a cwd whose main checkout (worktrees included) equals exactly one record's folder is that Maestro. Herdr sessions with env still win and print nothing. Two records for one folder: no card, a stderr note. Any error: no card, exit 0.
  • idle-check.ts: the conductor comes from the record; skills/catch-up/SKILL.md reads the context line first.

Not done

OpenCode Maestros. The real digismith-maestro record is live depot data, created at first use with identity-cli.ts write (see probe.md). A crashed sibling stays open in the context line until marked lost; the line shows its last_seen.

Review

Claude whole-branch review: no bugs. One minor note fixed: state must be an absolute path.

Tests

Full suite green (1808 tests before rebase). New: identity, identity-cli, the hook identity branch (worktree cwd, two records, herdr silent, env sessions unchanged, broken record, resume), idle conductor from the record.
