dg depot can now start and stop a process on macOS and Linux, and the Windows path is unchanged. On the Mac Workbox, dg depot opencode ensure started a real OpenCode server, the listening PID matched the tracking file, and stop left nothing behind. A second bug is fixed too: a spawn ENOENT from taskkill used to look like "already exited", so stopProcess could return stopped: true without killing anything. It now returns an error. Linux and Windows are covered by unit fixtures only.

  • process-lifecycle.ts: new pure parseLsofPid, parseSsPidForPort, listenerCommand(platform, port) and isProcessAlive. stopProcess takes an optional platform so tests can drive the Windows branch. The DGS-180 kill-on-failure catch in ensureProcess is unchanged.
  • The stop wait loop treats a zombie (ps -o stat= starts with Z) as gone. A child killed by the same Node process stays a zombie until the event loop runs, and kill(pid, 0) still succeeds on it. The CLI does not need this (ensure and stop are separate processes), but the in-process test does.
  • process-lifecycle.test.ts: fixtures for lsof and ss -ltnp (IPv4, IPv6, wildcard, longer-port non-match, no process column), the listenerCommand table, isProcessAlive, the taskkill ENOENT test (win32 branch on a host without taskkill) and an already-gone POSIX stop test. The existing Windows tests are untouched.
  • Not touched: bridge/, opencode/, index.e2e.
