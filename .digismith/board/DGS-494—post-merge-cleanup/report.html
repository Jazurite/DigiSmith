Post-merge cleanup — Implementation Report

Date: 2026-10-16 · Ticket: DGS-494 · Branch: DGS-494__post-merge-cleanup

Summary

Worker flow left its worktree and merged branch behind after a pushed merge, and a stale board file in the main checkout made git merge refuse. This change adds one cleanup script, a post_merge_cleanup preference gate, a stale-board move before the merge, and pointers in the runbook and Maestro prompt. Built inline with TDD; the Maestro approved the spec, and an independent whole-branch review found 10 items, of which the verified ones were fixed.

Documents: spec and plan.

What was delivered

PartResult
scripts/post-merge-cleanup.tsChecks the branch is merged into --base (default main), deletes the post-finish pins, removes the worktree (--force only when every untracked file is under .impeccable/), runs git branch -d. Stops with a message on tracked changes or real untracked files. --dry-run, safe re-run, already cleaned on a second run. 11 Vitest tests against temp git repos.
Skill Step 6Reads post_merge_cleanup: auto runs the script, ask asks each time, unset asks once and saves.
Skill Step 5 Option 1Moves an untracked own copy of the branch's board files to ~/.digismith-depot/backups/<branch>-stale-board/ before the merge (mv -n, never a delete).
Bootstrap, preferences, hook docBoard files are written inside the worktree only; the new preference key is documented; the pin deletion now belongs to the script.
Runbook and .opencode/prompts/maestro.mdStart command carries --allowedTools "Bash(node --experimental-strip-types */post-merge-cleanup.ts *)"; text points at preferences.post_merge_cleanup. The runbook is git-excluded and was edited on disk only.

Review

Fixed: cache files with spaces or non-ASCII names, second-run exit code, hardcoded base branch, unguarded discard path, mv overwriting a backup, running the script from inside the worktree, missing wording for a declined ask. Kept as specced: pins deleted second.
