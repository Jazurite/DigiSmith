Summary

Every Claude Code session with the DigiSmith plugin is now a run by itself. Each run has a role, a project and a ticket when one is known. Oculus and dg run list show these runs, and the watchdog flags only builder, reviewer and scout runs. The SessionStart hook makes an automatic run when DIGISMITH_RUN_ID is not set. The run id is s-<session_id>. An index in runs/.index/ maps the session id and the claude pid to the run. Inside herdr, a detached labeller sets the role once. The role rule is one function, roleOf. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (9 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 9 fix round(s) before merge.

Reference documents: the design spec and the implementation plan.

What Was Delivered

Task 1

Repo info and identity folder match

repoInfo reads project, root, branch and worktree from .git files without a git process; ticketOfBranch and maestroIdentityAt match the ticket key and the Maestro identity folder.

Task 2

The role rule and the run record fields

roleOf in run/role.ts is the one role rule; the run record gets source, project, session_id, role_from and a nullable ticket.

Task 3

The run index and the automatic start

runs/.index/ maps a session id and a claude pid to a run; startAuto makes s-<session_id> runs and continues a run after /clear.

Task 4

The hook's automatic path and the herdr labeller

The hook records a session without DIGISMITH_RUN_ID; a detached labeller reads herdr-ws agent list once and sets the role.

Task 5

The hooks.json guard, the compile cache, the timing test and the README

The hook command line skips a machine without a depot, uses the node compile cache, and has a timing test.

Task 6

Readers: dot folders, ticket by record, the activity window, project in the output

listRuns skips dot folders, filters by ticket before it reads events, and keeps a 7-day window; dg run list shows the project.

Task 7

Watchdog scope: only builder, reviewer and scout

WATCHED_ROLES and isWatched in watchdog.ts; unwatched runs close their open items with "role not watched".

Task 8

nightwatch views: project, source, a null ticket, the project filter, the window

RunRowView gets project, source and a nullable ticket; runsView and dg nightwatch view runs take --project.

Task 9

Nexus API and Oculus web: new roles, project, a null ticket

GET /api/v1/nightwatch/runs?project=P; six roles; Oculus shows the project and has a Project filter.
