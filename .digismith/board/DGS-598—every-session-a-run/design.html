1. Goal

Every Claude Code session that has the DigiSmith plugin becomes a Nightwatch run on its own. This includes the Maestro, conductors, workers, Reviewers, Scouts and any other session, in every project. No dg run start is needed. The dashboard and dg run list show every session.

Today a session is a run only when the conductor starts it with dg run start and passes DIGISMITH_RUN_ID (DGS-581, opt-in). Two days of real work left no run.

Done when: a fresh conductor, worker, Reviewer and Desktop Maestro session each show up in dg run list with the right role and project, without dg run start. A resumed session continues its run. The watchdog flags no maestro or conductor run.

2. Facts found by the probe (2026-10-24 12:15 UTC+7 [05:15 UTC])

  • What a hook sees. Claude Code gives every child process CLAUDE_PID (the claude process; it equals the parent pid of a tool shell), CLAUDE_CODE_SESSION_ID and CLAUDE_CODE_ENTRYPOINT. Inside herdr it also gives HERDR_PANE_ID (for example w2:p8W), HERDR_TAB_ID, HERDR_WORKSPACE_ID and HERDR_ENV=1. The hook payload on stdin has session_id, cwd, source (SessionStart) and reason (SessionEnd).
  • The herdr agent name is not in the environment. herdr sets no variable with the agent name. The DGS-418 card variables (DIGISMITH_ID, DIGISMITH_ROLE) are empty in a worker pane. The name comes only from herdr-ws agent list, where each agent has name, pane_id, tab_id and workspace_id. That call takes about 85–90 ms (python wrapper).
  • Hook cost today. On the Workbox, bare node -e 0 takes 60–70 ms. The current hook-cli.ts takes 120–140 ms per call, so it is already over 100 ms. With NODE_COMPILE_CACHE set, the same hook takes about 90 ms. Node start-up dominates, and the cache is the fast path.
  • Identity cards. ~/.digismith-depot/identities/*.yml have flat key: value lines. The folder: line names the repo root of a Maestro (DGS-411). The session-card hook already treats a session outside herdr in that folder as the Maestro.
  • Readers. listRuns, findRunDir, watch.ts and the nightwatch views all scan runs/*/<id>/run.json. Any folder name works. The Nexus API checks role against ROLES in scripts/nexus-shared/nightwatch.ts.

3. Layout and record

Folders

runs/<ticket or project>/<run-id>/run.json, events.jsonl, seq, lock/
runs/.index/sessions/<session_id>   one line: <folder>/<run-id>
runs/.index/pids/<CLAUDE_PID>       one line: <folder>/<run-id> <session_id>
runs/.index/node-cache/              the node compile cache of the hooks

The folder is the ticket key when the branch names one at SessionStart. Otherwise it is the project name. The folder never changes after the run is made. Readers skip names that start with .. dg run list --ticket KEY now matches the record's ticket field as well as the folder name, so a run that learns its ticket later still shows.

Run id

An automatic run id is s-<session_id>, made from the session that started the run. A UUID matches SAFE_RE. A resume keeps the session_id, so it finds the same id. A /clear gets a new session_id and continues through the pid index (section 4). dg run start ids stay as they are (builder-…).

run.json: new and changed fields (schema stays nightwatch-run/v1, fields only added)

A reader that meets an old record with no new fields reads source as start, and project, session_id and role_from as null.

4. SessionStart without DIGISMITH_RUN_ID

  1. Guard. No depot folder: nothing happens, and no node process starts (shell test, section 6). The hook creates runs/ when the depot exists and runs/ does not.
  2. Same session. .index/sessions/<session_id> exists (resume, compact, or a second SessionStart): append started with its source to that run. Done.
  3. /clear. source is clear, and .index/pids/<CLAUDE_PID> names a run whose last event is ended with reason clear, or which has not ended: write .index/sessions/<new session_id> to that run, then append started (source clear, with the new session_id). The run continues.
  4. New run. Otherwise, make the run folder and run.json (fields from section 3; role from the fast rules in section 5), then append started. Write both index files.
  5. Herdr labeller. Inside herdr (HERDR_PANE_ID set), when the run was just made with role_from: pending, the hook starts one detached child (spawn, detached, stdio: ignore, unref) and returns at once. Section 5 has the details.

An explicit DIGISMITH_RUN_ID always wins. With it set, every hook works as today (DGS-581), and no automatic run or index entry is made.

A sub-claude -p that inherits DIGISMITH_RUN_ID writes into the parent run, as today. A sub-claude -p without it becomes its own automatic run with role other. Subagents inside a session fire no SessionStart and stay out of scope.

5. Role, project and ticket

Fast rules (in the hook, file reads only)

  • Outside herdr (HERDR_PANE_ID unset), when one identity card's folder equals the main repo root of the cwd: role maestro, role_from: identity. With no card, or with two cards for the folder: role other, role_from: none. The card files are read with a line regex. This is the same match as findByFolder, without the full validator.
  • Inside herdr: role other, role_from: pending, until the labeller finishes.

Labeller (detached, inside herdr only)

It runs ~/.digismith-depot/bin/herdr-ws agent list with HERDR_WS set to the workspace part of HERDR_PANE_ID and a 3 s timeout. It reads only name, pane_id, tab_id and workspace_id of the entry whose pane_id equals this pane. It reads no pane text and touches no other agent. Name rules, first match wins:

Agent nameRole
ends with -conductorconductor
contains -revreviewer
contains scout or probescout
^[a-z]+-\d+$ (for example dgs-598)builder
anything else, or no entry for this paneother

The labeller rewrites run.json once, through a temp file and an atomic rename. It fills role, sets role_from to herdr (none when no name was found), and fills ticket from a dgs-NNN name when the ticket is still null. It changes no other field. This is the only edit of a run.json after it is made. The README rule "nothing edits it later" gets this one exception. When the labeller fails (timeout, herdr down, bad JSON), it sets role_from: none if it can, logs one line to hook-errors.log and exits.

Project and ticket

  • Project: walk up from the payload cwd to the first .git. If .git is a file (gitdir: …/.git/worktrees/x), the main root is the folder above that .git. Otherwise the root is the folder that holds .git. Project = the base name of the root, made safe. With no .git, project = the base name of the cwd. With no usable cwd, project = unknown. A repo without .digismith/ is recorded the same way (Emma, Soveron and others).
  • Branch: HEAD of that git dir (ref: refs/heads/X). A detached HEAD gives null. Worktree: the folder that holds the .git file, else null.
  • Ticket: ^([A-Z]+-\d+)__ on the branch, else (labeller) the dgs-NNN agent name upper-cased, else null.

A conductor, the Maestro or a Builder can move to another branch or worktree later. The record keeps the start values. Later facts belong in events, as in DGS-581.

6. Hooks, guard and cost

The guard [ -z "$DIGISMITH_RUN_ID" ] || … (DGS-581 decision 6) becomes this, for all five run-event entries in hooks/hooks.json:

D="${DIGISMITH_DEPOT_DIR:-$HOME/.digismith-depot}"; [ -n "$DIGISMITH_RUN_ID" ] || [ -d "$D" ] || exit 0; NODE_COMPILE_CACHE="$D/runs/.index/node-cache" node --experimental-strip-types "${CLAUDE_PLUGIN_ROOT}/scripts/run-events/hook-cli.ts" <kind>
  • No depot (a machine without DigiSmith's depot): exit 0, and no node process starts.
  • Other hooks (blocked, tool, turn_end, ended) without DIGISMITH_RUN_ID: the hook reads session_id from stdin, then the one index file, then appends. With no index entry, it writes nothing. Nothing else changes: same data, same 150 ms lock wait for tool (drop and log on timeout), 2 s for the rest.
  • Every failure: exit 0, print nothing, at most one line to hook-errors.log (256 KB cap, as now). A session is never hurt.
  • The hook keeps its import rule: node:fs, node:path, node:os, node:crypto, plus node:child_process only in the SessionStart path, loaded only when it spawns the labeller. No yargs and no git process.

Cost target, measured in a test

A test runs the real hook-cli.ts with the hooks.json command line (compile cache on, temp depot), 7 times for each of started (new run, in a fake herdr pane, so the labeller spawn is counted) and tool. It checks that the median wall time is under 100 ms. The labeller's own time (about 90 ms for herdr-ws) is not in the hook, because the hook does not wait for it. On a slow or busy machine the test reports the numbers. A separate env flag can turn the assertion into a report only (NIGHTWATCH_TIMING=report) so that a loaded CI box does not fail it at random.

7. Watchdog and dashboard

  • classify (DGS-583) handles only builder, reviewer and scout fully. For maestro, conductor and other it returns only ended or healthy: never blocked, stalled or lost. This also covers old dg run start runs with role other. No phase budget applies to them.
  • runWatch reads a run's run.json first and skips a run of those three roles before it reads its events. Such a run gets no attention item and no ClickUp comment. An open item that an older pass made for such a run is closed with the note "role not watched".
  • Nightwatch views: RunRowView gets project and source. ticket may be null. runs takes a project filter. ROLES in scripts/nexus-shared/nightwatch.ts gets maestro and conductor. The Nexus API runs query takes project. The web run filters get a Project select, filled from the projects in the loaded rows. A null ticket shows as -. Nothing else in the UI changes.

Speed and retention

Maestro and conductor runs are many and long, so each read path gets an activity window:

  • "Active within N days" means that the mtime of events.jsonl (else of run.json) is newer than N days. A stat costs far less than reading the events.
  • dg run list shows runs active within 7 days by default. --days N and --all widen it. The window is checked before any events file is read.
  • runWatch: unchanged 7-day rule on created_at for the watched roles. Unwatched roles are skipped at the run.json step.
  • Nightwatch views overview and runs load only runs active within 7 days. run and events still open any run by id.
  • No deletion or archive in this ticket. Deletes need Jack. If the folder grows too large later, an archive is a new ticket.

8. Other changes

  • dg run start accepts roles maestro and conductor, and writes source: start, project and role_from: start.
  • formatList and formatShow print project and show a null ticket as -.
  • packages/cli/src/run/README.md and autonomous/WATCHDOG.md describe automatic runs, the index, the labeller, the guard and the role scope.
  • Privacy is unchanged: no message text, prompts, tool inputs or outputs anywhere. The labeller keeps four fields from the agent list and drops everything else, including cwd and terminal_title.

9. Tests without Jack

All tests use fakes only: DIGISMITH_DEPOT_DIR in a temp folder, fake git trees (.git folders and .git files written by the test), fake identity cards, and a fake herdr-ws script, set through an env override (NIGHTWATCH_HERDR_WS), that prints a fixture agent list. No real ClickUp, herdr, live API or real depot.

  • SessionStart with no run id: a new run in runs/<project>/s-<sid>/, the index files, and one started event. With a DGS-1__x branch, the folder is DGS-1 and the ticket is set.
  • Resume (same session_id): no new run, a second started with source resume.
  • /clear (new session_id, same CLAUDE_PID, after ended reason clear): the same run continues. With another pid, or after ended with a different reason: a new run.
  • Explicit DIGISMITH_RUN_ID: the DGS-581 behaviour, byte for byte, and no index entry.
  • Roles: a Maestro identity outside herdr; no card; two cards; each herdr name rule; a missing pane entry; labeller timeout and bad JSON (record stays valid, role_from: none, log line).
  • Project: a main checkout, a linked worktree, a folder with no git, a name with spaces.
  • No depot folder: the hooks.json command exits 0 and makes no file. A tool hook with no index entry writes nothing.
  • Privacy: a payload with prompt, tool input and output text leaves none of it in any file under the temp depot (the existing test, extended to automatic runs and to the labeller).
  • Timing test (section 6).
  • Watchdog: maestro, conductor and other runs that are silent 2 h, over budget or blocked come back healthy, open no item, and are skipped before their events are read. Builder, reviewer and scout keep all DGS-583 tests.
  • Readers: old records without the new fields; dot folders skipped; --ticket by record; the 7-day activity window; the Nexus contract and route tests with the new roles, project and a null ticket; the web filter test.
  • The strip-types smoke test covers every new file.

10. First use (after the merge and the plugin update)

  1. The conductor runs the plugin update in the worker panes. The Desktop Maestro restarts to load the new hooks (the conductor notes this).
  2. Start a fresh conductor tab, one worker and one Reviewer without dg run start. Then open the Desktop Maestro. dg run list shows four new runs with roles conductor, builder, reviewer and maestro, and project DigiSmith.
  3. Resume one of them (claude --resume) and run /clear in another. Each one keeps its run id, and dg run tail shows the extra started event.
  4. dg autonomous watch --dry-run lists no maestro or conductor run.
  5. One session in an Emma repo shows that repo folder name as its project. The dashboard Project filter shows it.

11. Out of scope

  • Subagents inside a session (later: shown within their parent run).
  • Non-Claude harnesses (OpenCode).
  • Seat detection beyond DIGISMITH_SEAT.
  • Archive or deletion of old runs.
  • Any settings file, LaunchAgent or Caddy change. The hooks change only in the plugin's hooks/hooks.json.
