DGS-329 field options — Implementation Report

Ticket: DGS-329Date: 2026-10-11

Summary

dg clickup update-field now adds and removes dropdown options, besides the rename built in DGS-135. It is a dry run unless --yes. It reads the field first and sends every other flag back unchanged.

Built

  • --add-option <name> (repeatable) with --color (default #cecece). The orderindex is the highest existing one plus 1. A name that exists, a repeated name, an empty name and a bad colour are errors.
  • --remove-option <name|id> (repeatable) puts the option ids in options.rem. An unknown option, a repeat, or an option also renamed is an error. Add, rename, remove and the field name go in one PUT.
  • Removal is a delete. With --yes it also needs --confirm-remove "<exact name>"; without it the command exits 1 and sends nothing. It was tested with mocks only and never run for real.
  • The dry run prints the field's current options, the planned change, and for each removal how many tickets hold the option (FrontdoorClient.getFieldValueCount, a read-only GET with count_values=true&option_id=). A used option gets a WARNING that says what ClickUp does to the values is not captured.
  • No allow rule and no ask rule for update-field; .claude/settings.json is untouched. The permission question for --remove-option is parked for Jack.

Captures

The ticket names the 03 folder for both calls. The add call [91] is in Raw_10_10_2026_12_19_58.folder; only the remove call [240] and the count call [235] are in Raw_10_03_2026_13_50_53.folder. The add body is {name, color, orderindex} with no id.

Tests

update-field.test.ts: 12 tests at the base, 48 now (two describes: 44 and 4 argv tests). frontdoor.test.ts: 19 at the base, 26 now. Whole repo: 1348 at the base, 1391 now; the one failure is the known e2e --help colour test, the same as on the base.

Review

Claude whole-branch review: "ready after fixes", 8 findings. Fixed: (1) getFieldValueCount reads value_count strictly and throws on missing, empty, garbage, negative or fractional values, so a bad answer is never read as "no ticket holds it". (2) A failed count in the dry run prints WARNING: could not count tickets after the plan; with --yes the command exits 1 and sends nothing. (5) Tests run the command through yargs with real argv strings: two --remove-option flags need two confirms; the greedy form --remove-option A B removes both and still needs both confirms; an empty value is an unknown option; --add-option -x is refused by yargs, --add-option=-x works. (6) Test gaps closed: one of two removals confirmed, WARNING before the PUT line, confirm with other case, spaces or a look-alike unicode letter fails, exact body in the add+rename test. (8) Colour must be 3 or 6 hex digits.

Known limits (plan.md): clash checks ignore removals, so remove X + add X and remove B + rename A to B fail closed; a field with duplicate option names blocks every removal (finding 3, skipped); an id that equals another option's name resolves to the id (finding 7, left).
