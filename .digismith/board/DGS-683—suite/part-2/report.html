DGS-683 Castle: the herdr-ws scope — Implementation Report

Ticket: DGS-683 (part 2: T10, T11, T12) · Date: 2026-11-02

Summary

herdr-ws now takes a scope of session:workspace pairs, reaches the Floor (default) and one Castle workspace, lets only tc- and nw- conductors be closed, renamed or relocated in Castle, and logs every cross-project act. The script is not installed; the deployed copy and the live sessions are untouched. Read "Suite" in the spec and plan as "Castle".

What changed

  • Scope. HERDR_SCOPE (fallback default:$HERDR_WS); a leading --session S; the wrapper builds the herdr argv itself and never forwards a caller's --session, --socket or HERDR_SOCKET_PATH.
  • Castle close rule. tab close, agent stop, pane close need a tc-/nw- label; rename is judged on the old and new name; unknown labels fail closed.
  • Relocate and flag targets. pane move/swap parse argv against herdr's real flags; every verb refuses --flag=value and --current, and checks every --pane/--tab/--workspace/--source-pane/--target-pane value against the scope.
  • Audit log. One JSON line per outside workspace to drivers/<KEY>.log or _unmapped.log: time, who, own, target, agent, pane, workspace, verb. Without HERDR_WS it still logs, with own:"unknown". A write failure never blocks the call.
  • Text payloads. Send text containing --flag=value (for example pane run) as ONE quoted argument.

Tests

59 hermetic tests with a fake herdr (scripts/opencode-boot/herdr-ws.test.ts), fork pool of 2. The old read-only script test-herdr-ws.mjs: ALL PASS.
