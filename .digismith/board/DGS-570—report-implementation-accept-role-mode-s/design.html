Problem

digismith:report-implementation reads an SDD ledger and expects a Final review (base <BASE>..<HEAD>, <model>): ... line (MEMORY.md, "Final-review ledger lines are standardized"). It builds the Final Review & Fix rows (2c) from that line and the lines that follow it. With no such line it stops and asks (Step 1, Error Handling).

In role mode (Review mode: role) the ticket review is a Reviewer worker. SDD's Role Mode section writes only Task final: review requested and Review ticket final r<R>: F<n> -> <verdict> (...). In the first role-mode build (DGS-566, 2026-10-18) the Builder had to add the missing line by hand.

The choice

A. report-implementation reads role-mode linesB. Role Mode writes the expected line
EditsStep 1 check, 2c, Error Handling, Quick Reference in a 700-line skill; a second grammar to parseOne paragraph in the Role Mode section of SDD
Data gapA verdict line holds only F<n>, the verdict and a reason. It has no severity and no finding text. The report would need report.md from the pack folder, which is outside the ledgerNone. The Builder has the Reviewer's report and writes the one-line summary, as in hand mode
Other readersEach future reader of the ledger learns two grammarsMEMORY.md grammar stays the single contract
RiskHand mode and inline mode could regressHand mode and report-implementation are untouched
Decision: B. It is the smaller change, it touches only role mode, and it keeps one ledger grammar. A needs data the ledger does not hold.

Design

Add a "Final review lines" paragraph to ## Role Mode (a herdr Builder), after "Verdict lines". It tells the Builder:

  1. When the parent returns the round 1 result of the ticket review, append (before any fix wave)
    Final review (base <MERGE_BASE>..<HEAD>, <model>): <one-line verdict and finding summary>. <model> is the model: line the ticket pack command printed. The summary names each finding as F<n> <severity> <what>, or says "no findings". The base and head are the hashes given to dg reviewer pack.
  2. After the one fix wave and its scoped re-review, append Scoped re-review (fix base <FIX_BASE>..<HEAD>, <model>): <verdict> with the model of the round 2 pack.
  3. For a ticket finding decided parked, write the verdict line (already required) and also Final review: parked — F<n> <finding> — ruling: <why>, the shape report-implementation reads. A fixed or rejected finding needs no extra line: 2c already finds it through the Scoped re-review line and the F-id in the Final review line.
  4. The ledger then holds the lines report-implementation expects. Nothing is written by hand outside Role Mode.

The Review ticket final verdict lines stay as they are: dg reviewer table reads them.

Files

  • skills/subagent-driven-development/SKILL.md: Role Mode section only (one paragraph; nothing else in the file). DGS-568 may also edit this file. The two edits sit in different sections, so a merge conflict is unlikely. The second ticket to merge rebases.
  • packages/cli/src/reviewer/sdd.test.ts: one new test.
  • MEMORY.md: one sentence in the Final-review convention: role mode Builders write the same lines.
  • Not touched: skills/report-implementation/SKILL.md, skills/reviewer/SKILL.md, anything under packages/cli/src other than the test (so no dist rebuild).

Assumptions

  • The ticket evidence settles the choice; no taste or product question is open.
  • The Builder gets the finding severity from the Reviewer's report, which its parent hands over with the verdict.
  • A parked ticket finding after the final review is rare; the extra line is cheap.
  • First use after the merge: the next role-mode build. Its report-implementation run must pass Step 1 with no hand-added line.

Tests

A test in sdd.test.ts (same style as the existing role-mode tests): the Role Mode section contains Final review (base, Scoped re-review (fix base and Final review: parked, and sits before ## Final Review. pnpm runs it with the CLI package tests.
