3. Confirmed design ruling: the combined tracked-check

jira-intake Step 3.3's "already tracked" check intentionally combines .digismith/board/ and .digismith/docs/ (git ls-files .digismith/board/ .digismith/docs/) even though the separate "is this write's own target ignored" check is target-only (git check-ignore -q on just the folder this write is headed to). This is deliberate, not a bug: the commit-vs-gitignore decision is made once per repo, not once per folder — the stored answer is a single bare .digismith/ line in .gitignore, which is a prefix match covering both folders at once. Tracked files in either folder therefore correctly mean the repo already chose "committed," and splitting the tracked-check per folder would just reintroduce the redundant question this check was written to avoid. A future reader hitting this asymmetry (one check target-only, the other combined) should read this paragraph rather than re-opening the question.
