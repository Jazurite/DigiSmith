2. scripts/board-path.ts

Builds and parses the board folder name <KEY>—<slug> (section 2), per section 9's build/parse rules. No existing code implements the slug algorithm today — digismith:jira-intake describes it only in prose, for an LLM to follow by hand. This module is the first time it's codified.

export function slugify(title: string): string
// lowercase; drop whole-word fillers (a, an, the, on, to, of, for, in);
// collapse remaining non-alphanumeric runs to one ASCII hyphen;
// truncate to ~40 chars at a word boundary; never leave a trailing
// filler word or hyphen. Same algorithm jira-intake's prose already
// describes (Step 3.1) — codified here as the first real implementation,
// not a second one.

export function buildFolderName(key: string, title: string): string
// `${key.toUpperCase()}—${slugify(title)}`.normalize("NFC")
// (NFC is a no-op while slugify only ever emits ASCII — defensive per
// section 9, in case a future slugify revision keeps more of the title.)

export type ParsedFolderName = { key: string; slug: string }
export function parseFolderName(name: string): ParsedFolderName
// Split at the FIRST U+2014. No em dash found → throw (section 9: "fails
// loudly if no U+2014 is found, rather than silently guessing a
// different separator"). Key validated against /^[A-Z]+-\d+$/ after
// uppercasing; slug returned untouched (it can never itself contain an
// em dash, so first-occurrence splitting is unambiguous).

export function boardRelPath(key: string, title: string): string
// `.digismith/board/${buildFolderName(key, title)}`

No caller inside this unit — Parts 3/4/6 wire it into writing-plans, report-implementation, update-history.ts, and the file moves. Section 9's risk table also proposes a thin dg board path <key> <title> CLI command for a human copy-pasteable result. No board folder exists yet (Part 6 hasn't run), so nothing needs that command today — proposing to defer it to whichever part first creates a real board folder, rather than building a CLI surface with no caller. Flagging this as a scope call I'm making, not a Jack-level policy question — easy to revisit.

4. lineage-handoff.ts and session-init.ts: no functional change

I expected to find a behavior gap here and didn't. Re-reading the current skills/handoff/SKILL.md text closely: the SessionStart banner (built by session-init.ts's buildLineagePointer) is deliberately fallback-only, permanently — not an interim state this unit needs to close. The skill text says so directly: "That line is built by the script and lists only fallback notes: a note at .digismith/sessions/<session-name>/note.md is found by 'resume' or 'Arise', not by that line." A current-convention note is never meant to appear in that banner; it's found by direct session-title match instead. scripts/lineage-handoff.ts's listNotes/parseLineageKey already implement exactly the fallback-only behavior this calls for — no rewrite needed.

5. .git/info/exclude: a conflict with the spec, flagged for approval

Design section 10's bullet: "drop the old handoff.md/brief.md patterns, add .digismith/board/** ... and .digismith/sessions/**/note.md, .digismith/sessions/**/brief.md." Checked this repo's actual .git/info/exclude and found three problems with applying it literally, right now:

  • The sessions patterns are already redundant. .digismith/sessions/ is already excluded as a whole directory (one line, already in the file). Adding .digismith/sessions/**/note.md and .../brief.md on top does nothing new.
  • Dropping the old fallback patterns now is premature and unsafe. Six real handoff.md files are live fallback notes today (A/A.4, B, B/B.2, D/D.3, E/E.4, _unlettered). They're excluded by .digismith/docs/**/handoff.md right now. Dropping that pattern before Part 6 migrates or moves those six files would make them show up as untracked, "ready to add" content in the main checkout — a real risk, not a theoretical one, and squarely the kind of thing the brief tells me not to touch this unit ("do not move or edit .digismith/sessions/DigiSmith/note.md," and more generally the file moves are Part 6's job).
  • .digismith/board/** would silently change this repo's own commit choice. Confirmed live: git check-ignore -q .digismith/docs/_unlettered/... exits 1 — this repo does not gitignore its own docs folder; every ticket's design.html/plan.md/ report.html is committed. Section 2 says board/ keeps "the same mechanism as today (commit-vs-gitignore stays a per-repo choice)" — for DigiSmith's own repo, that choice is "commit it." Blanket-adding .digismith/board/** here would reverse that silently, and would land Part 6's own migrated files as gitignored by accident.

Recommendation: no change to .git/info/exclude in this unit. Revisit the old fallback patterns exactly when Part 6 migrates or removes the six handoff.md files (drop the pattern only once nothing needs it), and treat .digismith/board/** as something Part 6 decides per this repo's existing per-repo choice (committed, matching docs/ today) rather than something this unit adds pre-emptively. This is the one point in this design I'm flagging for explicit sign-off rather than just proceeding on — it reverses part of what section 10 literally says to do.

6. Testing

Vitest, matching every existing scripts/*.test.ts (real temp git repos via fs.mkdtempSync + spawnSync("git", ...), not mocked git).

  • board-path.test.ts: slug determinism (same title twice → same slug), filler-word dropping, truncation at a word boundary with no trailing hyphen/filler, uppercase-key round trip, parse failure on a hyphen or en dash substituted for the em dash, parse success split at the first em dash when a slug happens to contain one some other way (defense in depth, even though slugify can't produce one), case-insensitive key matching.
  • session-path.test.ts: safe-name acceptance/rejection (empty, ., .., a name containing / or \), note/brief path shape for a plain name and for a name with spaces and ⚚ (confirms section 4's worker titles don't need special-casing — only the agent name, already plain, is ever used as <session-name>).
