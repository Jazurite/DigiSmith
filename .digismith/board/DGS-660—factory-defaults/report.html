Factory defaults — Implementation Report

Date: 2026-10-26 Ticket: DGS-660

The factory now claims a to do ticket that has spec and plan, no open blocker and a Mode that is not Manual. An empty Mode is Autonomous, an empty Sign-off is Auto, and the milestone never blocks a claim.

What shipped

  • ready.ts: no Sign-off or milestone reason; the Mode reason only for Manual ("Mode is Manual").
  • scan.ts: an empty Sign-off becomes Auto; only Manual is skipped; explicit Jack still stops at acceptance.
  • tracker-clickup.ts: every non-Manual ticket is read in full; a failed milestone read gives null and never fails a scan.
  • schedule-release.ts: an empty Mode moves like Autonomous; the no-mode stop is gone.
  • WATCHDOG.md, the scan help text and the scheduler job description state the new rule.

Rebase on DGS-658

DGS-658 added inProjects. The conflict was in ready.ts and its test. Jack's rule won: the old milestone and Sign-off lines are removed, the inProjects read stays, and DGS-658's three tests that asserted the old refusal became one "no milestone passes" test.

Tests

New and changed tests cover empty Mode, empty Sign-off and no milestone (each passes), explicit Manual (skipped), explicit Jack (stops at acceptance), the full read of an empty-Mode ticket, and a failed milestone read.

Review

Three task reviews and the whole-branch review: Approved, no Critical or Important. Minor findings: three fixed, one parked, one rejected (see findings.md).

First use

dg autonomous scan --dry-run --repo <main checkout> lists DGS-652 and DGS-654 as ready and skips the Manual tickets.
