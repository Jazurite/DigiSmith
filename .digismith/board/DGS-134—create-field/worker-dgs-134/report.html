DGS-134 dg clickup create-field — Implementation Report

Ticket: DGS-134Date: 2026-10-11

Summary

Added dg clickup create-field: it creates a dropdown custom field scoped to one folder, through the Frontdoor API. A dry run unless --yes.

Built

  • FrontdoorClient.createField(body): POST /customFields/v2/field?ignore_existing=true, with category_id set to the folder id. No location call is needed for a folder.
  • create-field --name --type drop_down --option name[:color]... --folder [--description] [--yes]. Default colours by position. It prints the field id and option ids.
  • The public API (v2, v3) cannot create custom fields, so Frontdoor is used.
  • Not built: setFieldLocations (dead code) and --list (refused: the list location type is not captured). No allow rule.
  • Tests: 15 new; the whole repo passes with FORCE_COLOR=1; the CLI build is clean.

Review

Claude whole-branch review, two verified finds, fixed with tests: a bare 3-digit hex tail (Plan:add) was read as a colour; a repeated --name gave a poor error.

Follow-ups

Capture the list location type, then build --list and setFieldLocations.

First use

The Profile dropdown on folder I: Account, after the merge and push. The result goes to the maestro report.
