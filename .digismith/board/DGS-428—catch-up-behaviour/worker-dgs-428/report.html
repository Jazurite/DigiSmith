DGS-428 catch-up behaviour — Implementation Report

Ticket: DGS-428Date: 2026-10-13

Summary

A Maestro can be caught up on its conductor's domain. A skill matches the intent by meaning, the command scripts/conductor/catch-up-cli.ts builds the catch-up from the conductor state, the cards, git and ClickUp, and the finished text goes into the conductor's note as one block per Maestro identity.

Built

  • catch-up-window.ts: window and idle test (asking session excluded, 24 hours for a new identity).
  • catch-up.ts and catch-up-cli.ts: build, render, write the block, reuse under 30 minutes, --refresh; exit codes 0, 2, 3, 4.
  • idle-check.ts: the second trigger, a pre-prompt handler (registered in DGS-418's hook list at merge).
  • skills/catch-up/SKILL.md: the intent skill, no keyword list.
  • deps-stub.ts: temporary stand-ins for DGS-417, 422 and 427.

Not done

The idle handler is registered after DGS-418 merges. OpenCode is text only (DGS-430). ClickUp comments are not read, only status.

Review

Claude whole-branch review, three findings, all fixed with tests: an orphan open marker could erase note text on a second write, path traversal through --project and --conductor, and unchecked card values in the idle hint.
