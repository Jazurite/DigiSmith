DGS-320 dg clickup update-folder — Implementation Report

Ticket: DGS-320Date: 2026-10-11

Summary

Added dg clickup update-folder --folder <id> --name <name> [--yes], which renames a folder through the public API (PUT /v2/folder/{id} with {name}). It is a dry run unless --yes. The request body is taken from the API reference and is not proven live yet; the first real send is DGS-321.

Built

  • ClickUpClient.updateFolder and getFolder (PUT and GET /folder/{id}).
  • The dry run prints the call and builds no client, so it needs no credentials and no network. An empty or blank name is refused, and so is a folder id that is not digits.
  • After --yes the command reads the folder back and prints the new name; a different name exits 1.
  • No --description: the API has no folder description. No allow rule was added.
  • 13 new tests (2 client, 11 command); the repo suite has 1361 tests (base 1348), and the one known e2e --help colour failure remains.

Review

The Claude whole-branch review said ready to merge, with four minor findings. Fixed: the name is trimmed before it is sent and compared with the read-back; a read-back answer without a string name now fails with "no name in the response" instead of reading back "undefined". Added tests for edge whitespace, a unicode name and a missing name. No other command has a registration test, so none was added for index.ts. Left as is: no name length cap. The CLI build was run with pnpm --filter @digismith/cli build.
