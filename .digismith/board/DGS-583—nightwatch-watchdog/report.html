Summary

A plain-code watchdog reads the DGS-581 run record every 5 minutes, puts blocked, stalled and lost runs on an attention list, comments once on the ticket, and adds the circuit breaker and the failure causes. The Maestro dropped the automatic retry during the build (option C): the attention item records retryEligible and causeClass, and the retry is the follow-up DGS-588. Code in packages/cli/src/autonomous/ gets a pure watchdog.ts and small I/O modules around it; dg autonomous watch, attention, resume and release --cause wrap them; one new job runs watch every 5 minutes in the existing Nexus scheduler. No new service, no model tokens. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (9 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 8 fix rounds before merge.

Reference documents: the design spec and the implementation plan.

What Was Delivered

Task 1

Preflight

Probe of the merged DGS-581, DGS-486 and DGS-582 code; it found that the retry has no consumer, and the Maestro chose to drop the retry.

Task 2

The pure classifier

classify, phaseOf and decideRetry in watchdog.ts: five states, the check order, the phase clocks and the review-clock restart; no I/O.

Task 3

Budgets from the config file

readBudgets reads nightwatch.budgets from .digismith/config.yml with defaults 45, 60 and 20 minutes; a bad value gives one problem and the default.

Task 4

Attention list and notify

The one attention writer is widened to six kinds and a resolved line; attention.ts reads and formats it; notifyNew posts one ticket comment per new item with limits.

Task 5

Failure causes and the breaker

The twelve-code cause list with three classes, and breaker.json that opens at two failed releases and fails closed.

Task 6

The watch pass

pane.ts (one read-only herdr pane list per workspace) and runWatch, which classifies every open run and opens, resolves and comments.

Task 7

Commands, release with cause, breaker in the scan

dg autonomous watch, attention, attention resolve and resume; release --cause; the scan stops while the breaker is open; back closes it.

Task 8

Registry entry, catch-up block, report block

The nightwatch-watchdog job every 5 minutes in the Nexus scheduler, a Needs Jack, Nightwatch block in the catch-up, and an Attention block in the report.

Task 9

Whole-ticket check, runbook text and docs

Ten hand mutation checks all caught, the runbook text for the conductor, and WATCHDOG.md.

Follow-ups

  • The automatic retry is the follow-up DGS-588 (J.5, waits on DGS-583). DGS-583 records retryEligible and causeClass on each attention item and writes nothing to the DGS-582 journal.
  • Task 3: an inline budgets: {} flow style and tab indentation in .digismith/config.yml are ignored without a problem message.
  • One-time reopen at upgrade: an already-resolved item can reopen once, because an older watch-state.json has no since.
  • Second prompt on the same run: a new blocked episode (a later since) opens item n+1 even after Jack resolved the earlier one; the same since stays closed.
  • An old lost item is not closed automatically; only blocked and stalled items close by themselves. Jack closes a lost item with dg autonomous attention resolve.
  • Runs older than 7 days are skipped unless they have ended and still hold an open blocked or stalled item (F4, F11). Each run is read once per pass.
  • Older type errors in tracker-clickup.ts and some older test files remain; none are in files this ticket added.
