Goal

On 2026-10-19 a night merge stood still from 04:21 to about 07:50 UTC+7 (a classifier block, DGS-572) and nobody knew. This ticket adds a plain-code watchdog that reads the run record of DGS-581 and puts a stuck run on an attention list within minutes. It also adds the circuit breaker and the failure causes with one bounded retry. It uses no model tokens and no new service. The ten decisions and the four open points come from the Maestro and are settled (checkpoint 1, 2026-10-21). Warren (MIT) gave ideas only; no code is copied.

Out of scope: the night mandate hook (DGS-584), merge and cleanup safety (DGS-585), the UI (DGS-586), push and email (DGS-448).

The classifier

packages/cli/src/autonomous/watchdog.ts exports a pure function. It does no I/O and reads no clock of its own.

classify(run, events, pane, now, budgets) -> { state, cause, since }
state: 'healthy' | 'blocked' | 'stalled' | 'lost' | 'ended'
pane:  'present' | 'gone' | 'unknown'   // the command looks it up; 'unknown' when herdr does not answer

run is the frozen run.json, events the parsed events.jsonl lines (a line that does not parse is skipped), now a number, budgets the resolved minutes.

StateRule
endedAn ended event exists. Nothing else is checked.
lostNo ended, and the pane is gone, or the newest event is older than 30 minutes (silence). The run has no events at all: silence counts from created_at.
blockedThe last blocked event has no later tool or turn_end. since is that event's time.
stalledThe phase clock is older than the phase budget (next section).
healthyNone of the above.

Order of the checks: ended, then pane gone (lost), then blocked, then silence (lost), then stalled. A blocked run waits for a human and sends no events, so the 30 minute silence rule must not turn it into lost. A gone pane still wins over blocked, because nobody can answer a pane that does not exist. pane: 'unknown' never makes a run lost by itself; only silence can.

Phases and budgets

Budgets come from .digismith/config.yml under nightwatch.budgets, in minutes, defaults building: 45, review: 60, merge: 20. A value that is not a positive whole number, or a block that does not parse, gives one attention item (kind failed, cause bad-budget-config, run -) and the defaults are used for that value. It never turns the watchdog off.

The phase and its start come from phaseOf(run, events), also pure:

  • The latest phase event (data.phase is building, review or merge) sets the phase; its time is the start. A phase ends at the event merged (merge), or at ended.
  • No phase event: a builder run is building and a reviewer run is review, both from the started event (from created_at when there is none). A scout or other run has no phase and is never stalled.
  • A builder's review_ready event starts a new building clock when the next tool event comes, so the 45 minutes count per task, not per run.

Settled by the Maestro (checkpoint 1): DGS-581 adds one event type phase (data.phase: building|review|merge) to its closed set and to dg run event. The DGS-582 controller writes it on each phase change; the conductor runbook line covers manual runs. This ticket only reads phase events and adds no data.phase to other events. A run with no phase event uses the role default above, so a merge without the marker is never stalled; blocked and lost still work.

The watch command and its schedule

dg autonomous watch [--dry-run] does the I/O around classify: it lists <depot>/runs/*/*/run.json (root from $DIGISMITH_DEPOT_DIR, else ~/.digismith-depot), reads the events, asks herdr whether the pane still exists (a read-only look-up through herdr-ws), calls classify, and applies the result to the attention list. It watches every open run, not only autonomous ones. A run is open when it has no ended event and is not already past the retention rule below.

  • Closed runs are not re-read forever. Only runs created in the last 7 days are looked at; an older run without ended is skipped and not reported. (Retention keeps the 5 minute pass short.)
  • Single pass, never throws. A broken run directory is skipped with one line on stderr. Exit 0 unless the depot root cannot be read at all.
  • Output: one line per run whose state is not healthy or ended, then a summary line. --dry-run prints the same and writes nothing and sends nothing.

Registry entry

One defineJob entry in scripts/nexus-api/src/scheduler/registry.ts, in the style of the DGS-486 entries (file: process.execPath, absolute dg path): name nightwatch-watchdog, atUtc7: '00:00', windowEndUtc7: '23:59', everyMinutes: 5 (the registry minimum), so it runs all day, not only in the night window. catchUp: 'skip', manualOutsideWindow: 'allowed', timeoutMs 2 minutes, notify: 'failures', order: 40. No new service.

The attention list

~/.digismith-depot/autonomous/attention.jsonl (the folder honors AUTONOMOUS_DIR, as DGS-486 does). Append only: no line is ever rewritten. DGS-582 names the same file and line shape; if its spec differs, DGS-582 follows this one (open point 1).

open:     {"schema":"nightwatch-attention/v1","id":"<run>.<kind>.<n>","ts":"<ISO UTC>","ticket":"DGS-583","run":"<run-id>",
           "kind":"blocked|stalled|lost|refused|failed|unknown","cause":"<code or short text>","since":"<ISO UTC>"}
resolved: {"schema":"nightwatch-attention/v1","id":"<same id>","ts":"<ISO UTC>","resolved":true,"by":"watchdog|jack","note":"..."}
  • One open item per (run, kind). n counts the earlier resolved items of that pair, so a reopened problem gets a new id. The open state is derived: an id with no later resolved line.
  • Auto-resolve: the watchdog resolves blocked and stalled items when the run is healthy or ended again. lost, refused, failed and unknown stay open until Jack (or a command) resolves them, because the cause needs a human look.
  • Writers: the watchdog, and dg autonomous release (kinds failed, refused, unknown). Each line is one appendFileSync of a short line; readers skip a line that does not parse.
  • dg autonomous attention [--json] lists open items (id, ticket, run, kind, cause, since in UTC+7, age). dg autonomous attention resolve <id> [--note ..] appends the resolved line (by: jack); an unknown or already resolved id exits 1 and writes nothing.
  • The catch-up (scripts/conductor/ consult) and autonomous-report (DGS-486) each add an Attention: block with the open items, none when empty. Both read the file through one shared reader in packages/cli/src/autonomous/attention.ts.

Notify

A new open item posts one ClickUp comment on its ticket through dg clickup add-comment --task <ticket> --text .. --yes, the same call shape as notify.ts. The watchdog is a short process every 5 minutes, so the in-memory map of notify.ts does not work. The limit lives in ~/.digismith-depot/autonomous/notify-state.json (atomic temp file and rename): at most one comment per ticket and kind per hour, and at most 10 comments in one pass. An item whose comment failed or was limited stays marked unsent and is tried again at the next pass. A failing comment never stops the pass or the item. The text is: Nightwatch <kind>: run <id>, <cause>, since <UTC+7> (UTC+7). Needs Jack. Items with no ticket (the budget config item) get no comment. Push and email stay with DGS-448.

Circuit breaker

State file ~/.digismith-depot/autonomous/breaker.json: { "open": boolean, "streak": number, "failed": ["DGS-1", ..], "openedAt": ISO | null }, written with a temp file and rename.

  • dg autonomous release --result failed adds one to streak and records the ticket. --result merged sets streak to 0. stopped and awaiting-jack change nothing: Jack's wait is not a failure. A failed release whose cause class is transient and that gets its one retry (next section) does not count yet; the retry's own result counts.
  • streak reaching 2 sets open: true, writes an attention item (kind failed, run -, cause circuit-breaker-open) and one comment on the second ticket.
  • autonomous-scan reads the file first. When open it exits with the outcome breaker and claims nothing, makes no ClickUp call and writes one event. An unreadable or malformed file counts as open (fail closed).
  • dg autonomous back and the new dg autonomous resume set open: false and streak: 0 and resolve the breaker item. resume only closes the breaker; it does not touch the away switch. Nothing else closes it, not even a day passing.

Failure causes and one retry

dg autonomous release --ticket K --result failed --cause <code>. The list is a constant in causes.ts, each code in one class. A code outside the list is recorded as unknown with a warning (the release itself never fails, or the lock would stay held at night).

ClassCodesRetry
transientgateway-5xx, gateway-timeout, rate-limited, pane-died, tab-lostone automatic retry
durableclassifier-block, merge-refused, test-red, review-rejected, spec-gapnone; goes to Jack
unknownunknown (also no --cause, or any other text)none (fails closed)

A classifier block is durable by rule: it can only be fixed by Jack.

  • Pure decision: decideRetry(kind, causeClass, retriesUsed) -> 'retry' | 'attention'. Retry only when the class is transient, or the kind is lost, and retriesUsed is 0. A lost run is re-dispatched once; blocked and stalled never retry (a human looks).
  • The retry count lives in the DGS-582 journal. The decision reads it through journal.retryCount(ticket) and records a retry as a planned entry before anything runs, so a restart of the watchdog, the controller or Nexus never gives a second retry. The retry itself is a controller action (planned, then settled); the watchdog and release only plan it. They never start a worker.
  • When the decision is attention, the open item is the result, and Jack sees it in the catch-up.

What the watchdog never does

It never answers a prompt, never sends keys to a pane, never kills a process, never deletes or rewrites a file (the attention list and the run files are append only; the two state files are replaced by rename, which is not a delete of data anyone reads). Its herdr access is one read-only "does this pane exist" call. A test reads the source of watchdog.ts and the watch command and fails on any herdr verb other than that call, on kill, unlink, rm and on send.

Tests and first use

Tested without Jack, with vitest, a fake clock (now is a number or an injected function), fake run.json and events.jsonl in a temp depot (DIGISMITH_DEPOT_DIR and AUTONOMOUS_DIR point there), a fake pane look-up and a fake dg that records comments. No real depot, no herdr, no ClickUp, no Nexus.

  • classify: each state, the check order (blocked plus silence is blocked; blocked plus gone pane is lost), the 30 minute edge (29:59 and 30:00), pane: 'unknown', no events, a blocked event followed by tool, by turn_end and by nothing, each phase budget at the edge, a builder per-task reset, a scout never stalled, an unparsable line skipped.
  • budgets: defaults, an override, a negative, a string and a broken block (one item, defaults used, the watchdog still runs).
  • attention: open, one open per (run, kind) on two passes, auto-resolve of blocked, a reopened item gets n+1, lost stays open, resolve of an unknown id exits 1, an unparsable line in the file.
  • notify: one comment per new item, none on the second pass, the per-hour limit, the 10 per pass cap, a failing dg keeps the item unsent and retries, no comment for a ticket-less item.
  • breaker: two failed releases open it; a merged release between them resets; stopped does not count; a transient retry does not count; the scan exits breaker with zero ClickUp calls; a malformed file is open; back and resume close it.
  • causes and retry: every code in exactly one class; an unknown code becomes unknown; decideRetry table; a second pass after a restart does not plan a second retry (journal count 1); the watchdog plans but never starts a worker.
  • watch command: a depot with a healthy, a blocked, a stalled, a lost and an ended run gives four items and one comment each, then a second pass adds nothing; --dry-run writes nothing; the 7 day skip; a broken run directory is skipped; the "never" source test.
  • registry: the new entry passes validateJobs, runs every 5 minutes and sits in the window all day.
  • readers: the catch-up and autonomous-report show the open items and none.

First use (after DGS-582 and this ticket are merged, installed, and the Nexus API restarted once): the conductor runs dg autonomous watch --dry-run against the real depot and sees only real runs and no change on disk. Then it starts a throwaway worker through the runbook (dg run start, then the worker), triggers one permission prompt and leaves it unanswered. Within 5 to 10 minutes dg autonomous attention shows one blocked item and the ticket has one comment. The conductor answers the prompt; the item resolves itself at the next pass. Then it closes the tab; the run, with no ended event, becomes lost after the pane is gone. Jack's own check is the morning catch-up: it shows Attention: and none on a quiet night.

Dependencies and open points

  • Needs DGS-581 (run record, merged or in review) and DGS-582 (controller and journal). No build starts before the Maestro orders it, after DGS-582 is merged. The plan sets the interfaces it needs from DGS-582 (journal.retryCount, journal.plan) as a small file the build checks first.
  • Needs DGS-486 (autonomous-scan, release, back, report). At the time of this spec the code is in a worktree, not on main, and packages/cli/src/autonomous/ does not exist on main. If DGS-486 is not merged when the build starts, the Builder stops and tells the conductor.
  • Settled, attention file shape: the shape in this spec is DGS-583's; DGS-582 follows it (the conductor tells dgs-582).
  • Settled, merge phase marker: the phase event type in DGS-581 (see "The classifier"). The build needs DGS-581 to have it on main first; the plan's first task checks that.
  • Settled, blocked beats silence: a run waiting for a prompt is blocked, and only a gone pane makes it lost.
  • Settled, 7 day retention: runs older than 7 days with no ended event are skipped. The window is a constant.
