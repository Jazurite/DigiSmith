DGS-136 dg clickup list-fields and --field — Implementation Report

Ticket: DGS-136Date: 2026-10-10

Summary

Added dg clickup list-fields and a repeatable --field "<name or id>=<value>" option on create-task and update-task. First use set ClickUp API Type on DGS-266 and DGS-267 (Frontdoor) and DGS-320 (Public); each read back correctly.

Built

  • list-fields --list <id> [--json]: id, name, type and drop-down options of a list.
  • --field resolves a field by id or case-insensitive name; a duplicate name is an error that asks for the field id; an unknown field or option is an error that lists the valid names. Types: drop_down (option name or id), text, short_text, number, currency, checkbox. labels and automatic_progress are refused.
  • Every field resolves before the first write, so a bad one writes nothing. No dry run, like update-task. update-task with only --field skips the empty PUT. A failed field write names the field and shows ClickUp's error body.
  • Tests: the CLI suite passes (443 tests) with FORCE_COLOR=1; the build is clean.

First use

With Jack's yes at checkpoint 2: DGS-266 and DGS-267 = Frontdoor, DGS-320 = Public. The first run returned 404 on each task and wrote nothing; two retries later all three were set. The 404 cause was not found and looks transient on the ClickUp side.
