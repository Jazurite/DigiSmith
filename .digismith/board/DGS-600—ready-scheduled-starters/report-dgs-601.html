Summary

A Nexus job schedule-release moves each scheduled ticket whose "Scheduled at" is past to ready (Mode Autonomous) or to do (Mode Manual). dg can create the date field, write a date-and-time value and create the ClickUp "Schedule" view. A pure core runScheduleRelease uses the DGS-600 Tracker, writes events to events.jsonl and keeps its comment-once notes in schedule-notes.json; the command dg autonomous schedule-release wraps it, and the Nexus registry runs it every 5 minutes. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (9 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 1 fix round before merge.

Reference documents: the design spec and the implementation plan.

What Was Delivered

Task 1

Client: date value options and space views

setCustomField(..., valueOptions?) sends value_options; getSpaceViews and createSpaceView read and create space views.

Task 2

create-field --type date

buildFieldCreateBody takes a field type; a date body has type: "date" and type_config: {}, with a capture hint on a 4xx only.

Task 3

--field writes a date and time

parseDateTimeValue reads YYYY-MM-DD HH:MM (UTC+7) or an ISO time with an offset; date fields are sent with { time: true }.

Task 4

The tracker reads Scheduled at

LoTask.scheduledAt is ms, null or "invalid"; EventKind gains schedule-move and schedule-move-failed.

Task 5

The schedule-release core

runScheduleRelease moves due tickets by Mode, reads the status back, comments once per problem and never stops on one failed write.

Task 6

dg autonomous schedule-release

The command prints one summary line and one line per scheduled ticket; --dry-run writes nothing.

Task 7

The Nexus job

Job schedule-release: every 5 minutes, all day, catchUp: 'skip', order 45, no model tokens.

Task 8

dg clickup create-view

Creates a list view at a space, filtered on one status and sorted by one custom field id; refuses a name clash and reads the view back.

Task 9

Whole-suite check and the post-merge setup

Part A: all suites and the strip-types smoke pass. Part B (field, view, Nexus restart, first dry run) runs after the merge.
