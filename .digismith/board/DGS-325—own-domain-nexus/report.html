DGS-325 own domain for Nexus — Implementation Report

Ticket: DGS-325Date: 2026-10-13

Summary

pazurite.com (Nexus, /api/v1/...) and opencode.pazurite.com (OpenCode at /) become DNS-only Cloudflare records that point to the Workbox's tailnet address 100.108.1.19, so only Jack's devices with Tailscale on reach them. Tailscale Serve keeps port 443 and forwards the raw TCP stream to Caddy on 127.0.0.1:8443. Caddy ends TLS, gets its certificates by DNS challenge, Caddy listens on loopback only. The workbox.tail730dcf.ts.net name is dropped (Jack's decision): Caddy's Tailscale certificate getter cannot reach the local tailscaled, that URL stops working at the cut-over (J7), and Jack re-pairs the OpenCode Desktop app with https://opencode.pazurite.com. The rollback brings it back. The cut-over is done and first use passed: Jack logged in at https://opencode.pazurite.com and streaming works.

Findings that shaped the design

  • A non-root process on macOS 26.7.1 cannot bind port 443 on a specific address; only 0.0.0.0 works, and that includes the company LAN. Hence the raw TCP forward.
  • Caddy v2.11.7 with caddy-dns/cloudflare v0.2.4 comes pre-built from Caddy's download service, and the hash is reproducible.
  • A throwaway Caddy on 127.0.0.1:18443 streams SSE, passes a websocket upgrade, and refuses connections on the LAN and tailnet addresses.
  • Tailscale Serve did not answer on the IPv6 address from the Mac, so the Shopify AAAA is removed instead of repointed.

Known gaps

  • Done: Caddyfile, caddy-run.sh, plist template, install.sh, test-config.mjs and test-stream.mjs, all passing; install.sh ran for real.
  • The authenticated streaming check was done by Jack in J7; no agent touched the password.
  • The ts.net certificate through Caddy is untested until the loopback proof; Desktop-app pairing can only be tested at the cut-over.

Cut-over and first use

  • J6 done: the LaunchAgent runs Caddy on 127.0.0.1:8443 only, with real Let's Encrypt certificates for both names.
  • J7 done at about 17:32 UTC+7: Tailscale Serve is one TCP forward from 443 to 127.0.0.1:8443; the undo reference is ~/.digismith-depot/caddy/serve-before.json.
  • First use passed at about 17:4x: login with the server password works and streaming works. Checks: 200 with a valid certificate for opencode, 404 on pazurite.com, LAN 443 and 8443 refused.
  • The ts.net URL no longer works (accepted); the Desktop app is re-paired with the new name.

Staging certificate

scripts/caddy/staging-cert.sh obtained Let's Encrypt staging certificates for pazurite.com and opencode.pazurite.com by DNS challenge through Cloudflare, on loopback only with skip_install_trust and a temp data dir. The token was never printed. No service was loaded.
