.gitattributes eol — Implementation Report

Date: 2026-10-26 · Ticket: DGS-499 · Commit range: fe6d03a6..e279ea8c

Summary

Git now stores and checks out text files as LF on every machine. The rule * text=auto eol=lf is line 1 of .gitattributes. The existing -text lines come after it and win, so the 14 vendored skill folders and vendored/* stay byte-identical. One task, one line, built directly from the plan with no subagent ledger. Reference documents: the spec and the plan.

Evidence

  • Open branches: every unmerged branch has the same count of CRLF text files outside the exception list as main (3). No branch adds one.
  • Rule test in a scratch clone: a CRLF file in the normal tree became i/lf; a CRLF file under vendored/ stayed i/crlf. git add --renormalize . staged nothing else.
  • After the edit: git ls-files --eol (index and working-tree columns) identical to before; the 21 files at 100755 identical; git diff --summary empty; the same 4 CRLF files remain.
  • Merge diff: .gitattributes only, no protected path. Fast-forward merge, pushed.
  • Test suite: two full runs, 2 or 3 failures each, all load timeouts. test-install.test.ts and oculus/index.test.ts pass alone. runner.test.ts "escalates to SIGKILL" also fails on main.

Not done on purpose

DGS-478's real fix (keep git trees out of the MEGA two-way sync) is a separate item. A .gitattributes rule does not stop working-tree drift written outside git.
