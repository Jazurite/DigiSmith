dg reviewer table accepts r2+ verdict lines

Date: 2026-10-21Ticket: DGS-572

Problem

In DGS-456 the Builder wrote verdict lines for round r2 that name findings an r1 pack raised. dg reviewer table failed with "verdict line names no finding", because it matches a line only to a finding of the pack with the same round. The ledger is an audit record, so nobody may delete the lines. The table must accept them.

Rules for the table

  1. Identity. A finding is identified by review kind, review id and finding id (F1), raised by the pack of round R. Example: task 4 r1 F1.
  2. Own-round line. A line Review task 4 r1: F1 -> ... for a pack that raised F1 in that round is the ruling of round R, as today.
  3. Re-ruling line (new). A line with round N > R for the same kind and id, naming a finding id that no pack of round N raised, but an earlier pack raised, is a re-ruling of that earlier finding. If a pack of round N did raise that id, the line belongs to that pack's finding (exact match first).
  4. Latest ruling. The table shows, per finding, the ruling with the highest round. For the same round, the later ledger line wins. The Round column shows the round that raised the finding. The Verdict column shows the latest ruling, and when it came from a later round it appends [r2], for example fixed (abc123) [r2].
  5. Missing ruling. A finding with no line at its own round or later still fails: "findings with no verdict line".
  6. Unknown id stays an error. A line that matches no finding in any pack fails with: ledger line <n>: <line>: no pack raised <kind> <id> <Fk>; packs read: <list of pack folders>. The same holds for a re-ruling line whose round is lower than or equal to the raising round of every match.
  7. Ledger is read only. The change reads the ledger. No code or test deletes or rewrites a ledger line; tests write a fresh fake ledger in a temp folder.

JSON output (schema 1)

dg reviewer table --json prints JSON to stdout. With --out <file> it writes the file instead. Without --json, --out is required and the markdown is unchanged in shape. DGS-582 reads this JSON; the shape is stable and a change needs a new schema number.

{
  "schema": 1,
  "findings": [
    {
      "id": "task 4 r1 F1",
      "review": { "kind": "task", "id": "4" },
      "finding": "F1",
      "severity": "Important",
      "raisedRound": 1,
      "latestRound": 2,
      "latestRuling": { "verdict": "fixed", "reason": "abc123" },
      "history": [
        { "round": 1, "verdict": "parked", "reason": "wait" },
        { "round": 2, "verdict": "fixed", "reason": "abc123" }
      ]
    }
  ],
  "approvedReviews": [ { "kind": "task", "id": "7", "round": 2 } ]
}

Findings are in the table order (kind, id, round, finding number). history is in round order, ledger order within a round. reason is an empty string when the line has none. approvedReviews lists packs with no findings (the "approved, no findings" rows).

Skill text

The SDD skill (role mode, "Verdict lines") and the Reviewer card ("Report and table") say: write the verdict line of a re-review as Review task 4 r2: F1 -> fixed (abc123), where r2 is the re-review round and F1 is the finding the earlier pack raised. One example in each. The rule "r<R> is the round of the pack that raised the finding" is replaced: a line may use the raising round or a later round. The existing skill tests that check the text are updated, and a test checks the example line parses.

Components

  • packages/cli/src/reviewer/verdicts.ts: parse lines into entries with the ledger line number, keeping every line (no overwrite in a map).
  • packages/cli/src/reviewer/table.ts: resolve entries to findings, build rows, build the JSON model, render.
  • packages/cli/src/reviewer/index.ts: --json flag, --out optional with --json.
  • skills/subagent-driven-development/SKILL.md, skills/reviewer/SKILL.md: format text and example.

Consumers of parseVerdictLines are checked in the plan; the return type change must not break them.

Tests

Test first, with fake pack folders and a fake ledger in a temp folder: r2 re-ruling accepted and latest wins; same-round exact match preferred; unknown id error text names line, id and packs; missing ruling still fails; JSON shape and schema; --out rules; the SDD and card example parses; the ledger file bytes are the same after a run.
