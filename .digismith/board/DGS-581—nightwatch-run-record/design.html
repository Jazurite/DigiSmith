Goal

Every worker run (Builder, Reviewer, Scout) gets two files in the depot: a frozen run.json written at dispatch, and an append-only events.jsonl written by plugin hooks and by dg run event. Later Nightwatch tickets (DGS-582, 583, 585, 586) read these two files and nothing else. This ticket builds the writers and three readers. The nine decisions below come from the Maestro and are settled.

Files and ids

  • Root: $DIGISMITH_DEPOT_DIR when set, else ~/.digismith-depot (the existing convention in sessions/cleanup.ts). Tests point this at a temp dir.
  • Run directory: <root>/runs/<KEY>/<run-id>/ with run.json and events.jsonl. Two helper files may sit beside them: seq (counter) and lock/ (lock directory, see below).
  • Run id: <role>-<UTC yyyymmddThhmmss>-<6 hex>, for example builder-20261021T133005-a1b2c3. Every attempt gets a new id. dg run start creates the directory with a non-recursive mkdir; if it exists, it draws a new suffix. A run id is never reused.
  • The ticket key and run id are checked against ^[A-Za-z0-9][A-Za-z0-9._-]*$ before they join a path.

run.json (frozen)

Written once with the wx flag (fails if present), never edited. Later facts go into events.

{ "schema": "nightwatch-run/v1", "run": "<run-id>", "ticket": "DGS-581",
  "role": "builder|reviewer|scout|other", "order": "<path>", "seat": "dev0",
  "model": "<id>", "plugin_version": "1.21.0", "base_sha": "<sha>",
  "branch": "<name>", "worktree": "<path>",
  "herdr": { "workspace": "w2", "tab": "<label>", "pane": "<id>" },
  "budget": { ... } /* optional */, "created_at": "<ISO UTC>" }

Unknown facts (no seat flag, no git worktree) are written as null, so the field set is always the same. plugin_version is read from .claude-plugin/plugin.json. base_sha, branch and worktree default from git in the --worktree directory when it exists.

Events and seq

One JSON object per line: {"schema":"nightwatch-event/v1","seq":1,"ts":"<ISO UTC>","run":"<run-id>","type":"started","data":{}}.

  • Types: started, blocked, tool, turn_end, ended (hooks); review_ready, merged, pushed, lost, phase (dg run event). A phase event needs data.phase to be exactly building, review or merge; any other value, or a missing one, is refused (exit 1, nothing written). The set is closed; an unknown type is refused by the CLI. dispatched is not an event: created_at in run.json is the dispatch time.
  • seq: starts at 1, grows by 1, no gaps in the file. A writer takes a lock by mkdir <run-dir>/lock (atomic on one machine), reads the seq counter file, writes the next number, appends the line with one appendFileSync, then removes the lock. A lock older than 1 s is treated as stale and broken (a holder keeps it for a few milliseconds). Wait limits: the PostToolUse hook (tool, the most frequent event) waits at most 150 ms, then drops its event and logs it, because a missing tool event is better than a slow session. Every other writer waits up to 2 s: the SessionStart, Notification, Stop and SessionEnd hooks and dg run event. So blocked, started, turn_end and ended are not dropped under normal contention. If even the 2 s wait fails, a hook logs the error and exits 0; dg run event exits non-zero.
  • If the counter file is missing or unreadable, the writer counts the lines of events.jsonl instead.
  • Append only. No code in this ticket rewrites or truncates either file.

Hooks

New entries in hooks/hooks.json call one script, scripts/run-events/hook-cli.ts <kind>. It imports only the small event writer (node:fs and node:path only, no yargs), so it starts fast. The existing hooks stay as they are; the new commands are added next to them.

Each new command tests the variable in the shell before node starts, so a session without DIGISMITH_RUN_ID starts no node process at all:

[ -z "$DIGISMITH_RUN_ID" ] || node --experimental-strip-types "${CLAUDE_PLUGIN_ROOT}/scripts/run-events/hook-cli.ts" tool

The shell test returns 0 when the variable is empty or unset, so the command still exits 0. The script keeps its own check as a second guard.

HookTypedata (ids, names, counts only)
SessionStartstarted{source} (startup, resume, clear), session_id
Notificationblocked{kind} from notification_type (permission_prompt, idle_prompt, other kinds copied as the name)
PostToolUsetool{tool, ok}; ok is false when the response carries an error flag
Stopturn_end{}
SessionEndended{reason}

Rules (decision 6):

  • No DIGISMITH_RUN_ID in the environment: the shell test in the command stops first; if the script is started anyway, it returns at once and writes nothing. Also nothing when the run directory has no run.json (a wrong id never creates a directory).
  • The whole body is in one try/catch; exit code is always 0; no output on stdout; stdin that is not JSON still writes the event with empty data. Hooks never block a tool call (PostToolUse and Stop are observation only).
  • An error goes to <root>/runs/hook-errors.log as one line (time, hook, error message, no payload), and that log stops growing at 256 KB.
  • Never written: message text, prompts, tool inputs, tool outputs. Fields not listed in the table are dropped, not copied. A test feeds a payload full of secrets and checks that none of it appears.
  • Target under 100 ms per hook; a test measures one call and reports the time, with a loose ceiling so a slow CI machine does not fail it.

dg run commands (packages/cli/src/run/)

  • dg run start --ticket KEY --role R --order PATH [--seat S] [--model M] [--worktree DIR] [--branch B] [--base-sha SHA] [--workspace W] [--tab T] [--pane P] [--budget JSON]: writes run.json, prints the run id alone on stdout (so the runbook can capture it).
  • dg run event <run-id> <type> [--data JSON]: appends one event of the five conductor types (review_ready, merged, pushed, lost, phase; for phase, --data '{"phase":"building"}' is required and checked). The readers do not change. Finds the run directory by scanning runs/*/<run-id>. Exit 1 on an unknown run or type; --data must be a JSON object.
  • dg run list [--ticket KEY] [--json]: one row per run (id, ticket, role, seat, created, event count, last event type). Newest first.
  • dg run show <run-id> [--json]: run.json plus a summary (event count, first and last timestamp, last type, whether ended was seen).
  • dg run tail <run-id> [--since seq]: prints the event lines with seq greater than the value (default 0), one JSON line each. It reads the file once and exits; it does not follow. A line that does not parse is skipped.

Dispatch and runbook

The conductor's worker-start step runs RUN_ID=$(dg run start ...) and starts the worker with DIGISMITH_RUN_ID=$RUN_ID in its environment. The repo holds no tracked start script (scripts/conductor/ has none), and the runbook .digismith/sessions/workbox.md is git-excluded. So the runbook change is a text block in report.md for the conductor to apply. A Reviewer or a retry runs dg run start again and gets a new id.

Tests and first use

Tested without Jack (vitest, DIGISMITH_DEPOT_DIR set to a temp dir, no real depot, no ClickUp):

  • run.json: all fields, null for unknown ones, refused overwrite, new id on a clash, bad key or id refused.
  • Events: seq 1..n in order; two parallel writers (child processes, 40 events each) give seq 1..80 with no gap and no duplicate and 80 valid lines; stale lock is broken; missing counter file falls back to line count.
  • Hooks, with fake stdin payloads piped to the real script: each of the five kinds writes the right type and data; no DIGISMITH_RUN_ID writes nothing (no directory, no log); wrong id writes nothing; bad JSON and a missing run directory exit 0; secrets in the payload never reach the file; time of one call recorded.
  • hooks.json: the five new entries exist, the existing three keep their commands, and the existing hook tests stay green.
  • The hooks.json commands themselves: a test runs each new command string through sh -c (with CLAUDE_PLUGIN_ROOT set to the repo and a fake depot). With DIGISMITH_RUN_ID unset or empty: exit 0, no node process (a node shim first in PATH that records each call stays unused), nothing written. With a valid run id and a payload on stdin: exit 0 and the event is written.
  • Lock waits: with the lock held by the test, a tool hook gives up near 150 ms and writes nothing; a blocked hook started at the same time writes its event once the lock is released within 2 s.
  • Readers: list (with and without --ticket, --json), show, tail with --since, on a fake depot.

First use is the conductor's, not Jack's (the real check, after merge and plugin update): the conductor starts a throwaway worker through the updated runbook (dg run start, then the worker with DIGISMITH_RUN_ID), triggers one prompt so the worker runs a tool call and a turn, triggers one permission prompt, then closes the tab. The conductor then runs dg run show <id>, which must show started, tool, blocked, turn_end, ended in seq order. A plain Claude session without DIGISMITH_RUN_ID must leave runs/ unchanged. The runbook text block from report.md is applied by the conductor as part of the merge, before this check.

Out of scope

Watchdog, state machine, Nexus API routes, UI. The running Nexus API is not changed. No sudo, no launchctl, no new LaunchAgent or background service, no delete outside the worktree, no real ClickUp write in tests. No Claude Code hook outside hooks/hooks.json and no change to .claude/settings*.
