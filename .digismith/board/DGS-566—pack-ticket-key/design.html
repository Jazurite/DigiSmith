1. Problem

dg reviewer pack writes pack.md. The file has no ticket line. The Reviewer card says: take the ticket key from the board folder named in the paths of pack.md. That is a guess from a path. A task Reviewer is reused for the whole ticket and the key is needed at every review: the session registration (entry.ts session --ticket <KEY> --role reviewer) counts the Reviewer's tokens with the ticket. A wrong or missing key loses those tokens.

2. Approaches

OptionSource of the keyVerdict
A. A --ticket optionThe Builder passes the key. It has it: the **Key:** line of ticket.md, and the branch prefix.Chosen. Explicit, one line, no guessing, works for both pack types and every round.
B. Read the git branch^KEY__ of the current branchNo. A keyless branch has no prefix. The pack builder would depend on the checkout it runs in.
C. Read it from --ticket-fileThe **Key:** lineNo. Only a round 1 ticket pack has that file. A task pack has none.

3. Design

Where the key comes from

dg reviewer pack gets a new required option --ticket <KEY|none>. PackInput gets ticket: string. The option is required on purpose: an optional one is the bug again, the day a Builder forgets it. Value none is for work with no tracker key (a ticket: false profile).

Validation

buildPack accepts /^[A-Z][A-Z0-9]*-\d+$/ or the word none. Anything else throws ticket: must be a ticket key such as DGS-566, or none. The CLI prints it as error: ... and exits 1, like every other pack error. A pack that fails writes no folder (the check runs before mkdir).

Manifest line

One line, first field after the title, before type::

# Review pack: task 7 round 1

ticket: DGS-566
type: task
id: 7
...

Same key: value shape as the other fields. It is written in every round and both types.

Card text

In skills/reviewer/SKILL.md, the registration rule becomes: "pack.md has a ticket: line. Use it as <KEY>. A ticket: none line means no registration: skip the command." The sentence about the board folder is removed. The flow step that lists what pack.md holds names the ticket line. skills/reviewer/brief.md already has {{KEY}} from the conductor: it stays, and its registration line stays.

SDD role mode

The four dg reviewer pack command lines in skills/subagent-driven-development/SKILL.md get --ticket <KEY>, and the role-mode text says where the Builder takes the key (the **Key:** line of ticket.md, or none).

4. Tests and old-path protection

  • pack.test.ts: the manifest has ticket: DGS-566 for a task pack, a ticket pack and a round 2 pack; none is written as ticket: none; a bad value (dgs-566, 566, empty) throws and leaves no folder.
  • index.test.ts: the CLI refuses a pack with no --ticket and prints the key in the manifest when given.
  • card.test.ts: the card names the ticket: line and no longer says "board folder".
  • sdd.test.ts: every dg reviewer pack line in the SDD skill carries --ticket.
  • both-paths.test.ts (the Task 14 tests): the old path test (hand mode, review-package alone, no pack) is not touched and still passes: hand mode never calls pack, so a required option cannot break it. The role path test gets the new argument and one added assertion: the pack of a real range carries the ticket: line.

5. How it is built

One build ticket, about 4 small tasks: (1) pack.ts and index.ts with their tests; (2) the card and card.test.ts; (3) the SDD command lines and sdd.test.ts; (4) both-paths.test.ts and a plugin version check.

This is the first role-mode build. A Builder runs it with DIGISMITH_REVIEW_MODE=role (runbook, "Start of a Reviewer"). The task Reviewers and the final Reviewer run as their own workers under the role mode of DGS-529. The plan keeps each task small, with a diff file per task and a findings block per review. The new ticket: line is what the reused task Reviewer reads. Until task 1 merges in the Builder's branch, the packs of this very build have no ticket: line: the Reviewer uses the key in the conductor's brief for those. No card-mode fallback is needed (the live check passed).

Out of scope: moving the Reviewer events (DGS-551), other pack fields, a ClickUp write.
