A limit on concurrent runs — Implementation Report

Date: 2026-10-26 Ticket: DGS-665 Commit range: 1e8bd702..2a56de9e

Summary

The system now refuses to start a run that would pass the limit of 2 builders, 1 reviewer and 1 role. A new pure module packages/cli/src/run/limit.ts counts busy runs from the Nightwatch run records and the factory lock. The limits are read from the nightwatch: block of .digismith/config.yml (main checkout). Callers: dg run start (refuses, exit 1, no record), the autonomous scan (returns busy with reason: builder-limit, no tracker call), and the displays (dg run limit, dg autonomous status, the catch-up Health Limits line, DigiSmith project only).

Beyond the plan: a builder start for the factory lock's own ticket is exempt from the builder limit (the lock already counts as that slot); the limits come from the main checkout config, found from a worktree through its .git link; spec line 74 now says other counts as a role. Protected paths touched: .digismith/config.yml, packages/cli/src/autonomous/*, skills/reviewer/SKILL.md. The scheduler reader ignores the new keys, so it is untouched. The runbook lines are in .sdd-workspace/runbook-lines.md for the conductor (the runbook is git-excluded).
