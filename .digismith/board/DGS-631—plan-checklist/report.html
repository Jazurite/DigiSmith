Summary

The branch adds dg clickup checklist sync (DGS-632). The command keeps a ticket's ClickUp "Plan" checklist equal to its plan and its build ledger. writing-plans creates the checklist (DGS-631). subagent-driven-development and executing-plans tick it as the build moves (DGS-634). Four client calls use the public API v2 checklist endpoints. Three pure modules parse the plan and ledger, build the wanted checklist and compute the writes. The command applies the writes with --yes, reads back and prints one JSON line. Each skill has one small named step. Followed the full Superpowers process: brainstorming → spec → writing-plans → digismith:subagent-driven-development (5 tasks, each dispatched to a fresh implementer subagent and independently reviewed) → a final whole-branch review, plus 2 fix round(s) before merge.

Reference documents: the design spec and the implementation plan.

Builds the wanted nested checklist and the writes that make the current checklist match it, matched by item key, so renames keep the same item.

Task 4

The dg clickup checklist sync command

The command: dry run unless --yes, writes, read-back check, one JSON line; an orphan child left by a failed write is adopted on the next run.

Task 5

Skill hooks (DGS-631 create, DGS-634 tick)

writing-plans creates the checklist; subagent-driven-development and executing-plans write ledger lines and sync after each step; a failed sync never blocks.
