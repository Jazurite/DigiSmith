Scheduled drift sweep of every checkout — Implementation Report

Date: 2026-10-26 Ticket: DGS-557 Commit range: 80beb4de..c0f1d0b4

Summary

A new Nexus scheduler job drift-sweep runs drift-check.ts --sweep from the depot every 10 minutes and checks every checkout under ~/Workspace. Each repo has a 30 s limit. The sweep writes drift-sweep.json atomically and appends to drift.csv only when a repo's result changed. It exits 0 when it ran, even with drift. The SessionStart alarm reads the state file and prints one sweep line for other drifting repos (cap 5, then and k more), or a stale line when the state is older than 60 minutes. Built by one worker from the plan (plan, spec), test first, Tasks 1 to 3. Tasks 1 and 2 share one commit. Task 4 (install, API restart, first use) comes after the merge.

The plan named no notes file, so the sweep paragraph is in a new scripts/workbox-health/README.md. The job touches the protected path scripts/nexus-api/src/scheduler/registry.ts; the Maestro approved the merge.
