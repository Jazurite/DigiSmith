Reviewer brief: skip session registration when the pack says ticket: none

Date: 2026-10-19 · Ticket: DGS-569 · Refinement only (DGS-488)

Problem

The card (skills/reviewer/SKILL.md, "Rules for the Reviewer") says: register the session with the key from the ticket: line of pack.md, and skip the command when that line is ticket: none. The brief template (skills/reviewer/brief.md) says "Register your session ... first" with --ticket {{KEY}} and no exception. A Reviewer started from the brief for a no-key pack has two rules that disagree. The DGS-566 ticket Reviewer saw this.

Fix

Change the one registration bullet in brief.md so it follows the card. The command line stays as it is, with {{KEY}}. The bullet gains the exception:

- Register your session so your tokens count with the ticket, first, at the start of every review (again after a `/clear`). `pack.md` has a `ticket:` line. A `ticket: none` line means the work has no tracker key: skip the command.
  `node --experimental-strip-types ~/.digismith-depot/repo/packages/cli/src/tokens/entry.ts session --ticket {{KEY}} --role reviewer`

The five placeholders stay the same. No new placeholder, no change to the card.

Test

In packages/cli/src/reviewer/card.test.ts, extend the brief.md test: the brief contains ticket: none and the ticket: line wording, and still contains the pinned command entry.ts session --ticket {{KEY}} --role reviewer. Written first, it fails on the current brief.

Files

  • skills/reviewer/brief.md (the bullet)
  • packages/cli/src/reviewer/card.test.ts (one assertion)

Not touched: skills/subagent-driven-development/ (DGS-570 and DGS-568 may touch it), skills/reviewer/SKILL.md, anything under packages/cli/src that is not a test (no dist rebuild).

Assumptions

  • The conductor fills {{KEY}} in the brief as today. For a no-key pack the Reviewer skips the command, so the value does not matter. The brief does not say what to put in {{KEY}} for such a pack; that is the runbook's "Start of a Reviewer", not this ticket.
  • The card wording is already right (its test pins it). Only the brief moves.
  • No wording Jack sees, no ClickUp setting, nothing public: no taste question.
  • The build runs in role mode (DIGISMITH_REVIEW_MODE=role); see the plan.
