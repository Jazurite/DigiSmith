DGS-196: dg shopee import-orders

Design for checkpoint 1. 2026-10-07 (UTC+7).

Goal

List Jack's own Shopee VN purchases from Proxyman captures. The module only parses files. It makes no call to Shopee.

Decisions

Data flow

text (stdin or file)
  -> paste.ts     : split at "[n] URL = " lines; per block keep {n, url, body}; skip the Request section
  -> list.ts      : parseOrderList(body) -> order ids (all pages, de-duplicated)
  -> detail.ts    : parseOrderDetail(body) -> Order (allow-listed fields)
  -> join.ts      : join(blocks) -> rows + missingCount
  -> format.ts    : table | json | csv

Order model

Order { orderId, orderSn, purchasedAt: Date | null, shopId, shopName,
        lines: [{ name, modelName, quantity, unitPrice }],
        total, currency, statusLabel }

One output row per line item. Order-level fields repeat on each row in CSV. The table prints them once per order.

Output

  • Table (default): times as 2026-10-07 08:56:38 UTC+7 [01:56:38Z]. Footer: orders, rows, missing count.
  • --json: ISO times (UTC+7 offset and UTC), numbers in VND.
  • --csv: one row per line item, header row, RFC 4180 quoting.
  • Exit 1 with a plain message when the file is missing, stdin is empty, or no order list block is found.

Error handling

  • A malformed block (no Response section, or a body that is not JSON): skipped. The error names the block number only, for example block 836: no JSON body. Exit code stays 0 if other blocks parsed. The summary counts skipped blocks.
  • Two details for one order id: the later block number wins.
  • Orders only in a detail, not in any list: ignored. The list is the source of truth for which orders exist.

Tests (TDD, synthetic only)

Invented ids and shop names. Fixtures are built in the test by a small helper that builds Proxyman-copy-shaped text. Each block carries a fake Request section with obvious dummy secrets (DUMMY-COOKIE-DO-NOT-LEAK and similar). Tests prove those strings never reach stdout, stderr, JSON, CSV or an error message. No real order, name, phone or address. A test asserts the output never contains the fixture's shipping name, phone or address.
